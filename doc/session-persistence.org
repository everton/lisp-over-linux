#+TITLE: Session persistence — keeping what a session changed
#+STARTUP: showall

The environment is one running Lisp heap, and a power-off throws it away. This doc
covers what's kept across boots, and how: a *journal* of every accepted definition,
replayed at boot; a *desk* file for tabs and Workspaces; *file-out*, which folds
live edits back into the repo's =.lisp= sources; and the leave menu that ties them
together.

Code: [[file:../initramfs/journal.lisp][journal.lisp]], [[file:../initramfs/desk.lisp][desk.lisp]], [[file:../initramfs/file-out.lisp][file-out.lisp]], [[file:../initramfs/lol-home.lisp][lol-home.lisp]] (where
files live). Related: [[file:storage.org][storage.org]] (the disk, and who owns what on it),
[[file:code-browser.org][code-browser.org]] Phase 6 (the change set), [[file:processes.org][processes.org]] §5–§6 (fork, and the
=sb-posix= rule).

*Status.* Journal + replay, desk, file-out and the leave menu: *built* (kernel tag
#27 on, userland only). *Image snapshots* (§9): *not built*, a plan — the "opaque"
part of a session (§1) is lost at power-off.

* 1. What a session creates

| What                                                          | Where it lives                                                         | Kind              | Kept by                                   |
|---------------------------------------------------------------+------------------------------------------------------------------------+-------------------+-------------------------------------------|
| Accepted definitions (=C-c C-c=)                              | the running code + =*registry*= ([[file:../initramfs/registry.lisp::defun accept-source][=accept-source=]])                    | *source*          | the journal (§4)                          |
| Their history ("Versions")                                    | =defn-versions=, newest first; =defn-born= for new ones                | *source*          | the journal, by replaying in order        |
| The change set (menu =c=)                                     | /derived/: [[file:../initramfs/registry.lisp::defun changed-definitions][=changed-definitions=]] scans the registry                    | *source*          | nothing extra to save                     |
| Forms run with Do it / Print it, the REPL, the net REPL       | nowhere — evaluated and forgotten                                      | source, unrecorded | not kept (§4)                             |
| Edited files (=C-x C-s=)                                      | the disk, via =write-file-atomically=                                  | file              | already persistent                        |
| A file buffer you did *not* save                              | the pane's text view                                                   | text              | the leave menu asks first (§7)            |
| Workspace buffers                                             | each Workspace pane's text view (=pane-tv=)                            | text              | the desk (§6)                             |
| Tabs, trails, windows                                         | =*trails*=, =*active*= ([[file:../poc/shell.lisp::defvar *trails*][shell.lisp]])                                    | describable heap  | the desk                                  |
| Clipboard history, PRIMARY, killed rectangle                  | =*clipboard*= ([[file:../poc/clipboard.lisp::defvar *clipboard*][clipboard.lisp]])                                         | strings           | the desk, only if you ask (§6)            |
| Spotter recents                                               | =*spotter-recents*= ([[file:../initramfs/present.lisp::defvar *spotter-recents*][present.lisp]]), capped at 8                        | subjects          | the desk                                  |
| File-manager settings                                         | =*file-sort*=, =*file-sort-reverse*=, =*show-hidden*=                  | symbols           | the desk                                  |
| The stage (COLLIDE bodies)                                    | =*the-collide-stage*= ([[file:../initramfs/stage.lisp::defvar *the-collide-stage*][stage.lisp]])                                     | *opaque heap*     | not kept                                  |
| Instances, closures, a =setf= on a closure's capture          | the heap                                                               | *opaque heap*     | not kept                                  |

The other globals in those files are per-frame caches, device state or constants.
Three kinds of thing, each with its own answer:

1. *Source* — definitions. The registry holds text, name, kind, package and (for a
   method) the specializer label. Writing them out is cheap; replaying them has
   subtle points (§4).
2. *Describable heap* — tabs, buffers, clipboard, recents, settings. Not source, but
   a few lines of printed data rebuild each: a tab is a list of subjects, and most
   subjects name something by name or path (=subj-defn NAME KIND=, =subj-dir PATH=).
3. *Opaque heap* — the stage mid-flight, an inspected instance (=subj-object=,
   =subj-retention=, =subj-disassembly=), a closure whose counter you =setf='d. No
   file describes these honestly. Only an image could keep them (§9).

* 2. The approach: source first

Smalltalk keeps two things: the *image* (a heap snapshot) and the *=.changes= file*
(a journal of every accepted method, written at accept time, so a crash loses
nothing accepted). This environment builds the journal half and leaves the image
half as an optional plan:

- *Only source survives a rebuild.* The working loop is edit → rebuild → boot. A
  saved image holds the old code for every module and would quietly discard each
  rebuild; a journal can be replayed into the new one, and file-out turns a live
  edit into a commit.
- *The journal gives the real guarantee* — crash-safe Accepts — with no PID 1 risk.
  None of it touches =preinit.c= or the kernel.
- *What it can't keep is cheap to rebuild.* Mid-flight stage bodies or an inspected
  instance come back by re-running a Workspace form.

| Combination                            | Keeps                                                    | Survives a rebuild?                | Crash-safe?                        |
|----------------------------------------+----------------------------------------------------------+------------------------------------+------------------------------------|
| journal only                           | definitions                                              | yes (replay / pending set)         | yes, per Accept                    |
| journal + desk                         | definitions, tabs, buffers, clipboard                    | yes                                | definitions yes, desk at last save |
| journal + desk + file-out (*built*)    | the above, and changes land in git                       | best: they become the build        | as above                           |
| image only                             | everything                                               | *no* (discarded on stamp mismatch) | only at the last save              |
| image + journal (Smalltalk's own pair) | everything; the journal bridges the gap and the rebuilds | partly                             | yes                                |

** Moving from the old layout

Files from an older image sit at the "old place" paths. [[file:../initramfs/lol-home.lisp::defun migrate-lol-home][=migrate-lol-home=]] runs
in =supervisor-main= right after =session-boot= (so it can log) and before anything
reads a setting, the key or the journal. For each old path it does
=renameat2(…, RENAME_NOREPLACE)= — a rename within =/home=, so a folder of any size
moves in one step — and logs =lol-home: moved OLD -> NEW= to =session.log=.

- *Never overwrites.* The flag makes the refusal atomic. Old and new both present
  is logged as "both kept" and left alone — except folders, whose entries are moved
  one by one under the same rule.
- *Never deletes a file.* An old folder goes with =rmdir(2)=, which only removes an
  empty one.
- *Idempotent, never signals.* A second boot finds nothing to move.

Tested by [[file:../poc/lol-home-test.lisp][poc/lol-home-test.lisp]] (33 checks, fake =HOME=​s in =/tmp=) and in the
guest by [[file:../check-persist.lisp][check-persist.lisp]]'s boot 5 and [[file:../check-files.lisp][check-files.lisp]] (the test disk keeps a
settings file at the old place on purpose).

** Ownership, diskless boots, release

- *Ownership is free.* PID 1 runs as the user ([[file:storage.org][storage.org]] §5), so every file is
  created as the user with no =chown=, and the host sees them as the user's own.
- *Diskless boots* (QEMU without =test-disk.img=, =lol.disk=none=, another
  machine) set =HOME= to =/= ([[file:../initramfs/preinit.c::int main][preinit's =main=]]) and run as root. =~/.lol= would be
  =/.lol= on the initramfs: writable, and gone at power-off — a silent failure.
  =persistence-available-p= ([[file:../initramfs/journal.lisp][journal.lisp]]) therefore asks for a real home on a
  mounted, writable =/home=; without one nothing is written and the leave menu says
  "nothing is kept".
- *After =release-disk=* =/home= is read-only, so every save happens before
  =power-off= calls it.

* 4. The change journal

** Records

On every /successful/ Accept, =accept-source= runs [[file:../initramfs/registry.lisp::defvar *accept-hooks*][=*accept-hooks*=]] with the name,
kind, label, package and exact text. [[file:../initramfs/journal.lisp::defun journal-accept][=journal-accept=]] appends one record to
=~/.lol/journal/changes.lisp= (=O_APPEND=, =fsync=, created 0600):

#+begin_example
(:seq 12 :time 3968650123 :build "a2ed0be 2026-10-03T10:47"
 :package "LOL.TEXTVIEW" :name "TV-DRAW" :kind :function :label nil
 :source "(defun tv-draw (tv canvas) …)")
#+end_example

A hook's string becomes =*accept-note*=, which the status line appends
("Accepted: foo - NOT journalled: …").

- *Names and source as strings.* The journal is read with =*read-eval*= nil and
  nothing interned until replay decides to; a record naming a vanished package
  fails alone.
- *Append-only, one form per record.* A power cut can tear at most the last one.
- *Journal order, not registry order.* =defclass= must replay before the
  =defmethod= that specializes on it, =defmacro= before its callers.
  =changed-definitions= sorts by name, which suits display only.
- *History for free.* Replaying three Accepts of one function rebuilds
  =defn-versions= as the session had it.
- *Only definitions.* An Accept that defines nothing (=(+ 1 2)=) isn't kept, and
  Do it / Print it / the REPL are never journalled, as Smalltalk's "do it" isn't.
- *The package is part of the record.* =accept-source= reads inside the package of
  the recorded definition (=defn-package=, stored by =load-recording=), else
  =*package*= for a fresh one. Without that, editing a =lol.*= definition would
  define a new symbol in =CL-USER= and leave the real one unchanged — and the
  journal would faithfully replay the mistake (§10).
- *=*build-stamp*=* is baked by =build.sh= as =<rev>[+dirty] <UTC time>=.

** Replay at boot

[[file:../initramfs/journal.lisp::defun boot-replay-journal][=boot-replay-journal=]] runs in =supervisor-main= after the network (so the net REPL
is up) and before =run-browser-fb=. It prints one line and logs every skipped
record to =session.log= ([[file:diagnostics.org][diagnostics.org]]). [[file:../initramfs/journal.lisp::defun classify-record][=classify-record=]] and
[[file:../initramfs/journal.lisp::defun run-record][=run-record=]] sort each record:

| Outcome           | When                                                     | What happens                                                 |
|-------------------+----------------------------------------------------------+--------------------------------------------------------------|
| /retired/         | its text is already the image's source for that defn    | removed from the journal: a folded-and-rebuilt change retires itself |
| /needs-rebuild/   | a =defstruct=                                            | never replayed automatically (below)                         |
| /pending/         | written by another build (=:build= ≠ =*build-stamp*=)    | waits in the journal view to be Accepted or dropped by hand  |
| /replayed/        | same build                                               | Accepted again under =handler-case= + =with-timeout= (30 s), warnings muffled |
| /failed/          | anything signalled                                       | reported; the boot carries on                                |

- *A failing record never stops the boot.* The result is a report subject: "14
  replayed, 1 failed: =ship-hull= — undefined function =hull-of=".
- *Structs are the sharp edge.* Redefining =(defstruct pt x)= as =(defstruct pt x
  y)= signals an incompatible-redefinition error with a =CONTINUE= restart, after
  which old instances are broken badly enough that printing them fails
  (=LAYOUT-INVALID=; verified in =./sbcl=). By replay time the image holds
  instances of its own structs (=*clipboard*= is one), so a replayed struct edit
  could break every copy and paste. File-out plus a rebuild is the way. =defclass=
  is fine: CLOS updates old instances lazily.
- *Each replayed record is tried in a child first*, through the Accept sandbox
  ([[file:processes.org][processes.org]] §7¾): a record that would kill PID 1 is refused like a typed one.
- *A torn tail is moved aside.* A record that won't read stops the reader;
  [[file:../initramfs/journal.lisp::defun quarantine-tail][=quarantine-tail=]] appends the tail to =changes-damaged.lisp= and rewrites the
  journal as its readable prefix. Left in place, the next Accept would be appended
  /after/ the torn record and swallowed into its unterminated string.
- *Switching replay off.* =lol.replay=off= on the kernel command line, or a file
  =~/.lol/journal/replay-off= ([[file:../initramfs/journal.lisp::defun replay-disabled-p][=replay-disabled-p=]]): the journal is read, nothing
  runs, and the desk isn't restored either. The file exists because a test harness
  can't change the kernel command line (it's in the EFI stub's boot entry); from
  the host it's one =touch=.

** The journal view

=subj-journal= (Spotter "journal") lists this boot's report by status, then this
session's Accepts. It opens by itself beside the desk when replay left something
for you.

| Key | Action                                                                          |
|-----+---------------------------------------------------------------------------------|
| =a= | Accept a pending or failed record now (it re-journals with this build's stamp)  |
| =d= | drop it                                                                         |
| =F= | file out (§5)                                                                   |
| =D= | discard the journal: /moved/ aside to =changes-discarded-<time>.lisp=, not deleted |

There's no "Accept all" for the pending set yet.

* 5. File-out to the repo's source

=build.sh= records each definition's file as an absolute path inside the checkout.
On a machine where the guest's =/home= is the host's, *the checkout is at that same
path inside the running image*, so the image can write its edits back.
[[file:../initramfs/file-out.lisp::defun file-out-changes][=file-out-changes=]], for each changed definition:

1. finds the build-time text — the oldest entry in =defn-versions=;
2. if that text occurs *exactly once* in =defn-file=, replaces it with the current
   source and saves with =write-file-atomically= (owned by the user);
3. otherwise (the file moved on, or the text occurs twice) leaves the file alone and
   appends the change to =changes-unfolded.lisp= for a human to fold in;
4. always puts a definition *born* this session in =changes-unfolded.lisp=: placing
   new code is a judgement the tool shouldn't make for you.

Then on the host you =git diff= and commit; git is the undo. On the next build the
records retire themselves (§4).

*The comment above a definition is kept.* =load-recording='s span includes the
comments before a form (for a file's first form, the file's header). An Accept from
the Workspace or the agent sends only the form, so a plain replace would delete
that header; =replacement-text= prepends the original's comment block when the new
text has none.

The rule-3 fallback also catches the risky case: a build from a dirty tree, edited
live, filed out over a tree that has since changed.

* 6. The desk: tabs, Workspaces, clipboard, recents

This pile is small and it's data, not code: one printed plist, read with
=*read-eval*= nil.

#+begin_example
(:version 1 :build "…" :saved 3970000000
 :trails (((:ref (:workspace) :text ";; my scratch…" :point (12 4)))
          ((:ref (:modules) :sel 3) (:ref (:module "poc/textview")) …))
 :active 0 :windows ((1 200 120 768 500)) :recents (…)
 :settings (:file-sort :name …) :clipboard nil)
#+end_example

- *A subject is written as a reference, never as itself.* [[file:../initramfs/desk.lisp::defgeneric desk-ref][=desk-ref=]] turns a subject
  into a small list of strings and keywords (=(:dir "/home/<user>/Pictures")=, =(:defn
  ("LOL.FB" "FB-GEOMETRY") :function)=). [[file:../initramfs/desk.lisp::defun desk-subject][=desk-subject=]], a *whitelist*, turns
  one back by calling the constructor; a symbol is found with =FIND-SYMBOL=, never
  interned, and a path must still exist.
- *A trail is cut at the first opaque pane.* An inspected instance, a closure, a
  terminal's process, a web page or an agent conversation has no reference; what
  came before it is kept.
- *Workspace text is restored whole, with its point.* It's where a half-written
  idea lives.
- *Unsaved file buffers aren't stashed.* The leave menu asks about them (§7). A
  secret second copy of a file you didn't save is how editors earn distrust.
- *The clipboard isn't kept unless you ask.* A pasted password lives there. The
  setting =:desk-clipboard N= in =~/.lol/settings= ([[file:../initramfs/settings.lisp][settings.lisp]]) keeps the newest
  N, at most 50.

[[file:../initramfs/desk.lisp::defun desk-data][=desk-data=]] writes it; [[file:../initramfs/desk.lisp::defun restore-desk][=restore-desk=]] reads it back once per boot, through
[[file:../poc/shell.lisp::defun open-environment][=open-environment=]]: keep existing trails, else restore the desk, else open the
Workspace. =run-browser-fb= clears the trails when the environment /dies/, so the
next =b= starts fresh. =open-environment= with an explicit root (menu =p=, =c=,
=l=) focuses an existing tab rooted at an =equalp= subject, or adds a tab.

** Two desk files

- *An explicit save* writes =desk.lisp= and removes =desk-autosave.lisp=.
- *The autosave*, every 5 minutes when something changed (a poll-loop service,
  =fb-register-service=), writes only =desk-autosave.lisp=.
- *"Shut down without saving"* removes the autosave.

So an autosave exists at boot only when the last session /didn't shut down/ (a
crash, a held power button), and then it's the newer truth and wins. With one file,
"without saving" would still bring back the last autosave.

* 7. Leaving: the power-off path

[[file:../initramfs/process.lisp::defun power-off][=power-off=]] runs =sync= → =release-disk= (=lol-rootd= remounts =/home=
read-only) → =reboot(RB_POWER_OFF)=. [[file:../poc/shell.lisp::defun leave-menu][=leave-menu=]] (=SuperL-q=) sets
=*leave-action*=, which =run-browser-fb= acts on after restoring the console:

| Key | Entry (with a disk)                        | Diskless                                |
|-----+--------------------------------------------+-----------------------------------------|
| 1   | Supervisor console                         | same                                    |
| 2   | Save and shut down                         | Shut down (no disk - nothing is kept)   |
| 3   | Shut down without saving                   | —                                       |
| 4   | Save and restart                           | Restart (nothing is kept)               |
| 5   | Install the new build and restart (when one is waiting; [[file:sbcl-init.org][sbcl-init.org]]) | same |

- *The console comes first,* so a reflexive Return is the step you can come back
  from.
- *Unsaved files come first.* Before any shut-down or restart,
  [[file:../poc/shell.lisp::defun unsaved-files-resolved-p][=unsaved-files-resolved-p=]] lists modified file panes: save all / discard /
  cancel.
- *"Save" writes the desk.* The journal is already current.
- *"Without saving" leaves the journal alone.* Those Accepts happened; forgetting
  them is the journal view's explicit =D=. That's Smalltalk's "quit without
  saving", whose =.changes= still holds everything.
- *The supervisor menu's =s=* asks the same question in text
  ([[file:../initramfs/desk.lisp::defun console-shutdown][=console-shutdown=]]).

* 8. Tests

Never the real disk: the guest checks use =test-disk.img=, and a persistence check
needs the second boot to see the first boot's writes, which =snapshot=on= would
throw away. So the harness's =*disk-copy*= copies =test-disk.img= into a scratch
dir (=LOL_PERSIST_DIR=, default =/tmp=) and attaches the *copy* writable; the
pristine image is never touched ([[file:storage.org][storage.org]] §8).

- *Host:* [[file:../poc/journal-test.lisp][poc/journal-test.lisp]] (=sbcl --script=, scratch =HOME=, 58 checks):
  append + stamp + 0600 + package; the five replay outcomes, including a runaway
  =defparameter= stopped by =with-timeout= (host only — no guest entry loops); the
  torn tail; replay-off; pending Accept/drop; discard; file-out (exactly once,
  already, duplicated text, born); the desk round trip; no symbol interned by
  reading a desk.
- *Guest:* [[file:../check-persist.lisp][check-persist.lisp]] (41 checks), six boots of one writable copy, with a
  fixture =examples.lisp= planted at the build's path by =debugfs=:
  1. Accept + a =lol.*= edit + Workspace text + a tab + clipboard + file out +
     "Save and shut down" over QMP.
  2. On the host, no root: =debugfs= finds the journal and desk owned by the user,
     =dumpe2fs -h= says clean, the fixture changed in exactly one place.
  3. Boot 2: everything back; then an Accept and a torn record, and =kill -9= QEMU.
  4. Boot 3: that Accept survived (the =fsync=), the cut tail reported, the journal
     view opened; "Shut down without saving".
  5. Boot 4 honours replay-off, then moves the journal, the desk and a font size
     back to the old XDG places; boot 5 finds them moved into =~/.lol=, the font
     kept, the journal replayed.
  6. Boot 6, diskless, writes nothing under =/.lol= or =/.local=.

* 9. Image snapshots — not built

The Smalltalk half: freeze the whole running heap with =save-lisp-and-die=, write
it to the disk, and boot that file next time instead of the shipped =/sbin/lisp=.
Everything would come back, the opaque heap included. It's feasible and the hard
part is proven on the host, but it's the most machinery for the least durable
result: every rebuild discards it, and it captures breakage as faithfully as work.
What it would take:

** 9.1 It dies, and PID 1 must not

=save-lisp-and-die= ends the process; its docstring says it "corrupts the current
Lisp image enough that the current process needs to be killed afterwards. This can
be worked around by forking another process that saves the core"
([[file:../sbcl/src/code/save.lisp::defun save-lisp-and-die][save.lisp]]). PID 1 exiting is a kernel panic. So the save happens in a *forked
child*: =fork= gives it a copy-on-write copy of the heap, the child saves and dies,
PID 1 waits and carries on.

** 9.2 Fork without =sb-posix=

=sb-posix:fork='s child-side fixup, =sb_posix_after_fork=, is defined in the SBCL
*runtime* ([[file:../sbcl/src/runtime/thread.c::void sb_posix_after_fork][thread.c]]), and every other step of [[file:../sbcl/contrib/sb-posix/interface.lisp::(defun fork][=sb-posix:fork=]] is an
=SB-IMPL= / =SB-THREAD= internal. So the contrib isn't needed:

1. under =sb-thread::*make-thread-lock*=: =sb-impl::finalizer-thread-stop=,
   =sb-thread::%dispose-thread-structs=, and refuse if
   =(sb-thread::avl-count sb-thread::*all-threads*)= is over 1;
2. inside =without-interrupts=: call libc =fork=;
3. in the child: call =sb_posix_after_fork= through =extern-alien=;
4. in *both* processes: =sb-impl::finalizer-thread-start=.

Verified in =./sbcl= 2.6.8 (=:sb-thread=, no =:sb-core-compression=; the finalizer
thread runs from startup):

| Variant                                                   | Result                                                                               |
|-----------------------------------------------------------+--------------------------------------------------------------------------------------|
| bare =fork()= via =alien-funcall=, child saves            | the child *hangs*: =deinit= tries to stop a finalizer thread the child doesn't have  |
| stop the finalizer first, then bare =fork()=              | the child fails =AVER (THREAD-P THREAD)=; the parent is fine                         |
| steps 1–3, finalizer restarted *only in the parent*       | the same =AVER= in the child                                                         |
| steps 1–4 exactly                                         | *works*: the child saved a 39 MB executable in 0.81 s, and the parent carried on     |
| =sb-posix:fork= (the contrib), for comparison             | works                                                                                |
| steps 1–4 with an extra thread running                    | refused: "Cannot fork with multiple threads running."                                |
| steps 1–4 with ~68 MB of live heap                        | works: a 96 MB executable in 1.10 s                                                  |

Copy it /exactly/: step 4 in the child looks pointless, but it's what lets
=deinit='s =finalizer-thread-stop= find a thread to stop. These are internals an
SBCL bump may move. They're plain function calls, not =declaim inline= over
groveled structs, so the [[file:processes.org][processes.org]] §6 rule /should/ hold — an estimate from the
code's shape, not tested in the guest.

** 9.3 One thread only

=deinit= refuses to save with more than one thread ([[file:../sbcl/src/code/save.lisp::defun deinit][deinit]]), and the fork recipe
refuses earlier. The image runs several — the net REPL, =netd=, =lol-watch=, the
=kmsg= reader, and more on demand — so a save would stop them all, fork, and start
them again in the parent. A connected net-REPL session is dropped, and a save can't
start /from/ the net REPL, since that's a thread being stopped.

** 9.4 Foreign state in a resumed image

The child's =deinit= runs =*save-hooks*= and closes every Lisp fd-stream — in its
own copy, so the parent's streams are untouched. A stream opened before the fork
comes back as an object that says "was closed by SB-EXT:SAVE-LISP-AND-DIE" on use:
legible, not a crash. Compiling works after a resume (=(* x 2)= → 42).

The danger is state that isn't a stream: a bare integer fd in a global survives as
a number that may name an unrelated file after a resume.

| Global                                      | Holds                                    | After a resume                                                         | Needs                                              |
|---------------------------------------------+------------------------------------------+------------------------------------------------------------------------+----------------------------------------------------|
| =lol.fb::*fb*=                              | =(FD XRES YRES STRIDE)= for =/dev/fb0=   | *handled*: an =*init-hooks*= entry clears it ([[file:../poc/fb.lisp::init-hooks][fb.lisp]])                 | nothing                                            |
| =*input-devices*=, =*input-watch-fd*=       | evdev fds + an inotify fd                | stale, but =run-browser-fb= reopens them ([[file:input.org][input.org]] §4¾)              | clear in a save-hook, for hygiene                  |
| =*net-repl-server*= / =-client= / =-thread= | sockets and a thread object              | stale; a later =stop-net-repl= could =close= a reused fd               | save-hook: =nil= them                              |
| =*stbi-state*=                              | =T= once =libstbi.so= has loaded         | =T=, but the library is gone: JPEG previews say "not loaded"           | save-hook: reset to =NIL=, so it reloads on demand |
| =*battery-cache*=                           | the last sysfs read                      | stale for 5 s at most                                                  | nothing                                            |
| =run-program= process objects (workers)     | pids of children                         | pids that no longer exist                                              | only matters mid-save                              |

- *=libstbi.so= is safe to reset.* It's loaded with =:dont-save t=
  ([[file:../poc/image.lisp::defun stbi-available-p][=stbi-available-p=]]); in a resumed test image
  =find-dynamic-foreign-symbol-address "lol_stbi_info"= was =NIL=.
- *Ruled out:* the framebuffer is written with =pwrite=, not =mmap=, so no dangling
  mapping; =run-program= reaps only pids it started ([[file:../sbcl/src/code/run-program.lisp][run-program.lisp]]), so it
  won't steal the saving child's =waitpid=.
- *=logcount-fix.lisp= should survive.* Its patch is in the heap, and =deinit='s
  =restore-cpu-specific-routines= is the path the shipped image already took. An
  estimate; =check-compile.lisp= against a resumed image is the proof owed.

** 9.5 Booting it without bricking the boot

The shipped =/sbin/lisp= is an =:executable t= image (the 2.2 MB runtime with the
core appended), and such an executable *refuses* =--core= ("more than one core file
specified"). So the saved image is a whole executable, =~/.lol/image=, which preinit
would =execve= in place of =/sbin/lisp=. =/home= is mounted =nosuid,nodev= but not
=noexec= ([[file:storage.org][storage.org]] §4), and preinit drops to the user before the =execve=, so
the capabilities carry over as now.

If the exec succeeds and the Lisp then dies, PID 1 dies, and preinit is gone. The
safety must come before the exec:

1. *Verify before promoting.* The saving child writes =image.new=; PID 1 runs it as
   an ordinary child in a new =verify= role (load, check the registry and a compile,
   print a token, exit). Only on success is it renamed over =image= (atomic on
   ext4), keeping =image.prev=.
2. *A boot-attempt marker* (the A/B-update trick). preinit writes =booting= before
   exec'ing the saved image; the Lisp deletes it after drawing a frame /and/ reading
   a key. A marker found at boot means the last attempt died: boot =/sbin/lisp= and
   say so on =/dev/kmsg=.
3. *A command-line escape:* =lol.image=shipped=, like =lol.disk=none=.

** 9.6 A newer build orphans it

A saved image forks the build that was current when it was saved. Rebuild, and the
image still holds the old code everywhere; it can't be merged with the new build,
only source can. So each image needs a sidecar stamp, =image.build=, which preinit
compares with a stamp it can read before any Lisp runs (say =/etc/lol-build= in the
cpio; the journal only needs the heap's =*build-stamp*=). On a mismatch the shipped
image boots and the journal carries the changes forward. With
frequent rebuilds the image path would be skipped on most boots — the strongest
argument against making it the base.

** 9.7 Size, time, memory, security

- *Size.* =initramfs/lisp-init= was 48,798,112 bytes at tag #25; with no core
  compression a saved image is the same order plus what the session allocated, so
  =image= + =image.prev= ≈ 100 MB of =/home=. =test-disk.img= (256 MB) would be
  tight. Estimate.
- *Time.* 0.81 s at 15 MB of heap, 1.10 s at 68 MB, writing to tmpfs on the host.
  A few seconds to disk in the guest, estimated.
- *Memory.* The child's GC dirties its copy-on-write pages, so a save can briefly
  need a second heap's worth of RAM.
- *Security.* A saved image is a user-owned file in =/home= that preinit would exec
  with PID 1's five capabilities ([[file:storage.org][storage.org]] §5). Any program the user runs on the
  host could then choose the code that runs as PID 1. The powers are modest and the
  user already owns the files, but it's a real widening — and it applies equally to
  a replayed journal, which is also code read from =/home=.

A snapshot test would save, verify, reboot into the saved image (the marker
cleared), then plant a broken =image= and check the next boot falls back to
=/sbin/lisp=.

* 10. Pitfalls and known limits

- *Accept used to ignore the package.* =accept-source= read with =read-from-string=
  in the current =*package*= (=CL-USER= at runtime), while =load-recording= filed
  every definition under its real package. Accepting an edited =lol.demo::twice=
  defined a new =cl-user::twice= and left the real one unchanged. Fixed by
  =defn-package= + =accept-package= (§4); =check-compile.lisp= asserts that
  re-Accepting =lol.examples::make-counter= lands in =LOL.EXAMPLES= and interns
  nothing in =CL-USER=.
- *Leaving to the console used to wipe the tabs.* =open-environment= replaced
  =*trails*= on every entry, so =SuperL-q= → console → =b= gave a fresh Workspace.
  It now keeps existing trails (§6) — and any image snapshot would have needed the
  same fix, since a resumed image enters through =open-environment= too.
- *Power-off didn't ask about unsaved files.* =leave-menu= went straight to
  =:power-off=; =unsaved-files-resolved-p= now asks (§7).
- *Not a finding:* a first guest run had two failures that were the harness —
  =between-markers= refuses any answer containing =~= (it could be a FORMAT
  string's echo) — not persistence. The probes ask for statuses instead.
- *Known gap, outside this work:* [[file:../initramfs/web.lisp::defparameter +web-special-keys+][=+web-special-keys+=]] contains
  =#.(string #\Return)=. =record-source= reads with =*read-eval*= off, so that read
  signals and recording of =web.lisp= stops there: later definitions aren't in the
  registry, the browser shows them as builtins, and file-out can't reach them. (By
  reading and the CLHS rule — =#.= with =*read-eval*= false is a =reader-error= —
  not measured in the guest.)
- *What isn't kept:* the opaque heap (§9); a web tab, a terminal or an agent
  conversation on the desk (the trail is cut there; conversations have their own
  store, [[file:agent.org][agent.org]]).
