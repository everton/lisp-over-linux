This file is the *single source of truth* for which kernel features the image
turns on, and *why each one is there*. Read it top to bottom when you (re)build
the kernel from scratch.

- *Kernel.* =linux-7.2.5=, config at [[file:../linux/.config][=./linux/.config=]] (the gitignored symlink);
  the tracked copy is [[file:../kernel/config-7.2.5][=kernel/config-7.2.5=]].
- *Current tag: #32* — the webcam ([[#webcam-v4l2-usb-video][The webcam — V4L2 + USB Video Class, NEW in tag #32]]). The tags before it, one line each, are in
  the change log at the end.
- *Size.* 1,203 =CONFIG_= lines are set at #32; most are auto-selected defaults.
  The tables list only the ones chosen on purpose.
- *Reference hardware.* Where a row names a device, it's the one the image is
  tested on: a Dell XPS 13 9300 (Ice Lake i7-1065G7, NVMe, Intel AX201 Wi-Fi,
  Realtek ALC289 audio, a UVC webcam).

* 1. Boot — how the kernel becomes the EFI application

| Option                    | State | Role                                                                    |
|---------------------------+-------+-------------------------------------------------------------------------|
| =CONFIG_EFI=              | y     | UEFI runtime support                                                    |
| =CONFIG_EFI_STUB=         | y     | The bzImage *is* the =.EFI= app — UEFI launches it, no GRUB             |
| =CONFIG_BLK_DEV_INITRD=   | y     | Accept an =initrd== from the firmware                                   |
| =CONFIG_INITRAMFS_SOURCE= | ""    | *Empty on purpose*: initramfs is a SEPARATE file, not baked in          |
| =CONFIG_BINFMT_ELF=       | y     | Load ELF binaries — THE line that makes userspace possible              |
| =CONFIG_BINFMT_SCRIPT=    | y     | =#!= shebang scripts (delegates to an ELF interpreter)                  |
| =CONFIG_CMDLINE=          | str   | Baked-in kernel cmdline (see below) — EFISTUB fallback boot has no args |

- *The baked cmdline.* =CONFIG_CMDLINE_BOOL=y=, no override:
  ="console=ttyS0,115200 console=tty0 initrd=initramfs.cpio"=. =initrd== loads the
  separate initramfs (EFISTUB opens it relative to the volume root); the
  =console== pair drives both serial (QEMU markers) and the fb console.
- *Why the initramfs is separate.* With =INITRAMFS_SOURCE=""=, changing the Lisp
  doesn't need a kernel rebuild, so =build.sh= runs in seconds.
- *Why ELF is the one that matters.* Without =BINFMT_ELF= the kernel can run
  *nothing* in userspace and panics with "No working init found". =BINFMT_AOUT= no
  longer exists (removed from x86 in 5.1); =BINFMT_MISC= is off.

* 2. Display — why the laptop screen is not blank
:PROPERTIES:
:CUSTOM_ID: display-laptop-screen-blank
:END:

| Option                       | State | Role                                                                |
|------------------------------+-------+---------------------------------------------------------------------|
| =CONFIG_FB=                  | y     | Framebuffer core                                                    |
| =CONFIG_FB_CORE=             | y     | The fbdev core proper (auto-selected by =FB=)                       |
| =CONFIG_FB_DEVICE=           | y     | Creates the =/dev/fb0= *character device* — what our Lisp writes to |
| =CONFIG_FB_EFI=              | y     | Use the framebuffer UEFI hands us (efifb)                           |
| =CONFIG_SYSFB=               | y     | Registers the firmware framebuffer efifb then claims                |
| =CONFIG_FRAMEBUFFER_CONSOLE= | y     | Draw the text console onto that framebuffer (fbcon)                 |
| =CONFIG_VT=                  | y     | Virtual terminal layer                                              |
| =CONFIG_VT_CONSOLE=          | y     | Console on the VT                                                   |
| =CONFIG_TTY=                 | y     | The tty layer console + stdio ride on                               |
| =CONFIG_UNIX98_PTYS=         | y     | Modern PTYs (=/dev/ptmx= + =/dev/pts/=); legacy pool is OFF         |
| =CONFIG_FONTS=               | y     | Manually choose compiled-in fbcon fonts                             |
| =CONFIG_FONT_8x16=           | y     | *The font in use* — 160x50 on a 1280x800 panel                      |
| =CONFIG_FONT_8x8=            | y     | Second built-in font (defconfig default, unused)                    |
| =CONFIG_FONT_TER16x32=       | *n*   | Terminus 16x32 — tried in #20, *reverted* (see below)               |

- *Why the screen isn't blank.* Real UEFI has *no legacy VGA text mode*. Without
  efifb + fbcon the screen stays blank while the kernel runs fine.
- *=FB_DEVICE= is easy to overlook.* =FB= gives the kernel a framebuffer;
  =FB_DEVICE= exposes it to userland as =/dev/fb0=. Without it fbcon still paints
  the console, and every Lisp drawing routine fails with "no such file".
- *The 8x16 font, not Terminus 16x32.* Bigger glyphs give 80x25 instead of 160x50,
  and mainline fbcon has *no scrollback*, so the lost rows cost more than the
  bigger glyphs buy. Reasoning and how to redo it: [[file:framebuffer.org::#fbcon-font-size-default][framebuffer.org, The fbcon font size: the default 8x16]].

Kernel source, if you want to read it:
[[file:../linux/drivers/video/fbdev/efifb.c][linux → drivers/video/fbdev/efifb.c]] (the dumb driver),
[[file:../linux/drivers/video/fbdev/core/fb_chrdev.c][linux → drivers/video/fbdev/core/fb_chrdev.c]] (the =/dev/fb0= read/write/mmap
entry points) and [[file:../linux/drivers/video/fbdev/core/fbcon.c][linux → drivers/video/fbdev/core/fbcon.c]] (glyph → pixels, with the
actual bit-stamping in [[file:../linux/drivers/video/fbdev/core/bitblit.c][bitblit.c]]).

* 3. Input — why you can type (the PCI saga)
:PROPERTIES:
:CUSTOM_ID: input-can-type
:END:

| Option                                               | State | Role                                                                         |
|------------------------------------------------------+-------+------------------------------------------------------------------------------|
| =CONFIG_PCI=                                         | y     | *Keystone* — without it: no USB AND no ACPI S5                               |
| =CONFIG_PCI_MSI=                                     | y     | Message-signalled interrupts                                                 |
| =CONFIG_PCIEPORTBUS=                                 | y     | PCIe port bus driver                                                         |
| =CONFIG_USB_SUPPORT= / =CONFIG_USB=                  | y     | USB core                                                                     |
| =CONFIG_USB_XHCI_HCD= / =_PCI=                       | y     | USB 3.x host controller (modern laptop ports)                                |
| =CONFIG_USB_EHCI_HCD= / =_PCI=                       | y     | USB 2.0 host controller                                                      |
| =CONFIG_USB_OHCI_HCD= / =_PCI=                       | y     | USB 1.x host controller                                                      |
| =CONFIG_USB_HID= / =CONFIG_HID=                      | y     | Interpret a USB keyboard as keystrokes                                       |
| =CONFIG_I2C= + =I2C_HID= + =_ACPI=                   | y     | Internal I2C-HID keyboard bus (laptops)                                      |
| =CONFIG_I2C_DESIGNWARE_CORE/_PLATFORM=               | y     | The common laptop I2C controller                                             |
| =CONFIG_SERIO= + =INPUT_KEYBOARD= + =KEYBOARD_ATKBD= | y     | Legacy PS/2 keyboard (QEMU + old machines)                                   |
| =CONFIG_INPUT_EVDEV=                                 | y     | =/dev/input/event*= layer — the mouse, the wheel, modifier state ([[file:input.org][input.org]]) |
| =CONFIG_INPUT_MOUSEDEV=                              | *n*   | deliberately OFF — why there is no =/dev/input/mouseN= to look for           |
| =CONFIG_MOUSE_PS2=                                   | y     | PS/2 mouse + laptop touchpad (QEMU's pointer)                                |

*Why PCI is the keystone.* Everything used early in boot (EFI framebuffer, RAM
rootfs, PS/2 keyboard in QEMU) is non-PCI, so a kernel without =CONFIG_PCI= works
under QEMU. Real hardware needs it twice: a USB keyboard sits behind xHCI, a PCI
device, and ACPI's =_S5= (power-off) evaluates operation regions in PCI config
space. One option fixes both a dead keyboard and a power-off that halts.

The chain a keypress travels: [[file:../linux/drivers/usb/host/xhci.c][=drivers/usb/host/xhci.c=]] (the USB 3.x host
controller) → [[file:../linux/drivers/hid/usbhid/hid-core.c][=drivers/hid/usbhid/hid-core.c=]] (USB HID reports → HID events) →
[[file:../linux/drivers/hid/hid-input.c][=drivers/hid/hid-input.c=]] (HID → input key codes) →
[[file:../linux/drivers/input/evdev.c][=drivers/input/evdev.c=]], which creates =/dev/input/event*= — the nodes
[[file:../initramfs/fb-browser.lisp][=fb-browser.lisp=]] polls for the mouse and Ctrl detection (mechanism:
[[file:input.org][input.org]]; what the browser does with it: [[file:code-browser.org::#guest-specifics][code-browser.org, Guest specifics (framebuffer)]]). Under QEMU
the PS/2 path is [[file:../linux/drivers/input/keyboard/atkbd.c][=drivers/input/keyboard/atkbd.c=]] on top of =serio=.

* 4. Platform & power
:PROPERTIES:
:CUSTOM_ID: platform-power
:END:

| Option                    | State | Role                                                         |
|---------------------------+-------+--------------------------------------------------------------|
| =CONFIG_ACPI=             | y     | Power-off (=reboot(RB_POWER_OFF)= -> =_S5=); depends on PCI  |
| =CONFIG_ACPI_BATTERY=     | y     | The battery in =/sys/class/power_supply/BAT0/= (the systray) |
| =CONFIG_ACPI_AC=          | y     | The adapter's =online= file (=/sys/class/power_supply/AC/=)  |
| =CONFIG_POWER_SUPPLY=     | y     | The sysfs class both register into; =select=-ed by both      |
| =CONFIG_RTC_MC146818_LIB= | y     | Reading the CMOS clock at boot; =select=-ed by =config X86=  |
| =CONFIG_RTC_CLASS=        | n     | Not needed: x86 reads the CMOS clock itself (no =/dev/rtc=)  |

- *Power-off path.* [[file:../initramfs/process.lisp::defun power-off][=power-off=]] FFI-calls =reboot(2)=, which lands in
  [[file:../linux/kernel/reboot.c][=kernel/reboot.c=]]; =RB_POWER_OFF= ends in ACPI's =_S5= handling in
  [[file:../linux/drivers/acpi/sleep.c][=drivers/acpi/sleep.c=]]. With =CONFIG_PCI= off it silently halts instead ([[#input-can-type][Input — why you can type (the PCI saga)]]).
- *Battery and AC came free.* Both are =default y= under =CONFIG_ACPI= in
  [[file:../linux/drivers/acpi/Kconfig][=drivers/acpi/Kconfig=]]; they're listed because the systray depends on them.
- *The clock without an RTC driver.* With =RTC_CLASS= off, x86's
  =timekeeping_init()= path still reads the CMOS chip through =RTC_MC146818_LIB=,
  so the time is right at boot. Why the RTC must hold UTC: [[file:systray.org][systray.org]].

* 7. Networking (IPv4 + QEMU virtio-net) — NEW in tag #21
:PROPERTIES:

The kernel half of the network stack ([[file:networking.org::#kernel-half-has-turned][networking.org, Kernel half — what has to be turned on]]). The bus plumbing a
NIC needs — =CONFIG_PCI= + =CONFIG_PCI_MSI= — is [[#input-can-type][Input — why you can type (the PCI saga)]]'s. Everything is built in
(=y=): we ship no modules and have no =modprobe=.

| Option              | State | Role                                                          |
|---------------------+-------+---------------------------------------------------------------|
| =CONFIG_NET=        | y     | The socket / protocol core — the master switch                |
| =CONFIG_INET=       | y     | IPv4 (TCP, UDP, ICMP) — the thing we actually want            |
| =CONFIG_UNIX=       | y     | AF_UNIX local sockets (useful even before a NIC has an IP)    |
| =CONFIG_PACKET=     | y     | AF_PACKET raw sockets (some DHCP clients use it)              |
| =CONFIG_NETDEVICES= | y     | The network-device layer (gate for any NIC driver)            |
| =CONFIG_NET_CORE=   | y     | Core netdev machinery (auto-selected)                         |
| =CONFIG_VIRTIO=     | y     | Virtio core                                                   |
| =CONFIG_VIRTIO_PCI= | y     | Virtio-over-PCI transport                                     |
| =CONFIG_VIRTIO_NET= | y     | The QEMU paravirtual NIC driver — binds =[1af4:1000]= as eth0 |

- *In the tree.* Every =sb-bsd-sockets= call enters through [[file:../linux/net/socket.c][=net/socket.c=]]; IPv4
  registers in [[file:../linux/net/ipv4/af_inet.c][=net/ipv4/af_inet.c=]]; the interface ioctls of
  [[file:networking.org::#userland-half-reaching-network][networking.org, Userland half — reaching the network from SBCL]] land in [[file:../linux/net/ipv4/devinet.c::devinet_ioctl][=net/ipv4/devinet.c='s =devinet_ioctl=]]; the virtio core
  =VIRTIO_PCI= plugs drivers into is [[file:../linux/drivers/virtio/virtio.c][=drivers/virtio/virtio.c=]].
- *Under QEMU.* With =-device virtio-net-pci= the NIC enumerates on PCI
  (=pci 0000:00:02.0: [1af4:1000] ... class 0x020000=) and =virtio_net=
  ([[file:../linux/drivers/net/virtio_net.c][linux → drivers/net/virtio_net.c]]) binds it. The SLIRP wiring
  (=-netdev user,...hostfwd...=) is [[file:../build.sh::QEMU_NET][build.sh → QEMU_NET]] and [[file:networking.org::#qemu-test-wiring][networking.org, QEMU test wiring (for build.sh --run)]].
- *The userland half.* The kernel brings =eth0= up with no address; addressing is
  Lisp's job. [[file:../initramfs/dhcp.lisp::defun configure-eth0][dhcp.lisp → configure-eth0]] leases one with a real DHCP handshake and
  [[file:../initramfs/net.lisp::defun start-net-repl][net.lisp → start-net-repl]] serves a REPL on TCP :4005.

Wi-Fi, IPv6 and USB Ethernet are [[#daily-driver-set-new][Daily-driver set — NEW in tag #26]]'s; wired PCI NICs stay off (see "Deliberately OFF").

* 10. Processors — SMP, NEW in tag #30
:PROPERTIES:
:CUSTOM_ID: processors-smp-new-tag
:END:

Before #30 the kernel had =SMP= off (=NR_CPUS=1=), so a 4-core / 8-thread CPU ran
as one, and the image's threads (agent turns, =netd=, the recorder's writer, run
panes' readers, the watchdog) only ever took turns. What "bringing up the other
cores" means in hardware — the BSP, INIT–SIPI–SIPI, the APIC — is
[[file:background/background.org::#multicore-bring-up-core][background.org, Multicore bring-up: one core boots, the rest are woken]].

| Option                                    | State | Role |
|-------------------------------------------+-------+------|
| =CONFIG_SMP=                              | y     | more than one CPU: the APs are woken at boot, the scheduler balances across them, locks become real spinlocks (=QUEUED_SPINLOCKS=, =QUEUED_RWLOCKS=), RCU becomes =TREE_RCU= / =TREE_SRCU= (in place of =TINY_RCU=) |
| =CONFIG_NR_CPUS=                          | 16    | the most this kernel will run (each slot costs ~8 KB, =arch/x86/Kconfig=); the reference laptop has 8, QEMU's checks use 4 — 16 leaves room for a bigger machine without the default 64 |
| =CONFIG_SCHED_SMT=                        | y     | the scheduler knows two hardware threads share a core, so it fills cores before siblings |
| =CONFIG_SCHED_MC=                         | y     | ... and that cores share a last-level cache (with =SCHED_CLUSTER= and =SCHED_CACHE=, both default y) |
| =CONFIG_SCHED_MC_PRIO=                    | y     | (default y under =SCHED_MC=) Turbo Boost Max 3.0 core ordering. It =select=s =X86_INTEL_PSTATE=, =X86_AMD_PSTATE= and =CPU_FREQ=: *frequency scaling came along with SMP*, unasked |
| =CONFIG_X86_INTEL_PSTATE= + =CONFIG_CPU_FREQ= | y | the Intel P-state driver. On Ice Lake, which has HWP (hardware P-states), it registers in active mode with the =powersave= policy (=intel_pstate.c=, =default_driver = &intel_pstate= when =hwp_active=) — the same as a stock Debian kernel; =CPU_FREQ_DEFAULT_GOV_SCHEDUTIL= is only the governor of its passive mode. Under QEMU there is no driver (=scaling_driver= absent) |
| =CONFIG_HOTPLUG_CPU=                      | y     | =def_bool y= under =SMP= on x86: CPUs can be taken off line (=/sys/devices/system/cpu/cpuN/online=) |

- *Pulled in by =make olddefconfig=.* =ACPI_HOTPLUG_CPU=, =ACPI_CPPC_LIB= (+ =PCC=,
  =MAILBOX=), =ACPI_PLATFORM_PROFILE=, =GENERIC_IRQ_MIGRATION= /
  =GENERIC_PENDING_IRQ= (interrupts moved between CPUs), =RPS= / =XPS= /
  =RFS_ACCEL= (network queues steered to CPUs), =SPLIT_PTE_PTLOCKS= /
  =PER_VMA_LOCK= (finer page-table locking), the =*_SPIN_ON_OWNER= mutex
  optimisations, the =HOTPLUG_*= helpers and RCU's stall detector
  (=RCU_CPU_STALL_TIMEOUT=21=). Dropped: =TINY_RCU=, =TINY_SRCU=, =UP_LATE_INIT=,
  =FORCE_NR_CPUS=, =X86_REQUIRED_FEATURE_UP=, =BROKEN_ON_SMP=. 78 =CONFIG_= lines
  changed in all.
- *No userland change.* SBCL 2.6.8 is built =:sb-thread= and its stop-the-world GC
  signals every thread wherever it runs. What SMP adds is threads running /at the
  same instant/ (a read-modify-write one CPU never splits can now interleave), so
  the whole guest suite was re-run at =-smp 4=; no race showed.
- *QEMU runs =-smp 4=.* =build.sh=, =refresh-screenshot.sh= and the guest harness
  boot 4 CPUs; =QEMU_SMP= / =LOL_QEMU_SMP= change it (=1= = a single CPU).
- *Tested.* [[file:../check-smp.lisp][=check-smp.lisp=]]: =cpu/online= = =0-3=, 4 threads of one compiled
  loop take 764 ms against 692 ms for one (4× on one CPU), seen on 4 CPUs by
  =sched_getcpu=, and 4 threads allocate through a forced full GC. On the XPS 13:
  =nproc= = 8 and =cpu0/cpufreq/scaling_driver= = =intel_pstate=.

* 11. Restarting — kexec, NEW in tag #31
:PROPERTIES:
:CUSTOM_ID: restarting-kexec-new-tag
:END:

*kexec* lets the running kernel boot the next one, without the firmware or GRUB.

- *The call.* A process with =CAP_SYS_BOOT= hands the kernel a kernel and an
  initramfs (=kexec_file_load(2)=, system call 320 on x86-64: two file descriptors
  and a command line). The kernel parses the bzImage itself, copies both into
  memory and waits.
- *The jump.* At =reboot(LINUX_REBOOT_CMD_KEXEC)= it shuts devices down as a reboot
  would and jumps into the loaded kernel, which boots as if a bootloader had
  started it. No firmware runs: the screen isn't reset and POST is skipped.
- *Permission.* PID 1 already holds =CAP_SYS_BOOT= (it's how it powers off,
  [[file:storage.org][storage.org]]); =kexec_load_permitted= in [[file:../linux/kernel/kexec_core.c][=kernel/kexec_core.c=]] asks for nothing
  more. The userland side is [[file:sbcl-init.org][sbcl-init.org]], "Updating from inside".

| Option                    | State | Role |
|---------------------------+-------+------|
| =CONFIG_KEXEC_FILE=       | y     | =kexec_file_load(2)=: the kernel reads the image from a file descriptor and parses it (=arch/x86/kernel/kexec-bzimage64.c=), so no =kexec-tools= is needed in the image |
| =CONFIG_KEXEC_CORE=       | y     | =select=-ed by =KEXEC_FILE=: loading segments, =machine_kexec=, the purgatory (=ARCH_SUPPORTS_KEXEC_PURGATORY=: a small trampoline that runs between the two kernels) |
| =CONFIG_EFI_RUNTIME_MAP=  | y     | =select=-ed by =config EFI= when =KEXEC_CORE= is on (=arch/x86/Kconfig=): the next kernel needs the EFI runtime services' memory map to call them after the jump; =kexec-bzimage64.c= passes it as setup data |
| =CONFIG_KEXEC=            | n     | the OLDER call, =kexec_load(2)=, which takes segments prepared in user space by =kexec-tools=; we have no such tool and want none |
| =CONFIG_KEXEC_SIG=        | n     | verify the next kernel's signature. Without Secure Boot it would only refuse our own unsigned builds |
| =CONFIG_CRASH_DUMP=       | n     | its default follows =ARCH_DEFAULT_CRASH_DUMP= (y on x86), so it is set off by hand: a crash kernel needs =crashkernel== memory reserved at every boot and a tool to read =/proc/vmcore=. Our crash story is the session log and =kernel.panic=10= ([[file:diagnostics.org][diagnostics.org]]) |

- *The command line.* The bzImage carries =CONFIG_CMDLINE= (=console=… initrd=…=),
  and with =CMDLINE_BOOL= and no =CMDLINE_OVERRIDE= the kernel /prepends/ it to
  whatever it's given (=arch/x86/kernel/setup.c=, =builtin_cmdline=). So userland
  passes only what isn't built in: =/proc/cmdline= minus =console==, =initrd== and
  GRUB's =BOOT_IMAGE== ([[file:../initramfs/process.lisp::defun kexec-cmdline][=kexec-cmdline=]]).
- *Tested.* [[file:../check-update.lisp][=check-update.lisp=]] kexecs a QEMU guest (it comes back in the same
  QEMU). On the XPS 13 a kexec is not yet verified: the EFI framebuffer should
  survive (the old kernel's =screen_info= is handed over, =kexec-bzimage64.c=), and
  NVMe, the AX201 and HD-Audio all have shutdown paths. If a device doesn't come
  back, the =:restart-via :firmware= setting (=~/.lol/settings=) restarts through
  the firmware instead.

* Deliberately OFF (and what it would take to turn on)

** Sound through the DSP, HDMI audio, USB and Bluetooth audio — OFF (tag #29)

- *=SND_SOC= (SOF, AVS).* The Intel DSP path, needed where microphones are
  digital and wired to the DSP. The reference laptop's are analogue, on the codec
  ([[#sound-new-tag-29][Sound — NEW in tag #29]]). It would also need the DSP's firmware and topology from the host.
- *=SND_HDA_CODEC_HDMI=.* Sound over HDMI/DisplayPort wants i915's audio component
  (=SND_HDA_I915=); we run on efifb with no i915.
- *=SND_USB_AUDIO=.* A USB headset. One option turns it on (no firmware).
- *Bluetooth.* The whole stack, the AX201's Bluetooth firmware, and a sound server
  for the hands-free profile — ruled out in [[file:screencast.org::#choosing-mic-built-headset][screencast.org, Choosing the mic: built-in or headset]].

** Other storage — SATA/AHCI, USB mass storage, vfat, modules — OFF (tag #25)

Only the path to the reference disk is built: NVMe → GPT → ext4. =ATA=/=SATA_AHCI=
(a SATA disk), =USB_STORAGE= + =SCSI= + =BLK_DEV_SD= (the boot stick, or any USB
drive) and =VFAT_FS= (the ESP, most sticks) stay off until something needs them.
=CONFIG_MODULES= stays off too: everything is built in, so there's no =modprobe=
and no =/lib/modules= to keep in step. Reasons and the rest: [[file:storage.org::#kernel-half][storage.org, The kernel half (tag #25)]].

** Wired real-hardware NICs — OFF (Wi-Fi is ON since tag #26, in the daily-driver set)

For wired links only =virtio-net= (QEMU) and USB Ethernet ([[#daily-driver-set-new][Daily-driver set — NEW in tag #26]]) are built in. A
PCI wired chip is one more =y= (=CONFIG_R8169= / =CONFIG_E1000E=). See
[[file:networking.org::#kernel-half-has-turned][networking.org, Kernel half — what has to be turned on]].

** Hardware RNG — OFF (entropy comes the slow way)

=CONFIG_HW_RANDOM= is not set: no hwrng framework, no =virtio-rng= driver, and the
QEMU line passes no RNG device. The kernel seeds its CRNG only from
interrupt/input timing; on an idle VM that often completes only once you start
*typing* — the =random: crng init done= line in the middle of the REPL prompt.
Harmless: nothing needs secure randomness at boot. To seed instantly:
=CONFIG_HW_RANDOM=y= + =CONFIG_HW_RANDOM_VIRTIO=y= and =-device virtio-rng-pci= on
the QEMU line in =build.sh=. Full story: [[file:background/background.org::#entropy-crng-random-crng][background.org, Entropy and the CRNG — the "random: crng init done" message]].

** Legacy BSD PTYs — OFF (tag #22)

=# CONFIG_LEGACY_PTYS is not set=. The legacy scheme pre-allocates a *fixed pool*
(=CONFIG_LEGACY_PTY_COUNT=, 256) of =/dev/pty??= master + =/dev/tty??= slave nodes
— 512 unused nodes in =/dev=. Modern PTYs (=CONFIG_UNIX98_PTYS=: =/dev/ptmx= mints
=/dev/pts/N= on demand) stay on and are what the terminal pane uses
([[file:terminal.org][terminal.org]]), so nothing is lost.

** binfmt_misc — OFF; not needed (would only delegate to an ELF interpreter).
