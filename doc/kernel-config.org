tracked copy is [[file:../kernel/config-7.2.5][=kernel/config-7.2.5=]]).
Current tag: *#29* (SOUND: the HD-Audio controller and the Realtek codecs — §9; built on #28 = when
the KERNEL is stuck: Magic SysRq, the lockup and hung-task
detectors, pstore on EFI variables — §6; built on #27 = USB Ethernet dongles, the RTL8153
and the generic CDC classes, §8; built on #26 = the daily-driver set: user namespaces, overlayfs, Wi-Fi, IPv6,

NVMe + ext4 + virtio-blk, see [[file:storage.org][storage.org]], #24 = rebased the config onto Linux 7.2.5, #23 =

* 1. Boot — how the kernel becomes the EFI application

| Option                    | State | Role                                                                    |
|---------------------------+-------+-------------------------------------------------------------------------|
| =CONFIG_EFI=              | y     | UEFI runtime support                                                    |
| =CONFIG_EFI_STUB=         | y     | The bzImage *is* the =.EFI= app — UEFI launches it, no GRUB             |
| =CONFIG_BLK_DEV_INITRD=   | y     | Accept an =initrd== from the firmware                                   |
| =CONFIG_INITRAMFS_SOURCE= | ""    | *Empty on purpose*: initramfs is a SEPARATE file, not baked in          |
| =CONFIG_BINFMT_ELF=       | y     | Load ELF binaries — THE line that makes userspace possible              |
| =CONFIG_BINFMT_SCRIPT=    | y     | =#!= shebang scripts (delegates to an ELF interpreter)                  |
| =CONFIG_CMDLINE=          | str   | Baked-in kernel cmdline (see below) — EFISTUB fallback boot has no args |

Baked cmdline (=CONFIG_CMDLINE_BOOL=y=, no override):
="console=ttyS0,115200 console=tty0 initrd=initramfs.cpio"=.
=initrd== loads the separate initramfs; the =console== pair drives both serial
(QEMU markers) and the fb console. (A =fbcon=font:TER16x32= parameter was here in
tag #20 and was dropped again when we reverted to the 8x16 font — Display table
below, [[file:framebuffer.org][framebuffer.org]] §7.)

Note: =CONFIG_INITRAMFS_SOURCE=""= is why =build.sh= rebuilds in seconds —
changing the Lisp does not need a kernel rebuild. The initramfs is passed as
=initrd=initramfs.cpio= (EFISTUB opens it relative to the volume root).

binfmt detail: with =BINFMT_ELF= off the kernel could run *nothing* in
userspace (every path bottoms out at an ELF interpreter) and would panic with
"No working init found". =BINFMT_AOUT= no longer exists in the tree (removed
from x86 in 5.1); =BINFMT_MISC= is off.

* 2. Display — why the laptop screen is not blank

| Option                       | State | Role                                                                |
|------------------------------+-------+---------------------------------------------------------------------|
| =CONFIG_FB=                  | y     | Framebuffer core                                                    |
| =CONFIG_FB_CORE=             | y     | The fbdev core proper (auto-selected by =FB=)                       |
| =CONFIG_FB_DEVICE=           | y     | Creates the =/dev/fb0= *character device* — what our Lisp writes to |
| =CONFIG_FB_EFI=              | y     | Use the framebuffer UEFI hands us (efifb)                           |
| =CONFIG_SYSFB=               | y     | Registers the firmware framebuffer efifb then claims                |
| =CONFIG_FRAMEBUFFER_CONSOLE= | y     | Draw the text console onto that framebuffer (fbcon)                 |
| =CONFIG_VT=                  | y     | Virtual terminal layer                                              |
| =CONFIG_VT_CONSOLE=          | y     | Console on the VT                                                   |
| =CONFIG_TTY=                 | y     | The tty layer console + stdio ride on                               |
| =CONFIG_UNIX98_PTYS=         | y     | Modern PTYs (=/dev/ptmx= + =/dev/pts/=); legacy pool is OFF         |
| =CONFIG_FONTS=               | y     | Manually choose compiled-in fbcon fonts                             |
| =CONFIG_FONT_8x16=           | y     | *The font in use* — 160x50 on the 1280x800 panel                    |
| =CONFIG_FONT_8x8=            | y     | Second built-in font (defconfig default, unused)                    |
| =CONFIG_FONT_TER16x32=       | *n*   | Terminus 16x32 — enabled in #20, *reverted* (see below)             |

=CONFIG_FB_DEVICE= is the one that is easy to overlook: =FB= gives the kernel a
framebuffer, but =FB_DEVICE= is what exposes it to *userland* as =/dev/fb0=.
Without it fbcon would still paint the console and the screen would look fine —
and every one of our Lisp drawing routines would fail with "no such file".

*Font: back to the 8x16 default.* Tag #20 compiled in Terminus 16x32 and selected
it with =fbcon=font:TER16x32= on the cmdline; both were later undone. Bigger
glyphs meant 80x25 instead of 160x50, and mainline fbcon has *no scrollback*, so
the halved screen cost us multi-line output permanently. The extra rows/columns
matter more than glyph size. Full reasoning and how to redo it:
[[file:framebuffer.org][framebuffer.org]] §7.

Kernel source for this subsystem, if you want to read it:
[[file:../linux/drivers/video/fbdev/efifb.c][linux → drivers/video/fbdev/efifb.c]] (the dumb driver),
[[file:../linux/drivers/video/fbdev/core/fb_chrdev.c][linux → drivers/video/fbdev/core/fb_chrdev.c]] (the =/dev/fb0= read/write/mmap
entry points) and [[file:../linux/drivers/video/fbdev/core/fbcon.c][linux → drivers/video/fbdev/core/fbcon.c]] (glyph → pixels, with the
actual bit-stamping in [[file:../linux/drivers/video/fbdev/core/bitblit.c][bitblit.c]]).

Why it matters: real UEFI has *no legacy VGA text mode*. Without efifb+fbcon
the laptop screen stays blank even though the kernel is running fine. This was
the original "it booted but showed nothing" bug.

* 3. Input — why you can type (the PCI saga)

| Option                                               | State | Role                                                                         |
|------------------------------------------------------+-------+------------------------------------------------------------------------------|
| =CONFIG_PCI=                                         | y     | *Keystone* — without it: no USB AND no ACPI S5                               |
| =CONFIG_PCI_MSI=                                     | y     | Message-signalled interrupts                                                 |
| =CONFIG_PCIEPORTBUS=                                 | y     | PCIe port bus driver                                                         |
| =CONFIG_USB_SUPPORT= / =CONFIG_USB=                  | y     | USB core                                                                     |
| =CONFIG_USB_XHCI_HCD= / =_PCI=                       | y     | USB 3.x host controller (modern laptop ports)                                |
| =CONFIG_USB_EHCI_HCD= / =_PCI=                       | y     | USB 2.0 host controller                                                      |
| =CONFIG_USB_OHCI_HCD= / =_PCI=                       | y     | USB 1.x host controller                                                      |
| =CONFIG_USB_HID= / =CONFIG_HID=                      | y     | Interpret a USB keyboard as keystrokes                                       |
| =CONFIG_I2C= + =I2C_HID= + =_ACPI=                   | y     | Internal I2C-HID keyboard bus (laptops)                                      |
| =CONFIG_I2C_DESIGNWARE_CORE/_PLATFORM=               | y     | The common laptop I2C controller                                             |
| =CONFIG_SERIO= + =INPUT_KEYBOARD= + =KEYBOARD_ATKBD= | y     | Legacy PS/2 keyboard (QEMU + old machines)                                   |
| =CONFIG_INPUT_EVDEV=                                 | y     | =/dev/input/event*= layer — the mouse, the wheel, modifier state ([[file:input.org][input.org]]) |
| =CONFIG_INPUT_MOUSEDEV=                              | *n*   | deliberately OFF — why there is no =/dev/input/mouseN= to look for           |
| =CONFIG_MOUSE_PS2=                                   | y     | PS/2 mouse + laptop touchpad (QEMU's pointer)                                |

Root-cause story: =CONFIG_PCI= was OFF in early builds. Everything used *early*
in boot (EFI framebuffer, RAM rootfs, PS/2 keyboard in QEMU) is non-PCI, so the
gap was invisible — until a real laptop needed USB (xHCI is a PCI device) for
its keyboard, AND ACPI needed PCI config-space operation regions for =_S5=
(power-off). Enabling PCI fixed BOTH the dead keyboard and the power-off halt.

In the tree, the chain a keypress travels: [[file:../linux/drivers/usb/host/xhci.c][=drivers/usb/host/xhci.c=]] (the USB
3.x host controller, the PCI device that made =CONFIG_PCI= mandatory) →
[[file:../linux/drivers/hid/usbhid/hid-core.c][=drivers/hid/usbhid/hid-core.c=]] (turn USB HID reports into HID events) →
[[file:../linux/drivers/hid/hid-input.c][=drivers/hid/hid-input.c=]] (HID → input subsystem key codes) →
[[file:../linux/drivers/input/evdev.c][=drivers/input/evdev.c=]], which is what creates =/dev/input/event*= — the same
nodes [[file:../initramfs/fb-browser.lisp][=fb-browser.lisp=]] polls for the browser's mouse and Ctrl detection
(the full mechanism: [[file:input.org][input.org]]; what the browser does with it:
[[file:code-browser.org][code-browser.org]] §6.3). The PS/2 path used under QEMU is
[[file:../linux/drivers/input/keyboard/atkbd.c][=drivers/input/keyboard/atkbd.c=]] on top of =serio=.

* 4. Platform & power

| Option                    | State | Role                                                         |
|---------------------------+-------+--------------------------------------------------------------|
| =CONFIG_ACPI=             | y     | Power-off (=reboot(RB_POWER_OFF)= -> =_S5=); depends on PCI  |
| =CONFIG_ACPI_BATTERY=     | y     | The battery in =/sys/class/power_supply/BAT0/= (the systray) |
| =CONFIG_ACPI_AC=          | y     | The adapter's =online= file (=/sys/class/power_supply/AC/=)  |
| =CONFIG_POWER_SUPPLY=     | y     | The sysfs class both register into; =select=-ed by both      |
| =CONFIG_RTC_MC146818_LIB= | y     | Reading the CMOS clock at boot; =select=-ed by =config X86=  |
| =CONFIG_RTC_CLASS=        | n     | Not needed: x86 reads the CMOS clock itself (no =/dev/rtc=)  |

The path from our Lisp to the machine actually stopping: [[file:../initramfs/process.lisp::defun power-off][=power-off=]] FFI-calls
=reboot(2)=, which lands in [[file:../linux/kernel/reboot.c][=kernel/reboot.c=]]; for =RB_POWER_OFF= that ends in
ACPI's =_S5= handling in [[file:../linux/drivers/acpi/sleep.c][=drivers/acpi/sleep.c=]]. This is why the option depends
on PCI: evaluating =_S5= needs ACPI operation regions that address PCI config
space, so with =CONFIG_PCI= off the shutdown silently halted instead.

The battery and AC rows were never chosen by hand — both are =default y= under
=CONFIG_ACPI= in [[file:../linux/drivers/acpi/Kconfig][=drivers/acpi/Kconfig=]], so they arrived with it at tag #19
and sat unused until the browser's systray read them. Listed here because the tray
now depends on them. Likewise the clock: with =RTC_CLASS= off there is no RTC
driver, yet the system time is right at boot, because x86's =timekeeping_init()=
path reads the CMOS chip directly through =RTC_MC146818_LIB=. Both stories, and why
the RTC must hold UTC: [[file:systray.org][systray.org]]. (Checked at tag #24 — no rebuild involved.)

* 7. Networking (IPv4 + QEMU virtio-net) — NEW in tag #21

The kernel half of the network stack (the roadmap in [[file:networking.org][networking.org]] §1). The bus
plumbing a NIC needs — =CONFIG_PCI= + =CONFIG_PCI_MSI= — was already on from #19.
Everything here is built-in (=y=), never a module: we ship no modules and have no
=modprobe=.

| Option              | State | Role                                                          |
|---------------------+-------+---------------------------------------------------------------|
| =CONFIG_NET=        | y     | The socket / protocol core — the master switch                |
| =CONFIG_INET=       | y     | IPv4 (TCP, UDP, ICMP) — the thing we actually want            |
| =CONFIG_UNIX=       | y     | AF_UNIX local sockets (useful even before a NIC has an IP)    |
| =CONFIG_PACKET=     | y     | AF_PACKET raw sockets (some DHCP clients use it)              |
| =CONFIG_NETDEVICES= | y     | The network-device layer (gate for any NIC driver)            |
| =CONFIG_NET_CORE=   | y     | Core netdev machinery (auto-selected)                         |
| =CONFIG_VIRTIO=     | y     | Virtio core                                                   |
| =CONFIG_VIRTIO_PCI= | y     | Virtio-over-PCI transport                                     |
| =CONFIG_VIRTIO_NET= | y     | The QEMU paravirtual NIC driver — binds =[1af4:1000]= as eth0 |

Where each of these lives in the tree: the socket layer every =sb-bsd-sockets=
call enters through is [[file:../linux/net/socket.c][=net/socket.c=]]; IPv4 registers itself in
[[file:../linux/net/ipv4/af_inet.c][=net/ipv4/af_inet.c=]] and the interface-configuration ioctls of
[[file:networking.org][networking.org]] §2b land in [[file:../linux/net/ipv4/devinet.c::devinet_ioctl][=net/ipv4/devinet.c='s =devinet_ioctl=]]; the virtio
core that =VIRTIO_PCI= plugs drivers into is [[file:../linux/drivers/virtio/virtio.c][=drivers/virtio/virtio.c=]].

Verified (tag #21): under QEMU =-device virtio-net-pci= the NIC enumerates on PCI
(=pci 0000:00:02.0: [1af4:1000] ... class 0x020000=), and =virtio_net=
([[file:../linux/drivers/net/virtio_net.c][linux → drivers/net/virtio_net.c]]) binds it. At that tag the supervisor's
=show-net-interfaces= diagnostic listed =eth0 (down)= — no IP yet, because
addressing is a userland job. The QEMU SLIRP wiring (=-netdev user,...hostfwd...=)
lives in [[file:../build.sh::QEMU_NET][build.sh → QEMU_NET]] and [[file:networking.org][networking.org]] §4.

*The userland half has since landed too* — =sb-bsd-sockets= is baked into the
image, [[file:../initramfs/dhcp.lisp::defun configure-eth0][dhcp.lisp → configure-eth0]] leases an address at boot via a real
DISCOVER/REQUEST handshake, and [[file:../initramfs/net.lisp::defun start-net-repl][net.lisp → start-net-repl]] serves a REPL on
TCP :4005. So the whole wired path is working end to end; see [[file:networking.org][networking.org]].

What is still OFF on the kernel side: real-hardware NIC drivers (=CONFIG_E1000=,
=CONFIG_R8169=, …), all Wi-Fi (=CFG80211=/=MAC80211= + firmware + WPA), and IPv6
(see below).

/Tried and dropped:/ =CONFIG_MAC80211_HWSIM= would have let QEMU emulate Wi-Fi
radios, but built in (we have no modules) it creates two fake radios on *every*
boot, the laptop's included, which shifts interface names and clutters the scan.
Wi-Fi is therefore tested only on the laptop.

/Regulatory database:/ =CFG80211_REQUIRE_SIGNED_REGDB= defaults on with
=CFG80211_USE_KERNEL_REGDB_KEYS=, which trusts the in-tree keys (=sforshee=,
=wens=, printed at boot). So the =regulatory.db= in the initramfs must be the
/upstream/-signed one, not Debian's. Without it the boot logs
=cfg80211: failed to load regulatory.db= and the radio is held to the world
domain — harmless, only slower.

* 9. Sound — NEW in tag #29

Tag #29 (2026-10-17) gives the image sound, for screencasts recorded with the user's
voice and for playing them back ([[file:screencast.org][screencast.org]], whose §2–§3 hold the hardware
evidence). The laptop (Dell XPS 13 9300) has Intel's Ice Lake audio controller
(=8086:34c8=) with a *Realtek ALC289* codec, and its microphones — the built-in one
and the headset jack's — are analogue, on that codec. Debian's own kernel drives it
with plain =snd_hda_intel= (=snd_intel_dspcfg.dsp_driver= = 0 chose it), so no DSP
driver and no firmware are needed.

* Deliberately OFF (and what it would take to turn on)

** Sound through the DSP, HDMI audio, USB and Bluetooth audio — OFF (tag #29)

- =SND_SOC= (SOF, AVS): the Intel DSP path. Needed on laptops whose microphones are
  digital and wired to the DSP; this one's are analogue, on the codec (§9). It would
  also need the DSP's firmware and topology copied from the host.
- =SND_HDA_CODEC_HDMI=: sound over HDMI/DisplayPort wants i915's audio component
  (=SND_HDA_I915=); we run on efifb with no i915.
- =SND_USB_AUDIO=: a USB headset. The user's headset is wired to the jack; one option
  turns it on if that changes (no firmware).
- Bluetooth: the whole stack, the AX201's Bluetooth firmware, and a sound server for
  the hands-free profile — ruled out in [[file:screencast.org][screencast.org]] §2.1.

** Other storage — SATA/AHCI, USB mass storage, vfat, modules — OFF (tag #25)
Only the path to /this/ laptop's disk is built: NVMe → GPT → ext4. =ATA=/=SATA_AHCI=
(a SATA disk), =USB_STORAGE= + =SCSI= + =BLK_DEV_SD= (the boot stick, or any USB
drive) and =VFAT_FS= (the ESP, most sticks) stay off until something needs them.
=CONFIG_MODULES= stays off too: everything is built in, so there is no =modprobe=
and no =/lib/modules= to keep in step. Reasons and the rest: [[file:storage.org][storage.org]] §2.

** IPv6 — was OFF until tag #26 (now ON, §8)

The paragraph below is the reasoning that held from #21 to #25, kept for the record.

=olddefconfig= would default =CONFIG_IPV6=y= the moment =INET= is on; we set
=# CONFIG_IPV6 is not set= on purpose (networking.org §5 scope guard). Everything
we want first — static IPv4 under QEMU SLIRP, a UDP/TCP "hello" — is IPv4. Turn
=CONFIG_IPV6=y= back on if/when an IPv6 path actually matters.

** Wired real-hardware NICs — OFF (Wi-Fi is ON since tag #26, §8)

For wired links only =virtio-net= (QEMU) is built in (the laptop has no wired port). A laptop's wired chip is one more =y=
(=CONFIG_R8169= / =CONFIG_E1000E=); Wi-Fi is a whole subsystem
(=CFG80211=+=MAC80211= + vendor driver + firmware blobs in the initramfs + a WPA
supplicant) and is a separate, later project. See [[file:networking.org][networking.org]] §1.

** Hardware RNG — OFF (entropy comes the slow way)

=CONFIG_HW_RANDOM= is not set, so there is no hwrng framework and no =virtio-rng=
driver, and the QEMU line passes no RNG device. The kernel therefore seeds its
CRNG only from interrupt/input timing; on this idle VM that often completes only
once you start *typing* — the =random: crng init done= line that lands in the
middle of the REPL prompt. Harmless: nothing here needs secure randomness at
boot. To seed instantly instead: =CONFIG_HW_RANDOM=y= + =CONFIG_HW_RANDOM_VIRTIO=y=
and add =-device virtio-rng-pci= to the QEMU line in =build.sh=. Full story:
[[file:background/background.org][background.org]] §8.

** Legacy BSD PTYs — OFF (tag #22)

=# CONFIG_LEGACY_PTYS is not set=. The legacy scheme pre-allocated a *fixed pool*
(=CONFIG_LEGACY_PTY_COUNT=, was 256) of =/dev/pty??= master + =/dev/tty??= slave
nodes, which =devtmpfs= then exposed — 512 unused nodes cluttering =/dev= (the
=/dev/ptya1= et al. you would see in a directory listing). Modern PTYs use
=CONFIG_UNIX98_PTYS= (=/dev/ptmx= mints =/dev/pts/N= on demand), which stays ON,
so nothing real is lost; turning legacy off just declutters =/dev=. (Unix98 PTYs
are unused so far anyway — see [[file:networking.org][networking.org]] §6b: a Dropbear-style PTY session
would only need =preinit= to mount =devpts=, no kernel change.)

** binfmt_misc — OFF; not needed (would only delegate to an ELF interpreter).
