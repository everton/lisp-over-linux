#+TITLE: Micro EFISTUB Linux — no bootloader, boots from USB via UEFI
#+STARTUP: showall

A *very* minimal Linux that a UEFI machine boots straight from a USB stick, with
*no GRUB, systemd-boot or any bootloader*. The kernel itself is the EFI
application (EFISTUB), and a tiny static =/init= prints a banner and stays alive.

This is the *base variant*: the smallest thing that boots. The project's real
image replaces =/init= with SBCL ([[file:sbcl-init.org][sbcl-init.org]]) but keeps this boot chain.

  initramfs.

* Goal

#+begin_example
  UEFI firmware -> \EFI\BOOT\BOOTX64.EFI (== the kernel) -> embedded initramfs
                -> /init -> banner on the EFI framebuffer console
#+end_example

- *Status.* Works in QEMU + OVMF (UEFI) and on real hardware (a Dell XPS 13 9300).
- *Kernel.* linux-7.2.5. Tag #16 was the first working build (glibc init), #17
  the same with a musl init ("Shrinking init with musl libc" below). Every tag since: [[file:kernel-config.org][kernel-config.org]]'s
  change log.
- *Medium.* A USB stick with GPT and one ESP (type =ef00=, FAT32), the kernel
  copied to =\EFI\BOOT\BOOTX64.EFI=.

* Pitfalls: why a first attempt doesn't boot

Each of these, alone, makes the machine "not boot". All are fixed by the steps below.

1. *=BOOTX64.EFI= isn't the kernel.* With EFISTUB the bzImage *is* the EFI app,
   so =BOOTX64.EFI= must be a literal copy of =arch/x86/boot/bzImage=. Check: =file=
   says "Linux kernel x86 boot executable, bzImage ... 64-bit EFI handoff entry
   point", and the first bytes are =MZ=.
2. *=init= exits.* When PID 1 returns, the kernel panics ("Attempted to kill
   init!"). PID 1 must loop forever.
3. *No initramfs embedded.* =CONFIG_INITRAMFS_SOURCE= left empty means no =/init=.
4. *No =/dev/console= and =DEVTMPFS= off.* Userspace has nowhere to print — a
   silent boot.
5. *No framebuffer console — the real-hardware killer.* =CONFIG_VGA_CONSOLE=
   alone (legacy VGA text) works in QEMU, but a real UEFI machine has *no* VGA
   text mode, only a GOP linear framebuffer. Without =efifb= + =fbcon= the kernel
   runs fine and the screen stays blank, which looks exactly like a failure.
6. *No serial console (debugging only).* With =SERIAL_8250_CONSOLE= off,
   =console=ttyS0= prints nothing, and headless QEMU debugging is blind.

*KVM vs TCG.* Every QEMU launch here passes =-machine q35,accel=kvm:tcg=: KVM
(the guest runs on the real CPU) with a fallback to TCG (QEMU translating every
instruction in software). The difference is large — one browser frame cost 67 ms
under TCG against 6.5 ms under KVM at 1280x800 (tag #24, [[file:framebuffer.org][[[file:framebuffer.org::#done-blit-single-copy][framebuffer.org, DONE: the blit is a single copy]]]]).

- *Check access.* =test -r /dev/kvm -a -w /dev/kvm=.
- *Pitfall: the =kvm= group isn't required.* udev tags =/dev/kvm= =uaccess=, so
  logind grants an ACL to whoever is logged in at the seat (=getfacl /dev/kvm=
  shows =user:<user>:rw-=; =ls -l= shows a trailing =@=).

* Step 1 — the init program

=initramfs/init.c= mounts the basics, prints a banner and never returns:

#+begin_src c :tangle initramfs/init.c
  /* Minimal PID 1 for a no-bootloader EFISTUB Linux.
   * Must NEVER return — when PID 1 exits the kernel panics. */
  #include <stdio.h>
  #include <unistd.h>
  #include <sys/mount.h>

  int main(void) {
      /* Best-effort: errors are fine if a node/dir is missing. */
      mount("proc",     "/proc", "proc",     0, NULL);
      mount("sysfs",    "/sys",  "sysfs",    0, NULL);
      mount("devtmpfs", "/dev",  "devtmpfs", 0, NULL);

      printf("vvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvv\n");
      printf("                      Hello from EFISTUB micro-linux!                          \n");
      printf("                  Kernel booted directly by UEFI, no bootloader.               \n");
      printf("^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^\n");
      fflush(stdout);

      /* Stay alive forever so the kernel never panics. */
      for (;;)
          pause();

      return 0;
  }
#+end_src

Build it *statically*, so the initramfs needs no libc:

#+begin_src sh :results output
  cd initramfs
  gcc -static -O2 -s -o init init.c
  file init    # => ELF 64-bit ... statically linked
#+end_src

* Step 2 — the initramfs contents (gen_init_cpio list)

Don't hand-roll a cpio. Hand the kernel a *gen_init_cpio* description file via
=CONFIG_INITRAMFS_SOURCE=; kbuild turns it into the embedded cpio at build time,
and it can create device nodes *without root*.

=initramfs/initramfs.list= (the =file= line needs the absolute path of the built
=init=):

#+begin_src text :tangle initramfs/initramfs.list
  # gen_init_cpio description file (used by CONFIG_INITRAMFS_SOURCE).
  # Creates device nodes WITHOUT needing root on the build host.
  dir  /dev          0755 0 0
  nod  /dev/console  0600 0 0 c 5 1
  nod  /dev/null     0666 0 0 c 1 3
  nod  /dev/tty      0666 0 0 c 5 0
  dir  /proc         0755 0 0
  dir  /sys          0755 0 0
  file /init /path/to/lisp-over-linux/initramfs/init 0755 0 0
#+end_src

The alternative, =cd initramfs && echo init | cpio -o -H newc > initramfs.cpio=
with =CONFIG_INITRAMFS_SOURCE= pointing at that =.cpio=, also works but can't make
=/dev/console= without root.

* Step 3 — kernel configuration

Start from the x86_64 default config, then apply the deltas that make EFISTUB +
embedded initramfs + a *visible* console work. From the project root:

#+begin_src sh :results output
  PROJECT=$(pwd)
  cd linux
  make defconfig          # base = x86_64_defconfig
  ./scripts/config \
    --enable  EFI \
    --enable  EFI_STUB \
    --set-str INITRAMFS_SOURCE "$PROJECT/initramfs/initramfs.list" \
    --enable  BLK_DEV_INITRD \
    --enable  DEVTMPFS \
    --enable  DEVTMPFS_MOUNT \
    --enable  CMDLINE_BOOL \
    --set-str CMDLINE "console=ttyS0,115200 console=tty0" \
    --disable CMDLINE_OVERRIDE \
    --enable  SERIAL_8250 \
    --enable  SERIAL_8250_CONSOLE \
    --enable  SERIAL_8250_PCI \
    --enable  FB \
    --enable  FB_EFI \
    --enable  FRAMEBUFFER_CONSOLE \
    --enable  FRAMEBUFFER_CONSOLE_DETECT_PRIMARY
  make olddefconfig
#+end_src

| Option                         | Why                                                                                                                                                                        |
|--------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =EFI= / =EFI_STUB=             | Make the bzImage a launchable UEFI app (PE/COFF, "MZ")                                                                                                                     |
| =INITRAMFS_SOURCE=             | Embed the initramfs *inside* the kernel: one self-contained file                                                                                                            |
| =BLK_DEV_INITRD=               | initramfs support                                                                                                                                                          |
| =DEVTMPFS= (+ =_MOUNT=)        | An automatic =/dev=, so userspace has device nodes                                                                                                                         |
| =CMDLINE_BOOL= / =CMDLINE=     | A built-in command line: with no bootloader nobody types one. The LAST =console== (=tty0=) becomes =/dev/console= for init, i.e. the screen                                |
| =CMDLINE_OVERRIDE= off         | Still merge a command line the EFI launcher passes (e.g. =efibootmgr -u=)                                                                                                  |
| =SERIAL_8250_CONSOLE=          | A real =console=ttyS0= for headless QEMU debugging                                                                                                                         |
| =FB= + =FB_EFI= + =FRAMEBUFFER_CONSOLE= | *The* fix for a visible screen on real hardware: efifb drives the UEFI GOP framebuffer and fbcon renders text on it                                               |

** Real-hardware input (PCI/USB/HID) — and why ACPI power-off needs PCI too
:PROPERTIES:
:CUSTOM_ID: real-hardware-input
:END:

=defconfig= plus the deltas above boots in QEMU and shows the screen on real
hardware — but there the *keyboard is dead* and ACPI power-off only halts. Both
come from one missing switch: =CONFIG_PCI=.

- *Why QEMU hides it.* Everything used early is non-PCI: the EFI framebuffer
  (mapped by firmware), the initramfs (RAM), QEMU's PS/2 keyboard (i8042, on the
  LPC bus).
- *The keyboard.* A laptop keyboard is USB or I2C-HID, and the USB xHCI
  controller is a *PCI device*. No PCI, no USB, no keyboard.
- *Power-off.* The DSDT declares operation regions in PCI *config space*. With
  PCI off, ACPI rejects the DSDT ("Unable to load the System Description
  Tables"), so there's no =\_S5= and power-off halts.

Enable PCI, the USB stack and the HID transports (all built in; there are no
modules to load):

#+begin_src sh
  cd linux
  ./scripts/config \
    --enable PCI --enable PCI_MSI --enable PCIEPORTBUS \
    --enable USB_SUPPORT --enable USB --enable USB_PCI \
    --enable USB_XHCI_HCD --enable USB_XHCI_PCI \
    --enable USB_EHCI_HCD --enable USB_EHCI_PCI \
    --enable USB_OHCI_HCD --enable USB_OHCI_HCD_PCI --enable USB_UHCI_HCD \
    --enable USB_HID --enable HID_GENERIC --enable INPUT_EVDEV \
    --enable I2C --enable I2C_HID --enable I2C_HID_ACPI \
    --enable I2C_DESIGNWARE_CORE --enable I2C_DESIGNWARE_PLATFORM
  make olddefconfig
#+end_src

Verify in QEMU with an emulated USB keyboard (=-device qemu-xhci -device usb-kbd=):
dmesg shows "xhci_hcd ... xHCI Host Controller" and "input: QEMU QEMU USB
Keyboard ...", and power-off prints "reboot: Power down" and the VM exits (tag #19).

Sanity-check the resulting =.config=:

#+begin_src sh :results output
  cd linux
  grep -E 'CONFIG_EFI_STUB|CONFIG_INITRAMFS_SOURCE|CONFIG_DEVTMPFS=|CONFIG_CMDLINE|CONFIG_SERIAL_8250_CONSOLE|CONFIG_FB=|CONFIG_FB_EFI=|CONFIG_FRAMEBUFFER_CONSOLE=' .config
#+end_src

* Step 5 — assemble the EFI boot file

With EFISTUB, "installing the bootloader" is one copy. The UEFI *removable-media
fallback path* is =\EFI\BOOT\BOOTX64.EFI= (x86-64), which firmware launches off a
USB stick with no NVRAM boot entry.

#+begin_src sh :results output
  mkdir -p iso_root/efi/boot
  cp linux/arch/x86/boot/bzImage iso_root/efi/boot/bootx64.efi
  file iso_root/efi/boot/bootx64.efi   # must say: Linux kernel ... bzImage
#+end_src

* Testing in QEMU (no root, no real USB needed)

** A. Quick check: boot the kernel directly (no EFI) — isolates init/initramfs

#+begin_src sh :results output
  : > serial.log
  timeout 40 qemu-system-x86_64 -machine q35,accel=kvm:tcg -m 1024 \
    -kernel linux/arch/x86/boot/bzImage \
    -append "console=ttyS0,115200" \
    -serial file:serial.log -display none -no-reboot
  grep -E 'Run /init|Hello' serial.log
#+end_src

Expect "Run /init as init process", then the banner. Exit code 124 is normal:
=timeout= kills the VM because =/init= loops forever.

** B. The real thing: boot via OVMF as a UEFI app (== the USB boot path)

QEMU's VVFAT exposes =iso_root/= as a virtual FAT disk, so this tests the exact
=\EFI\BOOT\BOOTX64.EFI= fallback launch.

#+begin_src sh :results output
  cp /usr/share/OVMF/OVMF_VARS_4M.fd ovmf_vars_test.fd   # writable NVRAM

  qemu-system-x86_64 -machine q35,accel=kvm:tcg -m 1024 \
    -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE_4M.fd \
    -drive if=pflash,format=raw,file=ovmf_vars_test.fd \
    -drive file=fat:rw:iso_root,format=raw,if=ide \

* Writing to a real USB stick  (DESTRUCTIVE — pick the right device!)

The kernel-as-=BOOTX64.EFI= needs only a *FAT32 EFI System Partition* on a GPT
disk. The removable-media fallback means no =efibootmgr= entry on the target.

** Identify the device FIRST

#+begin_src sh
  lsblk -o NAME,SIZE,TRAN,MODEL        # find the USB, e.g. /dev/sdX (NOT a partition)
#+end_src

*The SBCL image is TWO files, not one.* It ships a *separate initrd*
([[file:sbcl-init.org][sbcl-init.org]]), found through the built-in
=CONFIG_CMDLINE="… initrd=initramfs.cpio"=, which resolves relative to the ESP
root:

#+begin_example
  \EFI\BOOT\BOOTX64.EFI    the kernel (4.6 MB at #32), an EFI app in its own right
  \initramfs.cpio          the SBCL world (74 MB at #32), loaded by EFISTUB at boot
#+end_example

Copy only the kernel and it panics with "No working init found". =./build.sh=
leaves both in =iso_root/= in that shape, so the copy mirrors that directory.
(The base and musl variants embed the initramfs: one file.)

** Partition (GPT, one ESP) + format FAT32 + copy BOTH files

#+begin_src sh
  DEV=/dev/sdX                          # <-- set this to YOUR usb stick, double-check!
  sudo sgdisk --zap-all "$DEV"
  sudo sgdisk -n1:0:0 -t1:ef00 -c1:"EFI" "$DEV"   # ef00 = EFI System Partition
  sudo mkfs.vfat -F32 "${DEV}1"
  sudo mount "${DEV}1" /mnt
  sudo mkdir -p /mnt/EFI/BOOT
  sudo cp iso_root/efi/boot/bootx64.efi /mnt/EFI/BOOT/BOOTX64.EFI
  sudo cp iso_root/initramfs.cpio       /mnt/initramfs.cpio
  sync; sudo umount /mnt
#+end_src

Refreshing an existing stick is just the two =cp= lines; =./build.sh= prints them
when it finishes.

** Alternative without mounting (mtools)

#+begin_src sh
  DEV=/dev/sdX
  sudo sgdisk --zap-all "$DEV"
  sudo sgdisk -n1:0:0 -t1:ef00 -c1:"EFI" "$DEV"
  sudo mkfs.vfat -F32 "${DEV}1"
  mmd   -i "${DEV}1" ::/EFI ::/EFI/BOOT
  mcopy -i "${DEV}1" iso_root/efi/boot/bootx64.efi ::/EFI/BOOT/BOOTX64.EFI
  mcopy -i "${DEV}1" iso_root/initramfs.cpio       ::/initramfs.cpio
#+end_src

** Boot it on the machine

1. *Open the firmware boot menu.* The key is vendor-specific (F12/F9/F10/Esc at
   power-on).
2. *Pick the stick's UEFI entry*, e.g. "UEFI: <stick model>" — not a legacy/CSM entry.
3. *Turn Secure Boot off* (or sign the kernel with =sbsign= and enrolled keys): an
   unsigned EFISTUB kernel won't launch under Secure Boot.
4. *What you should see.* A few kernel log lines and the supervisor's
   diagnostics, then the code browser full screen — PID 1 is SBCL. =SuperL-q=
   leaves it for the supervisor menu: =b= reopens the browser, =r= is a REPL, =s=
   powers off. (The base variant shows the banner and waits.)

** Troubleshooting by where it stops (tells you the failing layer)

| Symptom                                                  | Layer and fix                                                                                                                                                                                                  |
|----------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Panic: "No working init found" / "Kernel panic - not syncing" | The kernel booted but found no userland: =\initramfs.cpio= is missing from the ESP *root* (not a subdirectory) or was copied short. Check its size on the stick and that the FAT32 had room                |
| Stick not listed in the boot menu                        | ESP / partition type (needs GPT + type =ef00= + FAT32), or Secure Boot hiding it                                                                                                                              |
| Firmware error, or straight back to the boot menu         | The firmware found =BOOTX64.EFI= but couldn't launch it: Secure Boot blocking an unsigned image, or a corrupt/short copy. Re-check =file BOOTX64.EFI=                                                        |
| Blank screen, machine doesn't reboot                     | The kernel runs with no visible console. Confirm =FB_EFI= + =FRAMEBUFFER_CONSOLE= are =y=; if a GPU driver steals the GOP, try =SYSFB_SIMPLEFB= + =DRM_SIMPLEDRM= + =DRM_FBDEV_EMULATION=. Add =earlyprintk=efi= to debug |
| Garbled text / wrong resolution                          | Cosmetic; tune the EFI framebuffer or pass =video==                                                                                                                                                            |

* Booting from the host's GRUB (no USB stick)

If the machine already runs a Linux with GRUB, the same two files can live in the
host's =/boot= as one more boot-menu entry. The image doesn't change; only *who
loads it* does — GRUB instead of the firmware's removable-media path. This works
on the XPS 13 (since tag #24).

** Where the files go, and why not the ESP

They go in =/boot/lisp/= on the host's root filesystem, *not* the EFI System
Partition.

- *=/boot= on the root fs.* On a typical Debian install =/boot= is a directory on
  the ext4 root, which GRUB reads natively. =df -h /boot /boot/efi= shows whether
  they're different filesystems.
- *The ESP is small and shared.* Often 512 MB of FAT32, used by the firmware and
  GRUB; no reason to put a large cpio there.
- *Pitfall: encryption.* This needs an *unencrypted* =/boot=; GRUB can't read
  through LUKS without extra modules.

#+begin_src sh
  ./build.sh --install-host      # build, then copy both files to /boot/lisp (sudo)
#+end_src

=--install-host= copies =iso_root/efi/boot/bootx64.efi= → =/boot/lisp/bzImage= and
=iso_root/initramfs.cpio= → =/boot/lisp/initramfs.cpio=, each only if =cmp= says it
changed. =build.sh= refreshes =bootx64.efi= only under =--kernel=, as for the stick.

** The menuentry (one time)

Put this in a script under =/etc/grub.d/= that =cat=s its body into =grub.cfg=
(=40_custom= is such a script), then run =sudo update-grub=:

#+begin_example
  menuentry "Lisp over Linux (SBCL as PID 1)" {
      search --no-floppy --file /boot/lisp/bzImage --set=root
      set gfxpayload=keep
      linux  /boot/lisp/bzImage
      initrd /boot/lisp/initramfs.cpio
  }
#+end_example

- *=search --file ... --set=root=* finds the partition by the file, not by a disk
  number that could shift when a USB stick is plugged in.
- *=gfxpayload=keep=* hands the kernel the GOP mode GRUB is in, which =efifb= (and
  so =/dev/fb0= and fbcon) inherits.
- *No kernel arguments.* The built-in =CONFIG_CMDLINE= still applies
  (=CMDLINE_OVERRIDE= is off); GRUB's empty line is merged with it.
- *Pitfall: =update-grub= doesn't announce custom entries.* It lists only the
  kernels it detected. Confirm with =grep -A5 "Lisp over Linux" /boot/grub/grub.cfg=.
  After that, rebuilding needs only =--install-host=: GRUB reads the files at boot.

*Make it the default if the image restarts itself.* A restart through the
firmware lands on GRUB's default entry (kexec, tag #31, skips GRUB entirely). The
=/etc/grub.d/= scripts run in name order, so naming the script =06_lisp= — before
=10_linux= — makes our entry the first, and the default with =GRUB_DEFAULT=0=. In
=40_custom= it comes last, and a firmware restart boots the host distribution.

** The =initrd=initramfs.cpio= in the built-in cmdline is harmless here

That parameter tells the EFI stub to load =\initramfs.cpio= from the root of its
own volume — right for the stick, meaningless for a kernel on ext4. It's never
used: GRUB's =initrd= publishes the cpio through a special EFI device path
(=LINUX_EFI_INITRD_MEDIA_GUID=), which the stub tries *first*, falling back to the
cmdline only when that path is absent (=EFI_NOT_FOUND=). See =efi_load_initrd()= in
=linux/drivers/firmware/efi/libstub/efi-stub-helper.c=.

** Two alternatives, and why not

- *GRUB =chainloader= of the bzImage as an EFI app.* Closest to the USB boot, but
  the file must sit on the ESP, and the built-in =initrd== then resolves to the ESP
  *root* — the cpio would have to be =/boot/efi/initramfs.cpio=.
- *A firmware boot entry* (=efibootmgr -c -d /dev/nvme0n1 -p 1 -L Lisp -l
  '\EFI\lisp\bootx64.efi'=). The purest EFISTUB path — GRUB never runs, you pick it
  from the firmware's menu — with the same ESP-root constraint on the cpio.

** Updating from inside the environment

Since tag #31 the image installs its own successor: build in the terminal, then
=SuperL-q= → *Install the new build and restart*. lol-rootd copies the pair into
=/boot/lisp= (keeping the old one as =*.prev=) and the image kexecs into it.
Details: [[file:sbcl-init.org::Updating from inside — build, install, restart][sbcl-init.org → Updating from inside]]. From the host distribution,
=--install-host= does the same.

** Safety

- *The host's disk is visible on purpose* (since tag #25). preinit mounts the
  host's root privately — =/= read-only at =/mnt/host=, only =/home= writable — and
  runs the environment as the user, so it can write nowhere the user couldn't
  ([[file:storage.org][storage.org]]).
- *One exception.* On request, lol-rootd writes a new build into =/boot/lisp= and
  nothing else (tag #31).
- *Pitfall: hibernation.* Don't boot the image while the host is hibernated:
  mounting a filesystem a sleeping kernel holds open corrupts it.
- *Secure Boot off.* As for the stick: GRUB's =linux= command refuses an unsigned
  kernel under shim.

* Shrinking init with musl libc
:PROPERTIES:
:CUSTOM_ID: shrinking-init-musl
:END:

Every C program needs a libc: =printf=, =malloc=, the startup code that calls
=main=, the syscall wrappers. Debian's default is *glibc*, large and not designed
for static linking. *musl* is a small MIT-licensed libc built for static linking
from the start (Alpine Linux uses it). Same source, different libc.

- *They're not ABI-compatible.* A *prebuilt* glibc binary wants glibc's loader,
  =libc.so.6= and =GLIBC_x.y= symbols; it won't run against musl. musl only helps
  for what you compile yourself.
- *Rule of thumb.* Building from source → musl (tiny static binaries). Prebuilt
  glibc binary → glibc (or a compat shim like Alpine's gcompat). Static linking
  with either → self-contained, no =libc.so= in the rootfs.
- *Why the image still ships glibc.* SBCL itself is a glibc-*dynamic* binary
  ([[file:sbcl-init.org][sbcl-init.org]]). Only building SBCL against musl would change that.
- *The other direction.* A musl-static program loading a glibc =.so= at runtime
  has a demonstrated answer: [[https://github.com/pg83/solo][pg83/solo]] links an ELF loader plus a glibc→musl ABI
  shim into the static binary (its case: vendor GPU drivers, shipped only as
  glibc =.so=s). The shim has to reimplement symbol versioning, all four TLS
  models, IFUNC resolvers, C++ exception unwinding and =getcontext=/=makecontext=.
  Nothing here needs it; the one hypothetical where it would come up is
  [[file:framebuffer.org::#gpu-give-up-real][framebuffer.org, No GPU — what we give up, and what a real driver would cost]].

Install the toolchain (it provides the =musl-gcc= wrapper) and swap the compiler:

#+begin_src sh :results output
  sudo apt install -y musl-tools
  cd initramfs
  gcc      -static -O2 -s -o init.glibc init.c   # for comparison
  musl-gcc -static -O2 -s -o init.musl  init.c
  cp init.musl init                              # initramfs.list points /init here
  stat -c '%s  %n' init.glibc init.musl
#+end_src

| Build (same source, =-static -O2 -s=) | Size                                |
|---------------------------------------+-------------------------------------|
| glibc static                          | 690,536 bytes (~674 KB)             |
| musl static                           | 17,768 bytes (~17 KB) — ~39× smaller |

Both are "not a dynamic executable" and boot identically via EFISTUB (tag #17).
Then rebuild the kernel so the smaller initramfs is re-embedded, and refresh the
stick's one file:

#+begin_src sh
  (cd linux && make -j"$(nproc)" bzImage)
  cp linux/arch/x86/boot/bzImage iso_root/efi/boot/bootx64.efi
  DEV=/dev/sdX
  sudo mount "${DEV}1" /mnt && \
  sudo cp iso_root/efi/boot/bootx64.efi /mnt/EFI/BOOT/BOOTX64.EFI && \
  sync && sudo umount /mnt
#+end_src

*Pitfall: one file vs two.* That single-file refresh is only for
*embedded-initramfs* builds (the base and musl variants). A *separate-initrd*
build (the SBCL image: =CONFIG_INITRAMFS_SOURCE=""= + =initrd== on the cmdline)
needs both files copied, as in "Writing to a real USB stick". See
[[file:sbcl-init.org][sbcl-init.org]] for that build.

*Future binaries* (busybox, etc.): build them static too, and against the same
libc as anything they interoperate with. A static musl busybox + a static musl
init is a clean, tiny, consistent userland.

* Notes & next steps

- *Where the banner goes.* To whatever the LAST =console== is (=tty0= here = the
  screen). Kernel printk goes to every console; only userspace =/init= writes to
  the single =/dev/console=. Put =console=ttyS0= last to prefer serial.
- *A shell instead of a banner.* Add a static busybox to the initramfs (a
  =/bin/sh= line in =initramfs.list=) and =exec= it from init.
- *A cmdline without rebuilding.* An =efibootmgr= entry with optional data, or a
  UKI / systemd-boot — but that reintroduces tooling.
- *A single dd-able image file* (GPT + ESP) is possible but needs a loop mount or
  mtools; writing the real device as above is simpler.
