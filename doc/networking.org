* The one-paragraph essence

To "have networking" two independent things must both become true: (1) the
KERNEL must be able to move packets — a socket layer (=NET=), a protocol stack
(=INET= = TCP/IP), a network device layer, and a *driver for an actual NIC*; and
(2) USERLAND must be able to *use* sockets — SBCL needs the =sb-bsd-sockets=
contrib baked into its frozen image, the interface needs an *IP address*
(static, or DHCP), and something has to resolve names (DNS) if we want them.
Neither half is useful without the other. We will build the kernel half first
(prove a link exists with packets), then the userland half (reach it from Lisp).

* Why this is harder than everything so far

| Past change            | Kernel? | Userland? | Notes                                   |
|------------------------+---------+-----------+-----------------------------------------|
| Draw the alien         | no      | yes       | /dev/fb0 already existed                 |
| Bigger fbcon font      | yes     | no        | compile-in font + cmdline               |
| *Networking*           | *yes*   | *yes*     | NET+INET+NIC driver AND sb-bsd-sockets  |

Everything we relied on before boots *early* and needs no driver negotiation.
A network link is different: a real driver must bind to a real (PCI) device,
bring the link up, and exchange packets with something on the other end. So we
test it in stages and prove each layer before adding the next.

* 2. Userland half — reaching the network from SBCL

A working kernel link is invisible until userland does three things:

** (a) sockets in the Lisp image — =sb-bsd-sockets= — *DONE*
SBCL's BSD-sockets API lives in the *=sb-bsd-sockets= contrib*, a =require=-loaded
fasl. Our image is a *frozen heap* (see [[file:sbcl-init.org][sbcl-init.org]]): we cannot =require= it at
runtime (no contrib fasls on the initramfs, no network to fetch them — the very
chicken-and-egg this whole file is about). So =build.sh= does
=(require :sb-bsd-sockets)= *at build time*, before =save-lisp-and-die=, with
=SBCL_HOME= pointed at the built tree's =obj/sbcl-home= so the contrib fasl
resolves. The socket code is then frozen into =/sbin/lisp= — at runtime no fasl
or =SBCL_HOME= is needed. Pure Lisp + kernel syscalls; no new native library.
(Resolved the old open question: yes, this SBCL tree can =require= it at build
time, given =SBCL_HOME=.)

** (b) an IP address — static, then DHCP — both *DONE*
A NIC with no address can't talk.
- *Static* ([[file:../initramfs/net.lisp::defun bring-up-interface][=bring-up-interface=]], [[file:../initramfs/net.lisp][=net.lisp=]]): assigns address + mask and
  brings the link UP via =SIOCSIFADDR= / =SIOCSIFNETMASK= / =SIOCSIFFLAGS=
  ioctls on a throwaway UDP socket — the classic =ifconfig= path as =sb-alien=
  calls (no =ifconfig=/=ip= binary). Kept as the fallback if DHCP gets no answer.
  ([[file:line-editing.org][line-editing.org]] explains what an ioctl is, if the shape is unfamiliar.) The
  kernel end of these is [[file:../linux/net/ipv4/devinet.c::devinet_ioctl][=net/ipv4/devinet.c='s =devinet_ioctl=]], which is
  where =SIOCSIFADDR= actually lands; sockets themselves enter through
  [[file:../linux/net/socket.c][=net/socket.c=]] and IPv4 is registered in [[file:../linux/net/ipv4/af_inet.c][=net/ipv4/af_inet.c=]].
- *DHCP* ([[file:../initramfs/dhcp.lisp][=dhcp.lisp=]]): a real *DISCOVER → OFFER → REQUEST → ACK* conversation,
  ~a hundred lines of pure Lisp on a =sb-bsd-sockets= UDP socket. The BOOTP packet
  and option parsing are built/parsed by hand. *Sending* with NO IP yet works over
  an ordinary socket: *SO_BINDTODEVICE* ties it to the interface so the broadcast
  leaves the right NIC with no routing entry. *Receiving* is the hard half — see
  "Why a packet socket" just below. The pieces by name: [[file:../initramfs/dhcp.lisp::defun build-dhcp][=build-dhcp=]] / [[file:../initramfs/dhcp.lisp::defun parse-dhcp][=parse-dhcp=]] (the BOOTP packet and
  its options, by hand), [[file:../initramfs/dhcp.lisp::defun dhcp-xchg][=dhcp-xchg=]] (one send/await-reply round with retries),
  [[file:../initramfs/dhcp.lisp::defun dhcp-acquire][=dhcp-acquire=]] (the four-message conversation), and [[file:../initramfs/dhcp.lisp::defun interface-mac][=interface-mac=]] (our own
  hardware address, via =SIOCGIFHWADDR=).
  [[file:../initramfs/dhcp.lisp::defun configure-eth0][=configure-eth0=]] ran it at boot, applied the leased IP+mask, and stashed
  the gateway/DNS (=*gateway*= / =*dns*=) for §2c. Verified against QEMU SLIRP:
  eth0 gets =10.0.2.15=, gw =10.0.2.2=, dns =10.0.2.3= from the ACK. (Since §2c
  the boot runs [[file:../initramfs/dhcp.lisp::defun network-up][=network-up=]] instead, and the code is no longer eth0-only:
  [[file:../initramfs/dhcp.lisp::defun dhcp-configure][=dhcp-configure=]] leases on any interface, which is how =wlan0= gets its
  address.)

*** Why a packet socket receives the replies (found on the laptop, 2026-10-12)
Until 2026-10-12 the replies came in on the same UDP socket. We set the DHCP
*broadcast flag* (bit 15 of the =flags= field), which asks the server to broadcast
its OFFER and ACK to =255.255.255.255:68=, and a UDP socket bound to port 68 does
receive a broadcast. QEMU's server obeys the flag, so every guest test passed. On the
laptop, Wi-Fi associated with the home network and *no address ever came*. That
router — a mesh access point; its DHCP replies carry a =MULTIAP_MASTER= option —
treats the flag as a hint. It *unicasts* the OFFER to the address it is offering, at
our MAC. The frame does reach =wlan0=. But the IP layer asks "is 192.168.1.x one of
mine?", gets "not yet", and, with forwarding off, drops the packet before any UDP
socket can see it. That is why real DHCP clients (=dhclient=, NetworkManager's,
=udhcpc=) all read replies from a *packet socket*.

A packet socket (=AF_PACKET=, [[file:../linux/net/packet/af_packet.c][=net/packet/af_packet.c=]]) receives frames at the
device, before the IP layer decides anything. We open it as
=socket(AF_PACKET, SOCK_DGRAM, htons(ETH_P_IP))=. =SOCK_DGRAM= means the kernel strips
the link header and hands us the IP packet. =ETH_P_IP= means IPv4 only. We bind it to
the interface with a =struct sockaddr_ll= that carries the interface index
([[file:../initramfs/dhcp.lisp::defun open-dhcp-packet-socket][=open-dhcp-packet-socket=]]). Every IPv4 packet arriving on the link then reaches
us. [[file:../initramfs/dhcp.lisp::defun dhcp-reply-from-ip-packet][=dhcp-reply-from-ip-packet=]] reads the IP header's length nibble, keeps
protocol 17 (UDP) with destination port 68, and returns where the DHCP part starts.

A packet socket needs =CAP_NET_RAW=, which PID 1 keeps ([[file:storage.org][storage.org]]). Without it,
the code falls back to the UDP socket and says so in netd's log. The UDP socket
stays open in either case: it sends, and holding port 68 stops the kernel answering
the server's broadcasts with "port unreachable". The interface index comes from the
=SIOCGIFINDEX= ioctl, not =/sys/class/net/IF/ifindex=: sysfs shows the network
namespace it was *mounted* in, which is wrong inside the host test's namespace.

Two smaller fixes came with it:
- *One attempt is a deadline, not one packet* ([[file:../initramfs/dhcp.lisp::defun dhcp-xchg][=dhcp-xchg=]]). The packet socket
  sees every IP packet, and a busy Wi-Fi carries other clients' DHCP replies. Each
  attempt now keeps reading until its timeout and skips what is not ours. Before,
  any stray packet used up the attempt.
- *Associated without a lease, keep asking.* [[file:../initramfs/wifi.lisp::defun wifi-dhcp][=wifi-dhcp=]] runs on association,
  and =netd='s Wi-Fi tick runs it again every 20 s while =wpa_state= is =COMPLETED=
  and there is no lease.

*Evidence that survives the machine.* Every exchange leaves a line in netd's log:
=wlan0: DHCP no offer — sent 4, 37 packets seen, 0 DHCP replies (packet socket)=.
The counts tell the failures apart: nothing seen means the link is dead; packets
but no DHCP means no server answered; DHCP replies that were not ours mean another
client's traffic. Those lines, and every Wi-Fi event, are also appended to
=~/.lol/log/network.log= ([[file:../initramfs/dhcp.lisp::defun network-log][=network-log=]]). That file is on the laptop's =/home=, so
Debian can read it after a failed boot; =/tmp/lol-wifi= is gone by then. It rotates
to =.old= at 256 KB, and a diskless boot writes nothing.

The test that reproduces the laptop's failure is [[file:../poc/dhcp-test.lisp][=poc/dhcp-test.lisp=]] (§8): a fake
router that unicasts, one veth cable, no root needed.

*** The loopback, =lo= (fixed 2026-10-12)
The kernel creates =lo= *down*, and until 2026-10-12 nothing here raised it. So
=127.0.0.1= did not exist. On the laptop, a Rails server in the terminal could not
be reached at =localhost= from the web pane. [[file:../initramfs/dhcp.lisp::defun network-up][=network-up=]] now raises =lo= first.
Setting =IFF_UP= is enough: when a loopback device comes up, the kernel gives it
=127.0.0.1/8= itself ([[file:../linux/net/ipv4/devinet.c::inetdev_event][=inetdev_event=]], =NETDEV_UP=), and IPv6 adds =::1=.
Containers and Chrome share this network namespace, so they all see the same
=lo=. =check-containers.lisp= serves a page on =127.0.0.1:3999= and fetches it
with =curl=. *Not a finding:* the first version of that check used Ruby's
=-run -e httpd=, which needs =webrick=, a gem Ruby 3 no longer bundles; the
server never started.

*** The default route

Giving =eth0= an address and a mask makes the kernel add *one* route by itself:
"=10.0.2.0/24= is on-link, out of =eth0=". That reached everything in QEMU's SLIRP
subnet and nothing beyond it. The internet needs a *default route* — "for every
other destination, hand the packet to the gateway" — and there are two ways to ask
the kernel for one: the =SIOCADDRT= ioctl with a =struct rtentry= (what the old
=route add= does), or an =RTM_NEWROUTE= message on an =AF_NETLINK= socket (what
=ip route add= does). We chose the *ioctl*: one route through one gateway is all
we need, it is the same throwaway-socket idiom as =SIOCSIFADDR= above, and the one
place netlink would earn its keep — IPv6 routes — never arises, because the kernel
installs those itself (§2f). [[file:../initramfs/net.lisp::defun %route-ioctl][=%route-ioctl=]] fills the 120-byte struct
(offsets measured with =offsetof= against glibc's =<net/route.h>=, not worked out
by hand: =rt_dst= at 8, =rt_gateway= 24, =rt_genmask= 40, =rt_flags= 56, =rt_dev=
88); [[file:../initramfs/net.lisp::defun add-default-route][=add-default-route=]] treats =EEXIST= as success. It needs =CAP_NET_ADMIN=,
one of PID 1's five ([[file:storage.org][storage.org]] §5; =linux/net/ipv4/fib_frontend.c= checks it).
Reading the table back needs no netlink either: the kernel prints it as text —
=/proc/net/route= (addresses as host-order hex: =0202000A= is =10.0.2.2=) and
=/proc/net/ipv6_route= — read by [[file:../initramfs/net.lisp::defun ipv4-routes][=ipv4-routes=]] and [[file:../initramfs/net.lisp::defun ipv6-default-route][=ipv6-default-route=]].

*** The lease as an object, and renewing it

A lease is an address *with a deadline*, plus facts the rest of the machine needs:
the router, the DNS servers, the NTP servers (option 42), the search domain
(option 15). [[file:../initramfs/dhcp.lisp::defstruct lease][the =LEASE= struct]] holds them, one per interface in =*leases*=;
[[file:../initramfs/dhcp.lisp::defun current-lease][=current-lease=]] is the one that owns the default route. [[file:../initramfs/dhcp.lisp::defun apply-lease][=apply-lease=]] makes a
lease true in the kernel (address, mask, default route — replacing another
interface's, so the newest link wins) and then runs =*lease-hooks*=: that is how
=dns.lisp= rewrites =/etc/resolv.conf= and =sntp.lisp= checks the clock without
=dhcp.lisp= naming either. At boot the supervisor calls [[file:../initramfs/dhcp.lisp::defun network-up][=network-up=]]: DHCP on every
*wired* interface with a carrier (none on the laptop), then the =netd= thread.
[[file:../initramfs/dhcp.lisp::defun netd-loop][=netd-loop=]] wakes every 5 s: a lease past its T1 (half its length by default)
gets a renewal REQUEST ([[file:../initramfs/dhcp.lisp::defun dhcp-renew][=dhcp-renew=]] — the "may I keep this address?" form, no
server id); a NAK or an expired lease starts over with DISCOVER; silence retries a
minute later. It also runs =*netd-hooks*=, which is where Wi-Fi lives (§7), so the
machine has *one* network thread. The QEMU static fallback (=10.0.2.15=) now
applies only to a =virtio_net= NIC — a real NIC never gets a made-up address.

*** DNS: a stub resolver in Lisp

"Stub" means we do not walk the DNS tree ourselves; we ask the *recursive*
resolver the lease named (SLIRP answers at =10.0.2.3=, a home router at its own
address) and it does the walking. A query is one UDP datagram to port 53 — a
12-byte header, the question as *labels* (=7example3com0=), a type and a class —
and the answer comes back in the same shape. The subtle part is *compression*: in
a reply a name may end in a two-byte pointer (top bits =11=) back to where the rest
of it already appeared; [[file:../initramfs/dns.lisp::defun decode-dns-name][=decode-dns-name=]] follows those, and stops after 64
jumps, because a loop of pointers is a malformed (or hostile) message.
[[file:../initramfs/dns.lisp::defun dns-query][=dns-query=]] adds what real networks need: *CNAME chasing* (=www.github.com= is an
alias; we follow the chain inside the answer, or ask again, at most 8 hops), *TC →
TCP* (an answer too big for UDP comes back truncated; we repeat it over TCP with
the 2-byte length prefix), a *TTL cache* with *negative caching* (an NXDOMAIN is
remembered for the SOA's minimum, at most five minutes), and *timeouts and
retries* over every server, two rounds. *Overrides* come first: our =/etc/hosts=,
then =~/.config/lol/hosts= (yours to edit), then =(setf (dns-override "name")
"10.0.2.2")= at the REPL. *AAAA* records are asked for only when there is an IPv6
default route (§2f). The API the other tracks use is [[file:../initramfs/dns.lisp::defun resolve-host][=resolve-host=]] → =#(93 184 215
14)= (IPv4 when there is one) and =resolve-addresses= (all of them, v4 first — the
docstring says why we depart from RFC 6724 there); failure is a =DNS-ERROR=
naming the reason.

No NSS, as §5 decided: glibc's =getaddrinfo= would =dlopen= =libnss_*= plugins
named by =/etc/nsswitch.conf=; our resolver is a datagram and a parser.

*** =/etc/resolv.conf=, for everybody else

Our own code never reads it, but glibc programs do — the host's tools run in a
container ([[file:containers.org][containers.org]]; =lol-ct= binds our file over the container's), or
anything run from =/mnt/host=. So [[file:../initramfs/dns.lisp::defun write-resolv-conf][=write-resolv-conf=]] (a lease hook) writes the
lease's servers and search domain into *our* root. The catch: our =/etc= is root's
and the user deliberately cannot write it. Instead [[file:../initramfs/preinit.c::static void give_resolv_conf][preinit creates that one file]]
and gives it to the user before dropping root, and the Lisp rewrites it *in place*
(=O_TRUNC=, no rename — a rename into =/etc= would need write permission on the
directory). A static =/etc/hosts= and an =/etc/nsswitch.conf= (=hosts: files dns=)
ship in the cpio from [[file:../initramfs/etc/hosts][=initramfs/etc/=]].

** (d) time: SNTP, and a clock only =lol-rootd= may set — *DONE*

An earlier version of this doc said the guest "boots at epoch 0" because
=CONFIG_RTC_CLASS= is off. *That was wrong*: x86 Linux reads the CMOS clock once at
boot even without the RTC class ([[file:systray.org][systray.org]]), the laptop's holds UTC, and QEMU's
emulated RTC starts at the host's time. So the clock is usually right, and
[[file:../initramfs/sntp.lisp::defun sync-clock][=sync-clock=]]'s main job is to *report drift*; it steps the clock only when it is
off by more than 2 s (a dead CMOS battery, a month switched off). It still
matters, because TLS judges certificates by their dates.

SNTP is one 48-byte UDP datagram each way to port 123. The reply carries when our
request reached the server (T2) and when the answer left (T3); with our own send
and receive times T1, T4, the offset is =((T2-T1) + (T3-T4)) / 2=. NTP counts
seconds from 1900 — which is exactly Common Lisp's universal-time epoch.

Setting the clock needs =CAP_SYS_TIME=, which PID 1 deliberately lacks. So
[[file:../initramfs/sntp.lisp::defun set-system-clock][=set-system-clock=]] asks =lol-rootd= with *one queued signal*: =sigqueue(2)=
carries a one-word payload, the new time in Unix milliseconds, and preinit's
handler ([[file:../initramfs/preinit.c::static void do_settime][=do_settime=]]) calls =clock_settime=. A request to =lol-rootd= is
a signal, never a message to parse — the whole vocabulary is three signal numbers
(=SIGUSR1=, 40, 41), fixed in both programs because glibc and musl number
=SIGRTMIN= differently (34 vs 35). =lol-rootd= refuses any time before 2026: a
clock pushed to 1970 would make every certificate "not yet valid". A diskless
boot runs as root and sets it directly. Verified in the guest: asking for +100 s
moves the clock by 100 s, and the next =sync-clock= steps it back.

The weakness, said out loud: SNTP is unauthenticated, so anyone on the path can
lie about the time we then use to judge certificates. Universally accepted; the
RTC is the cross-check.

** (e) HTTP/1.1 and HTTPS — *DONE*

[[file:../initramfs/http.lisp::defun http-request][=http-request=]] is the API agent.org's track consumes:

#+begin_src lisp
  (http-request url &key (method :get) headers body (want :string) on-chunk
                         (timeout 30) connect-timeout (redirects 5))
    => (values status headers body final-url)
#+end_src

HTTP/1.1 is text up to the body; the part a client must get right is the body's
*framing*, which comes in three kinds: =Content-Length: N=; =Transfer-Encoding:
chunked= (a series of =<hex size>\r\n<data>\r\n=, ending with size 0 and optional
trailer headers — how a server streams something whose length it does not know
yet, such as server-sent events); or neither, and the body runs until the server
closes. [[file:../initramfs/http.lisp::defun body-pieces][=body-pieces=]] turns all three into one "next piece" function, which
three consumers share: =:want :string= / =:octets= collect it, =:on-chunk= hands
each piece to a function *as it arrives* (the SSE hook — three chunks sent 0.3 s
apart arrive as three calls), and =:want :stream= wraps it in a Gray stream the
caller closes. Every request says =Connection: close= — one request per
connection, no pool — which is the right trade until something measures it.
Redirects 301/302/303/307/308 are followed; a 303, and a 301/302 answering a POST,
become a GET. Timeouts are =SO_SNDTIMEO= (on Linux it bounds =connect()= too) and
=SO_RCVTIMEO= per read. =:connect-timeout= (2026-10-13) bounds the connect alone
when it should be shorter than =:timeout=: the agent waits 300 s between two reads of
a long answer, but gives a connect 15 s — with one timeout for both, an unanswered
SYN could hold a question on "thinking..." for the kernel's whole SYN-retry budget,
about two minutes, per attempt ([[file:agent.org::14.8 Failure reporting][agent.org §14.8]]).

*HTTPS* is the one place we borrow: TLS from scratch is agent.org §9, a separate
project. Until then [[file:../initramfs/tls.lisp][=tls.lisp=]] uses the *host's* OpenSSL 3 from =/mnt/host=. The
rule that makes it safe: *the library is loaded at runtime, never at build time.*
A saved SBCL image reopens every shared object it had loaded, so a libssl loaded
while building would make =/sbin/lisp= refuse to start without =/mnt/host=. So
[[file:../initramfs/tls.lisp::defun ensure-openssl][=ensure-openssl=]] loads it on the first HTTPS request (=:dont-save t=), and every
OpenSSL function is looked up *by name at call time* ([[file:../initramfs/tls.lisp::defun ssl-sym][=ssl-sym=]],
=find-dynamic-foreign-symbol-address=). libssl needs libcrypto, which needs libz
and libzstd; the loader would look for those in *our* =/lib=, but it never looks
for a library already loaded under the same soname — so we load all four, deepest
first, by full path. It works because the image's glibc *is* the host's (copied at
build time); if the host upgrades glibc and the image is not rebuilt, the error
says so. Checked: the chain against the host's CA bundle
(=/etc/ssl/certs/ca-certificates.crt=), the *name* with =SSL_set1_host=, SNI, TLS
≥ 1.2. Without =/mnt/host= an HTTPS request fails with one sentence ("HTTPS needs
the host's OpenSSL, and there is no host system at /mnt/host …").

Verified in the guest (=LOL_GUEST_HOSTROOT=1=): =https://example.com/= → 200 with
its page, =https://expired.badssl.com/= refused as expired; on the host
=poc/http-test.lisp= also refuses badssl's wrong-host and self-signed certificates.

*** Interrupted is not timed out (2026-10-13)
Found in a session run inside the environment: an HTTPS read could fail with "timed
out waiting for …" long before any timeout could have fired. The cause is how SBCL
collects garbage. To stop
the other threads for a GC, it sends each one a signal (=SIGUSR2=,
=SIG_STOP_FOR_GC= in =./sbcl='s =src/runtime/linux-os.h=). A thread blocked in
=recv= or =send= on a socket that has a timeout set (=SO_RCVTIMEO= /
=SO_SNDTIMEO=, which we always set) is *not* restarted after the signal. The call
returns =EINTR= (signal(7) lists these calls as never restarted). OpenSSL reports
that as =WANT_READ= / =WANT_WRITE= — exactly the code our timeout produces. So a GC
in any thread looked like a network timeout in the thread doing HTTPS.

[[file:../initramfs/tls.lisp::defun tls-interrupted-p][=tls-interrupted-p=]] tells them apart. =errno= 4 (=EINTR=) is an interruption. So
is a =WANT_*= that came back well before any timeout could fire (under half a
second) without =EAGAIN= (11), which is what a real timeout leaves. =tls-connect=,
=tls-read= and =tls-write= then make the same call again, up to 200 times.

** (f) IPv6 — on since tag #26, and nothing breaks

We configure nothing: when an interface comes up the kernel gives it a link-local
=fe80::= address, and when the router advertises a prefix the kernel builds a
global address from it (SLAAC, stateless address autoconfiguration) and installs
the v6 default route. Under QEMU, SLIRP advertises =fec0::/64=: =eth0= gets
=fec0::5054:ff:fe12:3456= and a default route via =fe80::2=. The Lisp only reads:
[[file:../initramfs/net.lisp::defun ipv6-addresses][=ipv6-addresses=]] (=/proc/net/if_inet6=) for the network view, and
=ipv6-default-route= to decide whether AAAA lookups are worth making. =http.lisp=
connects to a 16-octet address with an =inet6-socket=. Checked that nothing broke:
every v4 path above passes with IPv6 on.

* 5. What to NOT do (scope guards)

- *No Wi-Fi at first* — cfg80211/mac80211 + firmware blobs + WPA supplicant is a
  whole subsystem; wired/virtio first. (Kept: wired came first; Wi-Fi is §7 now.)
- *No modules* — built-in (=y=) drivers only; we have no module loader.
- *No glibc NSS / resolver files* — prefer tiny Lisp DNS over dragging NSS in.
  (Kept: =dns.lisp=. We do /write/ =/etc/resolv.conf= and a two-line
  =nsswitch.conf=, for other people's glibc programs — §2c.)
- *No IPv6 initially* — IPv4 only keeps the surface small. (Superseded in tag #26:
  IPv6 is on, configured by the kernel alone, read-only from Lisp — §2f.)
- *No hand-rolled crypto on the critical path.* TLS and the WPA handshake come
  from the host's OpenSSL and =wpa_supplicant=, loaded or run from =/mnt/host= at
  runtime, never shipped (§2e, §7); TLS in Lisp stays agent.org §9.
- Keep it *didactic*: a hand-rolled Lisp DHCP/DNS/echo teaches the protocols and
  fits the "Lisp machine drives the hardware via FFI" theme better than shipping
  opaque busybox applets (though busybox is the pragmatic fallback).

* 6. Exposing the REPL over the network

Once the userland half works (=sb-bsd-sockets= baked in, =eth0= has an IP), the
SBCL REPL can be reached remotely. Two routes, in increasing cost — *(a) is now
implemented* (=net.lisp=); (b) remains planning:

** (a) Raw TCP REPL — *IMPLEMENTED* (=net.lisp= + a host client)
A listening socket whose stream is bound to =*standard-input*= / =*standard-output*=
turns the REPL into a network REPL. How it actually ships:

- *OFF at boot unless asked (tag #26: QEMU's =fw_cfg= or =lol.netrepl=1=, see the STATUS line); a menu toggle.* [[file:../initramfs/net.lisp::defun start-net-repl][=start-net-repl=]] / [[file:../initramfs/net.lisp::defun stop-net-repl][=stop-net-repl=]] /
  [[file:../initramfs/net.lisp::defun toggle-net-repl][=toggle-net-repl=]] manage a background accept thread (the loop itself is
  [[file:../initramfs/net.lisp::defun %serve-net-repl][=%serve-net-repl=]]); =supervisor-main= starts it
  at boot, and the menu's =t= toggles it, showing =[RUNNING]= / =[stopped]=. (It is
  remote root — see the warning below — but acceptable here because the only wire
  that reaches it is the trusted QEMU =hostfwd=.) =stop-net-repl= must =shutdown=
  the listening socket and =join= the accept thread before returning, or a later
  re-enable hits =EADDRINUSE= (closing a socket does not wake a blocked
  =socket-accept= in another thread).
- *It serves the FULL line editor*, not =plain-repl=. The earlier worry was "a
  socket peer is not a terminal we can put in raw mode" — true, but it does not
  have to be: a tiny *host-side raw-forwarding client*
  ([[file:../host-client/lol-repl-client.c][=host-client/lol-repl-client.c=]], ~120 lines, any libc) puts the *host* terminal
  in raw mode and forwards keystrokes byte-by-byte, so [[file:../initramfs/line-editor.lisp::defun read-line-edited][=read-line-edited=]] receives
  escapes and drives history/editing remotely; the redraw escapes go back to the
  client. So we get full editing over a bare socket *with no PTY on the guest*
  (this is the design worked out in the discussion behind §6 — the client owns
  raw mode; the guest only needs a terminal if it runs *unmodified* programs,
  which our custom editor is not).
- *Ctrl-C / Ctrl-D* are forwarded raw and handled in =read-line-edited=: Ctrl-C
  aborts the current line (=:cancel=, fresh prompt — it never reaches the editor
  as a byte on the *local* console, where ISIG turns it into SIGINT), Ctrl-D on an
  empty line ends the session and the client disconnects cleanly.

Connect from the host: build the client once (=cc -O2 -o host-client/lol-repl-client
host-client/lol-repl-client.c=) then run =host-client/lol-repl-client= (defaults to
the =hostfwd= =127.0.0.1:4005=). Pure Lisp + syscalls on the guest; *no new kernel
option and no native binary in the image* — the client is host-only tooling (C, so
it needs no host runtime at all; deliberately a different language from the guest).

*The catch — this is plaintext and unauthenticated.* Anyone who can reach the
port gets a remote =eval= (i.e. remote root, since the REPL is PID 1). It is
only acceptable when *every wire that reaches the box is already trusted* — the
QEMU =hostfwd= case (bound to the host loopback) or a direct cable to a dev
machine. *Never bind it to an untrusted LAN.* Encryption cannot be added "for
free": it must run on whatever machine the untrusted wire touches — which leads
to (b).

** (b) Dropbear — an authenticated/encrypted alternative
If the box must sit on a network we do *not* control, the REPL needs real SSH in
front of it. *OpenSSH is too heavy* (drags in OpenSSL/libcrypto, PAM, NSS — all
against this project's spirit). The realistic choice is *Dropbear*: a tiny SSH
server built for embedded systems that *statically links its own bundled crypto*
into a single small binary (the "busybox of ssh"). What adopting it would cost:

- A new *static third-party binary* in the initramfs (a C program, not a library
  — consistent with our "no new native *libraries*" rule; links musl static like
  =preinit=).
- Kernel: *PTY support is already present* — =CONFIG_UNIX98_PTYS=y= is on (and
  devpts is folded into it on modern kernels), so =/dev/ptmx= exists. The only
  missing piece is *mounting devpts* (=mount -t devpts devpts /dev/pts=, plus a
  =/dev/pts= dir) in =preinit=, so a session can get a slave tty. No kernel
  rebuild needed for this. (The old *legacy* BSD PTYs were removed in tag #22 —
  =CONFIG_LEGACY_PTYS= off — to declutter =/dev=; Unix98 is what anything modern
  wants anyway.)
- A minimal *accounts / host-key* setup: a host key generated at first boot, and
  one user (SSH authenticates *something*).
- Point Dropbear's login program at =/sbin/lisp= instead of a shell — so logging
  in drops you straight into the SBCL REPL, encrypted and authenticated.

Sequencing: ship (a) first (it costs nothing beyond the socket work already in
the plan and is perfect for QEMU/dev), and only take on (b) when a real,
untrusted network is actually in play.

* 7. Wi-Fi — built (2026-10-12), untested on hardware until §7.4 is run

*STATUS: implemented; every part QEMU can reach is tested (§8); the radio itself
is untested until you run the checklist in §7.4 on the laptop.* The kernel half
landed in tag #26 (=CFG80211=, =MAC80211=, =IWLWIFI=, =IWLMVM=, =RFKILL=). The plan
below was written first and is kept, with its two constraints, because the
implementation (§7.1–7.3) follows it; the =kernel/wifi-intel-ax201.config=
fragment it imagined was not needed — the orchestrator turned the options on in
the shared #26 config instead.

We *will* need this. "Minimal" must not collide with "useful": a machine that
can't reach a network is almost a toy, and — see §1 — this laptop has no wired
port, so Wi-Fi is its only real link.

** This machine's card (concrete)

=lspci -nnk=: =00:14.3 [8086:34f0] Intel Ice Lake-LP PCH CNVi WiFi=, driver
=iwlwifi= + op-mode =iwlmvm=, host interface =wlp0s20f3=. It is an *AX201 (Wi-Fi
6)*; because it is *CNVi* (the MAC is integrated into the PCH, the RF is a
companion module) it appears as a chipset device, not an M.2 card. Its firmware
on the host is the =iwlwifi-Qu*-hr-b0-<api>.ucode= family plus a =.pnvm= blob and
the signed =regulatory.db= / =regulatory.db.p7s=.

** What it needs (four layers)

- *Kernel 802.11 stack*, all built-in (=y=; we ship no modules): =CONFIG_CFG80211=
  (config plane, driven over *nl80211 netlink*), =CONFIG_MAC80211= (soft-MAC — the
  CPU runs the 802.11 MAC; Intel cards need it), =CONFIG_WLAN= +
  =CONFIG_WLAN_VENDOR_INTEL=, =CONFIG_IWLWIFI= + =CONFIG_IWLMVM=; pulls in crypto
  (CCMP/=libarc4=) and =CONFIG_RFKILL=.
- *Firmware blob* — the radio will not come up without the =.ucode= (+ =.pnvm= +
  =regulatory.db=) loaded at probe. ~1–2 MB, proprietary, *binary only*.
- *Userland supplicant* — any WPA2/WPA3 join needs the EAPOL 4-way handshake +
  key management, i.e. =wpa_supplicant=. We ship none; hand-rolling it in Lisp is
  unrealistic (association + handshake + AES-CCMP). nl80211 is *netlink*, much
  heavier to drive than the wired static-IP ioctls of §2 — realistically shell out
  to =iw= + =wpa_supplicant=. (An *open* network could skip the supplicant.)
- *Then the §2–3 top of stack* — an IP (DHCP, since APs lease) and DNS, just over
  =wlan0= instead of =eth0=.

** The two design constraints we settled (so it stays honest)

1. *Licensing — keep it out-of-tree, exactly like the kernel.* There is *no
   source to vendor*: =iwlwifi= the driver is in-tree GPL (comes with the kernel
   we already fetch); the proprietary part is the *firmware*, which is *data, not
   code*. Intel's licence *permits binary redistribution* (that is why distros
   ship =firmware-iwlwifi=), so we *could* legally commit it — we choose not to,
   to keep this repo MIT and source-only. Instead the firmware is *fetched* (from
   =linux-firmware=, or copied from the host's =/lib/firmware=) and copied into the
   initramfs at pack time, *never committed* — one more row in the README
   licensing table, alongside =Linux kernel | GPLv2 | fetched by deps.sh; never
   redistributed here=. (Or embed it in the bzImage via =CONFIG_EXTRA_FIRMWARE= +
   =CONFIG_EXTRA_FIRMWARE_DIR=, which never touches git either.)
2. *Portability — make it opt-in and parameterized, not baked in.* In a
   no-=modprobe=, everything-=y=, frozen-image distro, Wi-Fi is *inherently*
   machine-specific — that is not a betrayal of "minimal", it is the same
   per-machine specialisation the project already does (PCI added for *this*
   laptop's keyboard in #19; the Terminus font for *this* screen). To keep the
   default build card-agnostic: put the driver options in a *separate, opt-in
   kernel config fragment* (e.g. =kernel/wifi-intel-ax201.config=) merged only on
   request; fetch the firmware *keyed by card*; and keep *credentials out of git
   entirely* — SSID/PSK live in a file on the USB's ESP or a build-time env var
   (gitignored, with a committed =*.example=), never machine- or repo-bound. The
   *pattern* is portable even though any one fragment/firmware/credential is not;
   the doc says "for a different card, swap the fragment + firmware names."

** Decision (2026-08, kept)

Implement *after* the wired path (§2–3) is finished and proven in QEMU, following
the two constraints above so the repo stays MIT/source-only and the Wi-Fi bits
remain a documented, swappable overlay rather than a one-laptop hack. That is what
§7.1–7.3 did.

** 7.1 Firmware: copied from the host, keyed by card, never committed

[[file:../build.sh][=build.sh=]] (step 2c) writes a =gen_init_cpio= fragment, =initramfs/firmware.list=
(gitignored), naming files in the *build host's* =/lib/firmware= — the host is the
laptop — and appends it to the list when packing. Nothing is copied into the tree.

- *Which files*, read from the kernel rather than guessed: =pcie/drv.c= maps
  =8086:34f0= to the Qu family; =cfg/22000.c= has =IWL_22000_UCODE_API_MIN= *=*
  =MAX= = 77, so this kernel requests exactly =…-77.ucode= — =build.sh= reads that
  number out of =./linux= at build time. The file prefix depends on the chip's
  silicon step, decided at probe time from a register (=Qu-b0=, =Qu-c0=, =QuZ-a0=,
  all with the =hr-b0= radio), so all three go in, 1,406,576–1,406,720 bytes each.
  No =.pnvm=: that blob is for AX210 and later (none exists for Qu on the host).
  Debian keeps the real files under =intel/iwlwifi/= with top-level symlinks; the
  build follows them (=readlink -f=).
- *The regulatory database* must be the *upstream-signed* one. Our kernel has
  =CFG80211_REQUIRE_SIGNED_REGDB= + =CFG80211_USE_KERNEL_REGDB_KEYS=, trusting only
  the keys in =linux/net/wireless/certs/= (=sforshee.hex=, =wens.hex=). Debian's
  default =regulatory.db= is the =-debian= variant, re-signed by
  =benh@debian.org= — the kernel would refuse it. =regulatory.db.p7s-upstream= is
  signed by =wens= (checked with =openssl pkcs7 -inform DER -print=), so that pair
  is copied in as =regulatory.db= / =regulatory.db.p7s=.
- *Found at probe time:* the driver is built in and probes during boot, before
  =/init= runs — but the firmware loader calls =wait_for_initramfs()= before
  searching =/lib/firmware= (=drivers/base/firmware_loader/main.c=), so the cpio's
  files are there; no user-mode helper is involved (=FW_LOADER_USER_HELPER= off).
- *Card-keyed and opt-out:* =LOL_WIFI_CARD=auto= picks =ax201= when the build
  host has one of the Qu PCI ids; =LOL_WIFI_FIRMWARE=0= leaves Wi-Fi out. A
  different card is one more =case= arm in =build.sh=. ~4.2 MB of the cpio.

** 7.2 The supplicant: the host's =wpa_supplicant=, driven from Lisp

Joining WPA2/WPA3 is a cryptographic handshake no one should hand-roll, so
[[file:../initramfs/wifi.lisp][=wifi.lisp=]] runs the *host's* =/usr/sbin/wpa_supplicant= from =/mnt/host=. Its ELF
header names =/lib64/ld-linux-x86-64.so.2= — *our* loader, which would search *our*
=/lib= for =libnl=, =libdbus=… — so [[file:../initramfs/wifi.lisp::defun host-program-argv][=host-program-argv=]] runs the host's loader
explicitly with =--library-path= pointing into =/mnt/host=. (Not a chroot: that
needs =CAP_SYS_CHROOT=, and the supplicant must still see our =/dev=, =/tmp= and
network. Not a container either: =lol-ct= runs its command with *zero*
capabilities and =NO_NEW_PRIVS=, and the supplicant needs =CAP_NET_ADMIN= +
=CAP_NET_RAW= — which it inherits from PID 1's *ambient* set across =execve=.)

We talk to it over its *control interface*: a Unix-domain *datagram* socket per
interface (=/tmp/lol-wifi/ctrl/wlan0=). A request is one datagram of text
(=SCAN=, =STATUS=, =ADD_NETWORK=, =SET_NETWORK 0 ssid 486f6d65=…) and the reply goes
back to the sender's *address* — so the client binds its own socket to a path too
([[file:../initramfs/wifi.lisp::defun call-with-ctrl-socket][=call-with-ctrl-socket=]], fresh per request). One more socket sends =ATTACH= and
then receives *events*; [[file:../initramfs/wifi.lisp::defun on-wifi-event][=on-wifi-event=]] runs DHCP on =CTRL-EVENT-CONNECTED=, drops
the lease on =DISCONNECTED=, says "wrong passphrase" on =reason=WRONG_KEY=, and
refreshes the scan table on =SCAN-RESULTS=. SSIDs are bytes: sent as hex, read
back through the supplicant's =\xNN= escapes, kept as UTF-8 strings.

[[file:../initramfs/wifi.lisp::defun wifi-tick][=wifi-tick=]] is a =netd= hook: when a wireless interface exists and Wi-Fi is not
running it clears a *soft* rfkill block (one 8-byte =struct rfkill_event= written
to =/dev/rfkill=, which preinit now gives to the user — the kernel checks nothing
else, =net/rfkill/core.c=), raises the interface, imports the host's profiles,
starts the supplicant, and hands it *every known network*; the supplicant then
picks the strongest one in range and roams — the job it is good at. Otherwise it
caches =STATUS= + =SIGNAL_POLL= in =*wifi-state*=, which is all the systray reads.

*Known networks*, never in git or the image:
- =~/.config/lol/wifi/<SSID in hex>.net=, one readable plist each, created 0600
  by =open(2)= itself in a 0700 directory, and written *only after* a typed
  passphrase actually connects;
- the host's NetworkManager keyfiles. They are root-only (0600) on the host, so
  =lol-rootd= copies them on request — signal 41, [[file:../initramfs/preinit.c::static void do_nmimport][=do_nmimport=]] — to
  =/tmp/lol-nm-import/= (tmpfs: gone at power-off). It reads as root but *writes as
  the user*: =setfsuid(2)= changes only the identity used for file access, so
  whatever that path turns out to be (a symlink planted by the user, say) the
  write can reach nothing the user could not write anyway. Should =lol-rootd= do
  this at all? The secrets are the user's own Wi-Fi passwords, which
  NetworkManager will normally show the logged-in desktop user anyway
  (=nmcli --show-secrets=, subject to polkit); the request is ~40
  lines of C with no parsing in the root process. We judged that small and
  delimited enough. [[file:../initramfs/wifi.lisp::defun parse-nmconnection][=parse-nmconnection=]] reads both SSID spellings (text, and older
  NM's =72;111;…= byte list) and skips a =psk-flags=1= profile (its secret lives in
  a keyring agent, not the file).

=wpa_supplicant='s config file holds no networks — they arrive over the socket —
so no secret is ever written to it.

- *=SuperL-n=* (or =network= / =wifi= in the Spotter) opens [[file:../initramfs/net-views.lisp][=net-views.lisp=]]'s view:

  and "known"; when not connected, the last kernel-log lines about iwlwifi /
  cfg80211 / firmware ([[file:../initramfs/wifi.lisp::defun kernel-log][=kernel-log=]] reads =/dev/kmsg= — this kernel has no
  =DMESG_RESTRICT=); then interfaces with their IPv4 and IPv6 addresses, leases
  with their renewal time, the v4 and v6 default routes, DNS servers, the clock,
  and what =netd= and the supplicant did recently.
- Keys: =c=/=Enter= connect (a *masked* passphrase prompt when needed — the
  minibuffer grew a =:secret= flag in =poc/shell.lisp=), =s= scan, =g= refresh,
  =d= disconnect, =f= forget, =i= import NetworkManager profiles, =w= Wi-Fi on/off,
  =r= renew the lease, =t= check the clock.
- The *systray* shows the SSID and signal (=Home 72%=, coloured like the battery),
  =Not connected!= as the host's mode line does, or the wired link
  (=eth0 10.0.2.15=) — [[file:../initramfs/wifi.lisp::defun network-tray-item][=network-tray-item=]], via =sysinfo.lisp='s =tray-items=.

** 7.4 On the laptop: the checklist (run this, send back what differs)

Untested on hardware until this has been run once. Each step says what you should
see; the first one that differs is the one to report.

1. *Build on the laptop.* =./build.sh= must print
   =Wi-Fi firmware: card=ax201, 5 file(s) from /lib/firmware=. Fewer files →
   =apt install firmware-iwlwifi wireless-regdb=. Then =./build.sh --install-host=
   (GRUB) or copy to the USB stick ([[file:micro-distro.org][micro-distro.org]]).
2. *Boot it.* The environment comes up as usual. Within ~10 s the systray (top
   right, before the clock) shows *=Not connected!=* and then, if a network
   NetworkManager knows is in range, its *SSID and a percentage*.
   - Nothing at all in that spot → there is no wireless interface; go to 5.
3. *=SuperL-n=.* The first row should read =wlan0: connected to …= or
   =wlan0: scanning= / =disconnected=. The second row is the last message
   (=Wi-Fi up on wlan0, N known networks=). Press *=s=*, wait 3 s, press *=g=*: the
   networks around you, strongest first, with =known= on the ones it can join.
4. *Join one it does not know:* select it, *=c=*, type the passphrase (shown as
   =*=), Enter, wait, *=g=*. Expected: the first row says =connected to …=, a
   =leases= row =wlan0 192.168.x.y/… gw … dns …=, and a =routes= row
   =default via … dev wlan0=. Then, in the Workspace, =Print it= on
   =(http-get "https://example.com/")= — the page's HTML. And
   =(describe-clock)= — =clock: 0.0xx s …=.
   - A message =wrong passphrase for …= → retype; nothing is saved until it works.
   - Connected but no lease row → DHCP got no answer (it retries every 20 s).
     Send the =recent= rows, or, from Debian afterwards, =~/.lol/log/network.log=:
     its =DHCP … sent N, M packets seen, K DHCP replies= lines say which half failed.
5. *If something failed*, the view shows a *kernel log* section while Wi-Fi is not
   connected. Send back: those rows (or, from the Workspace,
   =(wifi-kernel-log)=), plus =(rfkill-radios)=, =(wireless-interfaces)=,
   =*wifi-message*=, and the file =/tmp/lol-wifi/wpa_supplicant.log=. What they
   usually mean:
   - =iwlwifi … no suitable firmware found= / =Direct firmware load … failed= → the
     file name the kernel wanted is in the line; check it is in
     =initramfs/firmware.list=.
   - =cfg80211: loaded regulatory.db is malformed or signature is missing/invalid=
     → the Debian-signed database got in (see §7.1).
   - =rfkill-radios= shows =:hard t= → the hardware switch / BIOS setting is off.
   - no =wlan0= and no iwlwifi lines at all → the driver never probed: send
     =(kernel-log "0000:00:14.3")=.
6. *Optional:* =i= in the view imports NetworkManager's profiles again; the
   =preinit: lol-rootd: nm import: N profile(s)= line in =(kernel-log "nm import")=
   says how many were copied. Expect 19 on this laptop (the files in
   =/etc/NetworkManager/system-connections= on 2026-10-12).

** 7.5 Kernel options worth considering (not needed for the above)

Checked against the #26 config; none blocks §7.1–7.4:
- =CONFIG_USB_RTL8152= (=drivers/net/usb/Kconfig=) — the user's USB Ethernet
  dongle is a Realtek RTL8153 (=0bda:8153=, bound to =r8152= on the host). With it,
  =network-up= would lease on it like =eth0= in QEMU: a wired fallback for the
  laptop.
- =CONFIG_MAC80211_HWSIM= (=drivers/net/wireless/virtual/Kconfig=) — simulated
  radios, which would let QEMU test the *whole* Wi-Fi path (the host's
  =wpa_supplicant= can play the access point in =mode=2=; there is no =hostapd= on
  the host). But built in it creates two fake radios at every boot, on the laptop
  too; it would need =mac80211_hwsim.radios=0= on the command line and radios
  created at test time. A decision for the user, not taken here.
- Not needed, though it looked like it: =CRYPTO_CMAC= (off) — mac80211 now selects
  =CRYPTO_LIB_AES_CBC_MACS= instead (=net/mac80211/Kconfig=), and =IWLMLD= (off) is
  the op-mode for newer cards, not the AX201 (=IWLMVM=).

* Open questions — RESOLVED (kept for the record)

- Static-IP-via-ioctl vs =busybox ip/udhcpc=? → *ioctl from Lisp* (=net.lisp=),
  self-contained and didactic, no binary.
- =sb-bsd-sockets= baked vs raw =sb-alien socket()=? → *baked the contrib* — the
  clean documented API, still pure Lisp + syscalls.
- Can this SBCL =require :sb-bsd-sockets= at build time? → *yes*, with
  =SBCL_HOME=$SBCL/obj/sbcl-home= so the contrib fasl resolves (=build.sh=).

- DHCP vs a hard-coded static address? → *DHCP* ([[file:../initramfs/dhcp.lisp][dhcp.lisp]]), with the static
  =bring-up-interface= path kept as the fallback when no server answers.

- Default route by =SIOCADDRT= or rtnetlink? → *the ioctl* (§2c): one route, the
  file's existing idiom; v6 routes come from SLAAC.
- DNS: a Lisp resolver or raw IPs? → *a Lisp stub resolver* (§2c).
- Is the RTC enough, or must the clock be set? → *both*: the RTC is right at boot,
  SNTP reports drift and steps it through =lol-rootd= when it is not (§2d).
- TLS: wait for agent.org §9, a broker, or the host's library? → *the host's
  OpenSSL at runtime* (§2e), until §9.
- Supplicant: write one, or run the host's? → *the host's*, through its own
  loader, with PID 1's ambient capabilities (§7.2).

Still open: real-hardware Ethernet over the USB dongle (§7.5), and whatever the
first laptop run of §7.4 turns up.
