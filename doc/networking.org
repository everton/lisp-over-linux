* The one-paragraph essence

"Having networking" needs two independent things. The *kernel* must move packets:
a socket layer (=NET=), a protocol stack (=INET= = TCP/IP), a network device layer
and a *driver for an actual NIC*. *Userland* must use sockets: SBCL needs the
=sb-bsd-sockets= contrib baked into its frozen image, the interface needs an *IP
address* (static or DHCP), and something must resolve names. Neither half is
useful without the other, so the kernel half comes first (prove a link with
packets), then the userland half (reach it from Lisp).

* Why this is harder than a framebuffer or a font

| Change            | Kernel? | Userland? | Notes                                  |
|-------------------+---------+-----------+----------------------------------------|
| Draw the alien    | no      | yes       | /dev/fb0 already existed               |
| Bigger fbcon font | yes     | no        | compile-in font + cmdline              |
| *Networking*      | *yes*   | *yes*     | NET+INET+NIC driver AND sb-bsd-sockets |

A framebuffer or a font is there at boot with no negotiation. A network link
needs a driver to bind to a real (PCI) device, bring the link up, and exchange
packets with something at the other end. So each layer is proved before the next
(§3).

* 1. Kernel half — what has to be turned on

All =y= since tag #21. The keystone =CONFIG_PCI= (and =CONFIG_PCI_MSI=; modern NICs
want MSI/MSI-X) was already on from tag #19 for USB/ACPI.

| Option              | Role                                                  |
|---------------------+-------------------------------------------------------|
| =CONFIG_NET=        | The socket / protocol core — THE master switch        |
| =CONFIG_INET=       | IPv4 (TCP, UDP, ICMP). The thing we actually want     |
| =CONFIG_UNIX=       | AF_UNIX local sockets (handy even before a NIC works) |
| =CONFIG_PACKET=     | AF_PACKET (raw frames; our DHCP receives on it, §2b)  |
| =CONFIG_NETDEVICES= | The network-device layer (gate for any NIC driver)    |
| =CONFIG_NET_CORE=   | Core netdev machinery                                 |
| a NIC driver        | the actual hardware — see below                       |
| =CONFIG_IPV6=       | on since tag #26 (§2f)                                |

NIC drivers, easiest first:

1. *=CONFIG_VIRTIO_NET=* (+ =CONFIG_VIRTIO=, =CONFIG_VIRTIO_PCI=) — QEMU's
   paravirtual NIC. Trivial to wire up in =build.sh --run= (§4), and it isolates
   "does our NET/INET stack work" from any hardware quirk.
2. *=CONFIG_E1000= / =CONFIG_E1000E=* — Intel's emulated/real NIC; another easy
   QEMU device, present on many machines.
3. *Wi-Fi* — the tested laptop has *no wired port*, only Intel Wi-Fi (§7), so on
   real hardware Wi-Fi is the main link and virtio is a QEMU convenience.
   =CONFIG_USB_RTL8152= (tag #27, [[file:kernel-config.org][kernel-config.org]]) adds a USB Ethernet
   dongle as a wired fallback.

Build NIC drivers *=y=*, not =m=: we ship no modules and have no =modprobe=.

* 2. Userland half — reaching the network from SBCL

** (a) sockets in the Lisp image — =sb-bsd-sockets=

SBCL's BSD-sockets API is the *=sb-bsd-sockets= contrib*, a =require=-loaded fasl.
Our image is a *frozen heap* ([[file:sbcl-init.org][sbcl-init.org]]): no contrib fasls on the initramfs,
no network to fetch them. So =build.sh= does =(require :sb-bsd-sockets)= *at build
time*, before =save-lisp-and-die=, with =SBCL_HOME= pointed at the built tree's
=obj/sbcl-home= so the fasl resolves. At runtime no fasl or =SBCL_HOME= is needed:
pure Lisp + kernel syscalls, no new native library.

** (b) an IP address — static, then DHCP

- *Static* ([[file:../initramfs/net.lisp::defun bring-up-interface][=bring-up-interface=]], [[file:../initramfs/net.lisp][=net.lisp=]]). Assigns address + mask and
  brings the link UP via =SIOCSIFADDR= / =SIOCSIFNETMASK= / =SIOCSIFFLAGS=
  ioctls on a throwaway UDP socket — the classic =ifconfig= path as =sb-alien=
  calls, no binary. It's the fallback when DHCP gets no answer, and only for a
  =virtio_net= NIC: a real NIC never gets a made-up address. ([[file:line-editing.org][line-editing.org]]
  explains what an ioctl is.) In the kernel, =SIOCSIFADDR= lands in
  [[file:../linux/net/ipv4/devinet.c::devinet_ioctl][=net/ipv4/devinet.c='s =devinet_ioctl=]]; sockets enter through
  [[file:../linux/net/socket.c][=net/socket.c=]] and IPv4 is registered in [[file:../linux/net/ipv4/af_inet.c][=net/ipv4/af_inet.c=]].
- *DHCP* ([[file:../initramfs/dhcp.lisp][=dhcp.lisp=]]). A real *DISCOVER → OFFER → REQUEST → ACK* exchange in
  pure Lisp. *Sending* with no IP yet works on an ordinary UDP socket:
  *SO_BINDTODEVICE* ties it to the interface, so the broadcast leaves the right NIC
  with no route. *Receiving* is the hard half (next section).

The DHCP pieces by name:

- *The packet.* [[file:../initramfs/dhcp.lisp::defun build-dhcp][=build-dhcp=]] / [[file:../initramfs/dhcp.lisp::defun parse-dhcp][=parse-dhcp=]] build and parse BOOTP and its
  options by hand.
- *One round.* [[file:../initramfs/dhcp.lisp::defun dhcp-xchg][=dhcp-xchg=]] sends and awaits a reply, with retries.
- *The exchange.* [[file:../initramfs/dhcp.lisp::defun dhcp-acquire][=dhcp-acquire=]] runs the four messages;
  [[file:../initramfs/dhcp.lisp::defun interface-mac][=interface-mac=]] reads our hardware address (=SIOCGIFHWADDR=).
- *Any interface.* [[file:../initramfs/dhcp.lisp::defun dhcp-configure][=dhcp-configure=]] leases on any interface (that's how =wlan0=
  gets its address); the boot calls [[file:../initramfs/dhcp.lisp::defun network-up][=network-up=]]. Under QEMU SLIRP, =eth0= gets
  =10.0.2.15=, gateway =10.0.2.2=, DNS =10.0.2.3=. (The older eth0-only entry,
  [[file:../initramfs/dhcp.lisp::defun configure-eth0][=configure-eth0=]], is still there.)

*** Why a packet socket receives the replies

A DHCP client can set the *broadcast flag* (bit 15 of =flags=), asking the server to
broadcast its OFFER and ACK to =255.255.255.255:68=; a UDP socket bound to port 68
receives that. QEMU's server obeys the flag. Many real routers treat it as a hint
and *unicast* the OFFER to the address being offered, at our MAC.

That frame reaches the interface, but the IP layer asks "is 192.168.1.x one of
mine?", gets "not yet", and, with forwarding off, drops it before any UDP socket
sees it. The symptom: Wi-Fi associated, no address ever. That's why real DHCP
clients (=dhclient=, NetworkManager's, =udhcpc=) read replies from a *packet socket*.

A packet socket (=AF_PACKET=, [[file:../linux/net/packet/af_packet.c][=net/packet/af_packet.c=]]) receives frames at the
device, before the IP layer decides anything.

- *How it's opened.* =socket(AF_PACKET, SOCK_DGRAM, htons(ETH_P_IP))=:
  =SOCK_DGRAM= strips the link header and hands us the IP packet; =ETH_P_IP= means
  IPv4 only. It's bound to the interface by a =struct sockaddr_ll= carrying the
  interface index ([[file:../initramfs/dhcp.lisp::defun open-dhcp-packet-socket][=open-dhcp-packet-socket=]]).
- *Filtering.* [[file:../initramfs/dhcp.lisp::defun dhcp-reply-from-ip-packet][=dhcp-reply-from-ip-packet=]] reads the IP header's length nibble,
  keeps protocol 17 (UDP) with destination port 68, and returns where the DHCP
  part starts.
- *Capability.* It needs =CAP_NET_RAW=, which PID 1 keeps ([[file:storage.org][storage.org]]). Without
  it, the code falls back to the UDP socket and says so in netd's log.
- *UDP socket still open.* It sends, and holding port 68 stops the kernel
  answering the server's broadcasts with "port unreachable".
- *Index by ioctl.* The interface index comes from =SIOCGIFINDEX=, not
  =/sys/class/net/IF/ifindex=: sysfs shows the network namespace it was *mounted*
  in, which is wrong inside the host test's namespace.
- *An attempt is a deadline.* The packet socket sees every IP packet, and a busy
  Wi-Fi carries other clients' DHCP replies. [[file:../initramfs/dhcp.lisp::defun dhcp-xchg][=dhcp-xchg=]] keeps reading until
  its timeout and skips what isn't ours, rather than spending the attempt on a
  stray packet.
- *Associated without a lease, keep asking.* [[file:../initramfs/wifi.lisp::defun wifi-dhcp][=wifi-dhcp=]] runs on association,
  and =netd='s Wi-Fi tick runs it again every 20 s while =wpa_state= is
  =COMPLETED= and there's no lease.

*** Logs that survive the machine

Every exchange leaves a line in netd's log:
=wlan0: DHCP no offer — sent 4, 37 packets seen, 0 DHCP replies (packet socket)=.
The counts tell failures apart: nothing seen means a dead link; packets but no
DHCP means no server answered; DHCP replies not ours means other clients' traffic.

Those lines, and every Wi-Fi event, go to =~/.lol/log/network.log=
([[file:../initramfs/dhcp.lisp::defun network-log][=network-log=]]), on the disk's =/home=, so you can read it from the host OS after
a failed boot (=/tmp/lol-wifi= is gone by then). It's one of the session logs
([[file:diagnostics.org][diagnostics.org]]): set aside at every boot, gzipped into =~/.lol/log/archive/=
with the newest 30 kept, cut at 16 MB mid-session; a diskless boot writes to
=/tmp/lol-log/= instead.

The unicasting router is reproduced by [[file:../poc/dhcp-test.lisp][=poc/dhcp-test.lisp=]] (§8): one veth
cable, no root needed.

** (c) the default route, the lease, and names

This is the outbound path the agent needs ([[file:agent.org][agent.org]]), built in four phases:

| Phase | What                                                                                    |
|-------+-----------------------------------------------------------------------------------------|
| N1    | =SIOCADDRT= + the lease as an object + renewal ([[file:../initramfs/net.lisp][net.lisp]], [[file:../initramfs/dhcp.lisp][dhcp.lisp]])                    |
| N2    | a stub resolver with a cache, TCP fallback, overrides ([[file:../initramfs/dns.lisp][dns.lisp]])                        |
| N3    | SNTP: drift report + stepping through =lol-rootd= ([[file:../initramfs/sntp.lisp][sntp.lisp]], §2d)                      |
| N4    | an HTTP/1.1 client, and HTTPS (§2e)                                                     |

*** The loopback, =lo=

The kernel creates =lo= *down*; without it, =127.0.0.1= doesn't exist and a server
in a container can't be reached at =localhost= from the web pane.
[[file:../initramfs/dhcp.lisp::defun network-up][=network-up=]] raises =lo= first. Setting =IFF_UP= is enough: when a loopback
device comes up, the kernel gives it =127.0.0.1/8= itself
([[file:../linux/net/ipv4/devinet.c::inetdev_event][=inetdev_event=]], =NETDEV_UP=), and IPv6 adds =::1=. Containers and Chrome share
this network namespace, so they all see the same =lo=. =check-containers.lisp=
serves a page on =127.0.0.1:3999= and fetches it with =curl=.

*** The default route

An address and a mask make the kernel add *one* route by itself: "=10.0.2.0/24= is
on-link, out of =eth0=". The internet needs a *default route* — "every other
destination, hand to the gateway". Two ways to ask for one:

- *=SIOCADDRT= ioctl* with a =struct rtentry= (what the old =route add= does) —
  *chosen*. One route through one gateway is all we need, it's the same
  throwaway-socket idiom as =SIOCSIFADDR=, and IPv6 routes, where netlink would
  earn its keep, are installed by the kernel itself (§2f).
- *=RTM_NEWROUTE= on an =AF_NETLINK= socket* (what =ip route add= does) — not
  needed.

[[file:../initramfs/net.lisp::defun %route-ioctl][=%route-ioctl=]] fills the 120-byte struct (offsets measured with =offsetof= against
glibc's =<net/route.h>=: =rt_dst= at 8, =rt_gateway= 24, =rt_genmask= 40,
=rt_flags= 56, =rt_dev= 88). [[file:../initramfs/net.lisp::defun add-default-route][=add-default-route=]] treats =EEXIST= as success. It
needs =CAP_NET_ADMIN=, one of PID 1's five ([[file:storage.org][storage.org]] §5;
=linux/net/ipv4/fib_frontend.c= checks it).

Reading the table back needs no netlink: the kernel prints it as text in
=/proc/net/route= (addresses as host-order hex: =0202000A= is =10.0.2.2=) and
=/proc/net/ipv6_route=, read by [[file:../initramfs/net.lisp::defun ipv4-routes][=ipv4-routes=]] and [[file:../initramfs/net.lisp::defun ipv6-default-route][=ipv6-default-route=]].

*** The lease as an object, and renewing it

A lease is an address *with a deadline*, plus facts the rest of the machine needs:
the router, DNS servers, NTP servers (option 42), the search domain (option 15).

- *The object.* [[file:../initramfs/dhcp.lisp::defstruct lease][The =LEASE= struct]], one per interface in =*leases*=;
  [[file:../initramfs/dhcp.lisp::defun current-lease][=current-lease=]] is the one owning the default route.
- *Applying it.* [[file:../initramfs/dhcp.lisp::defun apply-lease][=apply-lease=]] makes a lease true in the kernel (address, mask,
  default route — replacing another interface's, so the newest link wins), then
  runs =*lease-hooks*=. That's how =dns.lisp= rewrites =/etc/resolv.conf= and
  =sntp.lisp= checks the clock without =dhcp.lisp= naming either.
- *At boot.* The supervisor calls [[file:../initramfs/dhcp.lisp::defun network-up][=network-up=]]: DHCP on every *wired* interface
  with a carrier, then the =netd= thread.
- *Renewal.* [[file:../initramfs/dhcp.lisp::defun netd-loop][=netd-loop=]] wakes every 5 s. A lease past its T1 (half its length
  by default) gets a renewal REQUEST ([[file:../initramfs/dhcp.lisp::defun dhcp-renew][=dhcp-renew=]], "may I keep this address?",
  no server id); a NAK or an expired lease starts over with DISCOVER; silence
  retries a minute later.
- *One network thread.* =netd= also runs =*netd-hooks*=, which is where Wi-Fi
  lives (§7).

*** DNS: a stub resolver in Lisp

"Stub" means we don't walk the DNS tree ourselves; we ask the *recursive* resolver
the lease named (SLIRP's at =10.0.2.3=, a home router at its own address). A query
is one UDP datagram to port 53: a 12-byte header, the question as *labels*
(=7example3com0=), a type and a class. The answer comes back in the same shape.

- *Compression.* In a reply a name may end in a two-byte pointer (top bits =11=)
  back to where the rest already appeared. [[file:../initramfs/dns.lisp::defun decode-dns-name][=decode-dns-name=]] follows those and
  stops after 64 jumps: a pointer loop is a malformed (or hostile) message.
- *CNAME chasing.* [[file:../initramfs/dns.lisp::defun dns-query][=dns-query=]] follows an alias chain inside the answer, or
  asks again, at most 8 hops.
- *TC → TCP.* An answer too big for UDP comes back truncated; we repeat it over
  TCP with the 2-byte length prefix.
- *TTL cache.* With *negative caching*: an NXDOMAIN is remembered for the SOA's
  minimum, at most five minutes.
- *Retries.* Timeouts and retries over every server, two rounds.
- *Overrides first.* Our =/etc/hosts=, then =~/.lol/hosts= (yours to edit), then
  =(setf (dns-override "name") "10.0.2.2")= at the REPL.
- *AAAA only with a v6 route.* AAAA records are asked for only when there's an
  IPv6 default route (§2f).

The API: [[file:../initramfs/dns.lisp::defun resolve-host][=resolve-host=]] → =#(93 184 215 14)= (IPv4 when there is one) and
=resolve-addresses= (all of them, v4 first — the docstring says why we depart from
RFC 6724 there). Failure is a =DNS-ERROR= naming the reason.

No NSS (§5): glibc's =getaddrinfo= would =dlopen= =libnss_*= plugins named by
=/etc/nsswitch.conf=; our resolver is a datagram and a parser.

*** =/etc/resolv.conf=, for everybody else

Our code never reads it, but glibc programs do: the host's tools in a container
([[file:containers.org][containers.org]]; =lol-ct= binds our file over the container's), or anything run
from =/mnt/host=. So [[file:../initramfs/dns.lisp::defun write-resolv-conf][=write-resolv-conf=]] (a lease hook) writes the lease's servers
and search domain into *our* root.

- *Owned by the user.* Our =/etc= is root's, and the user can't write it.
  [[file:../initramfs/preinit.c::static void give_resolv_conf][Preinit creates that one file]] and gives it to the user before dropping root.
- *Rewritten in place.* =O_TRUNC=, no rename — a rename into =/etc= would need
  write permission on the directory.
- *Static companions.* A static =/etc/hosts= and an =/etc/nsswitch.conf=
  (=hosts: files dns=) ship in the cpio from [[file:../initramfs/etc/hosts][=initramfs/etc/=]].
- *The host's names too.* [[file:../initramfs/preinit.c::static void merge_host_hosts][Preinit appends the host's =/etc/hosts=]] to ours at
  boot, while still root, so names you gave your machines in the host OS resolve
  here and in every container. It's read at boot, so an edit there needs no
  rebuild.

** (d) time: SNTP, and a clock only =lol-rootd= may set

x86 Linux reads the CMOS clock once at boot even with =CONFIG_RTC_CLASS= off
([[file:systray.org][systray.org]]), and QEMU's emulated RTC starts at the host's time. So the clock is
usually right, and [[file:../initramfs/sntp.lisp::defun sync-clock][=sync-clock=]]'s main job is to *report drift*. It steps the clock
only when it's off by more than 2 s (a dead CMOS battery, a month switched off).
It matters because TLS judges certificates by their dates.

SNTP is one 48-byte UDP datagram each way to port 123. The reply carries when our
request reached the server (T2) and when the answer left (T3); with our own send
and receive times T1, T4, the offset is =((T2-T1) + (T3-T4)) / 2=. NTP counts
seconds from 1900 — exactly Common Lisp's universal-time epoch.

Setting the clock needs =CAP_SYS_TIME=, which PID 1 deliberately lacks:

- *One queued signal.* [[file:../initramfs/sntp.lisp::defun set-system-clock][=set-system-clock=]] asks =lol-rootd= with =sigqueue(2)=,
  whose one-word payload is the new time in Unix milliseconds. Preinit's handler
  ([[file:../initramfs/preinit.c::static void do_settime][=do_settime=]]) calls =clock_settime=.
- *Signals, never messages.* A =lol-rootd= request is a signal, never a message
  to parse: =SIGUSR1=, 40, 41 and 42 ([[file:storage.org][storage.org]]), fixed numbers in both
  programs because glibc and musl number =SIGRTMIN= differently (34 vs 35).
- *A floor.* =lol-rootd= refuses any time before 2026: a clock pushed to 1970
  would make every certificate "not yet valid".
- *Diskless.* A diskless boot runs as root and sets it directly.

Verified in the guest: asking for +100 s moves the clock by 100 s, and the next
=sync-clock= steps it back.

*Known limit:* SNTP is unauthenticated, so anyone on the path can lie about the
time we then use to judge certificates. Universally accepted; the RTC is the
cross-check.

** (e) HTTP/1.1 and HTTPS

[[file:../initramfs/http.lisp::defun http-request][=http-request=]] is the API the agent consumes:

#+begin_src lisp
  (http-request url &key (method :get) headers body (want :string) on-chunk
                         (timeout 30) connect-timeout (redirects 5))
    => (values status headers body final-url)
#+end_src

HTTP/1.1 is text up to the body. The part a client must get right is the body's
*framing*, three kinds:

- *=Content-Length: N=.*
- *=Transfer-Encoding: chunked=.* A series of =<hex size>\r\n<data>\r\n=, ending
  with size 0 and optional trailers — how a server streams something whose length
  it doesn't know yet, such as server-sent events.
- *Neither.* The body runs until the server closes.

[[file:../initramfs/http.lisp::defun body-pieces][=body-pieces=]] turns all three into one "next piece" function shared by three
consumers: =:want :string= / =:octets= collect it; =:on-chunk= hands each piece to
a function *as it arrives* (the SSE hook — three chunks sent 0.3 s apart arrive
as three calls); =:want :stream= wraps it in a Gray stream the caller closes.

- *One request per connection.* Every request says =Connection: close=; no pool.
- *Redirects.* 301/302/303/307/308 are followed; a 303, and a 301/302 answering a
  POST, become a GET.
- *Credentials stay home.* A redirect to *another origin* (scheme, host or port)
  drops =Authorization=, =Proxy-Authorization=, =Cookie= and =X-Api-Key= first
  ([[file:../initramfs/http.lisp::defun strip-credentials][=strip-credentials=]]), so a server we never chose doesn't get the API key, and
  an https→http hop doesn't send it in the clear. =poc/http-test.lisp= asserts
  both directions against two loopback ports.
- *Timeouts.* =SO_SNDTIMEO= (on Linux it bounds =connect()= too) and =SO_RCVTIMEO=
  per read. =:connect-timeout= bounds the connect alone when it should be shorter
  than =:timeout=: the agent waits 300 s between two reads of a long answer but
  gives a connect 15 s. With one timeout for both, an unanswered SYN could hold a
  question for the kernel's whole SYN-retry budget, about two minutes, per attempt
  ([[file:agent.org::Failure reporting][agent.org §9]]).

*** HTTPS: the host's OpenSSL, loaded at runtime

TLS from scratch is a separate project (agent.org §12). Until then
[[file:../initramfs/tls.lisp][=tls.lisp=]] uses the *host's* OpenSSL 3 from =/mnt/host=. The rule that makes it
safe: *the library is loaded at runtime, never at build time.* A saved SBCL image
reopens every shared object it had loaded, so a libssl loaded while building would
make =/sbin/lisp= refuse to start without =/mnt/host=.

- *Loaded on first use.* [[file:../initramfs/tls.lisp::defun ensure-openssl][=ensure-openssl=]] loads it on the first HTTPS request
  (=:dont-save t=).
- *Called by name.* Every OpenSSL function is looked up *at call time*
  ([[file:../initramfs/tls.lisp::defun ssl-sym][=ssl-sym=]], =find-dynamic-foreign-symbol-address=).
- *Dependencies by full path.* libssl needs libcrypto, which needs libz and
  libzstd. The loader would look in *our* =/lib=, but never looks for a library
  already loaded under the same soname — so we load all four, deepest first, by
  full path.
- *Same glibc.* It works because the image's glibc *is* the host's (copied at
  build time); if the host upgrades glibc and the image isn't rebuilt, the error
  says so.
- *What's checked.* The chain against the host's CA bundle
  (=/etc/ssl/certs/ca-certificates.crt=), the *name* with =SSL_set1_host=, SNI,
  TLS ≥ 1.2.
- *No host, one sentence.* Without =/mnt/host= an HTTPS request fails with "HTTPS
  needs the host's OpenSSL, and there is no host system at /mnt/host …".

Verified in the guest (=LOL_GUEST_HOSTROOT=1=): =https://example.com/= → 200 with
its page, =https://expired.badssl.com/= refused as expired. On the host,
=poc/http-test.lisp= also refuses badssl's wrong-host and self-signed certificates.

*** Pitfall: interrupted is not timed out

An HTTPS read could fail with "timed out waiting for …" long before any timeout
could fire. The cause is how SBCL collects garbage:

- *GC stops threads by signal.* SBCL sends each thread =SIGUSR2=
  (=SIG_STOP_FOR_GC= in =./sbcl='s =src/runtime/linux-os.h=).
- *Timed sockets aren't restarted.* A thread blocked in =recv= or =send= on a
  socket with =SO_RCVTIMEO= / =SO_SNDTIMEO= set (we always set them) gets =EINTR=
  back; signal(7) lists these calls as never restarted.
- *OpenSSL hides the difference.* It reports that as =WANT_READ= / =WANT_WRITE= —
  exactly what our timeout produces. So a GC in any thread looked like a network
  timeout in the thread doing HTTPS.

[[file:../initramfs/tls.lisp::defun tls-interrupted-p][=tls-interrupted-p=]] tells them apart: =errno= 4 (=EINTR=) is an interruption, and
so is a =WANT_*= that came back well before any timeout could fire (under half a
second) without =EAGAIN= (11), which a real timeout leaves. =tls-connect=,
=tls-read= and =tls-write= then retry, up to 200 times.

*The UDP side had the same bug.* SB-BSD-SOCKETS returns NIL from =socket-receive=
on =EINTR= and *signals* on a real timeout (=EAGAIN=); wrapping it in
=ignore-errors= makes the two look the same. So a GC during a DHCP attempt, a DNS
query, an SNTP exchange or a =wpa_supplicant= request ended it as "no answer".

- *The fix.* [[file:../initramfs/dhcp.lisp::defun socket-receive-patiently][=socket-receive-patiently=]] reads again after an =EINTR= until its own
  deadline; all four use it (=dhcp-receive= reports =:interrupted= and the attempt
  keeps listening). Plain HTTP writes retry =EINTR= too (=conn-write=).
- *The proof.* =poc/http-test.lisp= proves the premise first: with another thread
  interrupting the reader every 100 ms, a plain receive returns NIL within 0.5 s,
  while the patient one waits out its 2 s deadline.

** (f) IPv6 — on since tag #26

We configure nothing. When an interface comes up, the kernel gives it a link-local
=fe80::= address. When the router advertises a prefix, the kernel builds a global
address from it (SLAAC, stateless address autoconfiguration) and installs the v6
default route.

Under QEMU, SLIRP advertises =fec0::/64=: =eth0= gets =fec0::5054:ff:fe12:3456=
and a default route via =fe80::2=. The Lisp only reads:

- *Addresses.* [[file:../initramfs/net.lisp::defun ipv6-addresses][=ipv6-addresses=]] (=/proc/net/if_inet6=), for the network view.
- *The route.* =ipv6-default-route=, to decide whether AAAA lookups are worth
  making.
- *Connecting.* =http.lisp= connects to a 16-octet address with an
  =inet6-socket=.

Every v4 path above passes with IPv6 on.

* 3. The staged bring-up (prove each layer before the next)

1. *Kernel* (tag #21): the virtio NIC enumerates on PCI (=[1af4:1000]=, class
   0x0200) and =show-net-interfaces= lists =eth0 (down)=.
2. *Static IP from Lisp*: =eth0= UP|RUNNING at =10.0.2.15/24=.
3. *First packets*: the TCP REPL (§6a) — =nc 127.0.0.1 4005= through QEMU's
   =hostfwd= gives a live remote REPL, proving the whole INET path.
4. *DHCP*, then *outbound* (§2b–f), proved by =check-net.lisp= (§8).
5. *Wi-Fi* (§7) and *USB Ethernet* (§7.5).

* 4. QEMU test wiring (for build.sh --run)

User-mode networking needs no root and no host bridge. It's in
[[file:../build.sh::QEMU_NET][build.sh → QEMU_NET]], forwarding the REPL port:

#+begin_src sh
  QEMU_NET=(-netdev "user,id=net0,hostfwd=tcp::4005-:4005" \
            -device virtio-net-pci,netdev=net0)
#+end_src

=user= (SLIRP) gives the guest =10.0.2.15=, gateway =10.0.2.2=, DNS =10.0.2.3=,
all in software. =hostfwd= forwards a host port to a guest port, so a Lisp TCP
server is reachable from the host. The whole network bring-up is testable
headless, like the framebuffer screenshots.

* 5. Scope guards

- *No modules.* Built-in (=y=) drivers only; there's no module loader.
- *No glibc NSS or resolver.* A tiny Lisp DNS client instead (=dns.lisp=). We do
  /write/ =/etc/resolv.conf= and a two-line =nsswitch.conf=, for other people's
  glibc programs (§2c).
- *No hand-rolled crypto on the critical path.* TLS and the WPA handshake come
  from the host's OpenSSL and =wpa_supplicant=, loaded or run from =/mnt/host= at
  runtime, never shipped (§2e, §7). TLS in Lisp stays agent.org §12.
- *IPv6 by the kernel alone.* Configured by SLAAC, read-only from Lisp (§2f).
- *Didactic over opaque.* A hand-rolled Lisp DHCP/DNS teaches the protocols and
  fits the "Lisp machine drives the hardware via FFI" theme better than busybox
  applets (the pragmatic fallback).

* 6. Exposing the REPL over the network

** (a) Raw TCP REPL (=net.lisp= + a host client)

A listening socket whose stream is bound to =*standard-input*= /
=*standard-output*= turns the REPL into a network REPL.

- *Off unless asked.* It starts only when the boot asks: QEMU's =fw_cfg=
  (=-fw_cfg name=opt/lol/netrepl,string=1=, which =build.sh=,
  =refresh-screenshot.sh= and every =check-*.lisp= pass; real hardware has no
  =fw_cfg=) or =lol.netrepl=1= on the kernel cmdline — see
  [[file:../initramfs/net.lisp::defun net-repl-wanted-p][=net-repl-wanted-p=]]. The supervisor menu's =t= toggles it, showing
  =[RUNNING]= / =[stopped]=.
- *An accept thread.* [[file:../initramfs/net.lisp::defun start-net-repl][=start-net-repl=]] / [[file:../initramfs/net.lisp::defun stop-net-repl][=stop-net-repl=]] /
  [[file:../initramfs/net.lisp::defun toggle-net-repl][=toggle-net-repl=]] manage it; the loop is [[file:../initramfs/net.lisp::defun %serve-net-repl][=%serve-net-repl=]].
  =stop-net-repl= must =shutdown= the listening socket and =join= the thread before
  returning: closing a socket doesn't wake a blocked =socket-accept= in another
  thread, and a later re-enable would hit =EADDRINUSE=.
- *The full line editor, no guest PTY.* A socket peer isn't a terminal we can put
  in raw mode, but it needn't be. A host-side raw-forwarding client
  ([[file:../host-client/lol-repl-client.c][=host-client/lol-repl-client.c=]], ~120 lines, any libc) puts the *host* terminal
  in raw mode and forwards keystrokes byte by byte, so
  [[file:../initramfs/line-editor.lisp::defun read-line-edited][=read-line-edited=]] receives escapes and the redraw escapes go back. The guest
  would need a PTY only to run *unmodified* programs.
- *Ctrl-C / Ctrl-D.* Forwarded raw and handled in =read-line-edited=: Ctrl-C
  aborts the current line (=:cancel=, fresh prompt — on the *local* console it
  never reaches the editor as a byte, since ISIG turns it into SIGINT); Ctrl-D on
  an empty line ends the session and the client disconnects.

Connect from the host: build the client once (=cc -O2 -o host-client/lol-repl-client
host-client/lol-repl-client.c=), then run =host-client/lol-repl-client= (defaults
to the =hostfwd= =127.0.0.1:4005=). No new kernel option and no native binary in
the image; the client is host-only tooling, in C so it needs no host runtime.

*Security: plaintext and unauthenticated.* Anyone who reaches the port gets a
remote =eval= in PID 1. It's acceptable only when *every wire that reaches the box
is trusted* — the QEMU =hostfwd= case (bound to the host loopback) or a direct
cable to a dev machine. *Never bind it to an untrusted LAN.* Encryption has to run
on whatever machine the untrusted wire touches, which leads to (b).

** (b) Dropbear — an authenticated, encrypted alternative (not built)

On a network we don't control, the REPL needs real SSH in front. *OpenSSH is too
heavy* (OpenSSL/libcrypto, PAM, NSS). *Dropbear* is a tiny SSH server for embedded
systems that statically links its own bundled crypto into one small binary. What
adopting it would cost:

- *A static binary.* A new third-party C program in the initramfs (not a library,
  so consistent with "no new native libraries"), linked musl-static like
  =preinit=.
- *PTYs: already there.* =CONFIG_UNIX98_PTYS=y= is on and preinit mounts devpts at
  =/dev/pts= (for the terminal pane, [[file:terminal.org][terminal.org]]). Legacy BSD PTYs are off
  (=CONFIG_LEGACY_PTYS=, tag #22).
- *Accounts and a host key.* A host key generated at first boot, and one user.
- *Login into Lisp.* Dropbear's login program pointed at =/sbin/lisp=, so logging
  in drops you into the SBCL REPL, encrypted and authenticated.

Take it on only when a real, untrusted network is in play; (a) covers QEMU and
development.

* 7. Wi-Fi

The kernel half is tag #26 (=CFG80211=, =MAC80211=, =IWLWIFI=, =IWLMVM=, =RFKILL=).
Everything QEMU can reach is tested (§8); the radio is in use on the tested laptop.
§7.4 is the procedure for a new machine or a regression.

** The tested card

=lspci -nnk=: =00:14.3 [8086:34f0] Intel Ice Lake-LP PCH CNVi WiFi=, driver
=iwlwifi= + op-mode =iwlmvm=, an *AX201 (Wi-Fi 6)*. It's *CNVi*: the MAC is
integrated into the PCH and the RF is a companion module, so it appears as a
chipset device, not an M.2 card. Its firmware is the
=iwlwifi-Qu*-hr-b0-<api>.ucode= family plus the signed =regulatory.db= /
=regulatory.db.p7s=.

** What it needs (four layers)

- *Kernel 802.11 stack*, all built in: =CONFIG_CFG80211= (the configuration plane,
  driven over *nl80211 netlink*), =CONFIG_MAC80211= (soft-MAC — the CPU runs the
  802.11 MAC; Intel cards need it), =CONFIG_WLAN= + =CONFIG_WLAN_VENDOR_INTEL=,
  =CONFIG_IWLWIFI= + =CONFIG_IWLMVM=; these pull in crypto and =CONFIG_RFKILL=.
- *Firmware blob.* The radio won't come up without its =.ucode= (and
  =regulatory.db=) loaded at probe. Proprietary, binary only.
- *A supplicant.* Any WPA2/WPA3 join needs the EAPOL 4-way handshake and key
  management, i.e. =wpa_supplicant=. Hand-rolling that in Lisp is unrealistic. (An
  *open* network could skip it.)
- *Then §2's top of stack.* DHCP and DNS, over =wlan0= instead of =eth0=.

** Two design constraints

1. *Licensing: firmware stays out of the repo.* The driver is in-tree GPL; the
   proprietary part is the *firmware*, which is data, not code. Intel's licence
   permits binary redistribution (distros ship =firmware-iwlwifi=), but this repo
   stays MIT and source-only. So the firmware is copied from the build host's
   =/lib/firmware= into the initramfs at pack time, never committed — like the
   kernel, fetched and never redistributed here.
2. *Portability: per card, opt-out, no credentials in git.* In an everything-=y=,
   no-=modprobe= image, Wi-Fi is inherently machine-specific. The build picks the
   firmware *by card*, a different card is one more =case= arm, and credentials
   live only in the user's home (§7.2).

** 7.1 Firmware: copied from the host, keyed by card, never committed

[[file:../build.sh][=build.sh=]] (step 2c) writes a =gen_init_cpio= fragment, =initramfs/firmware.list=
(gitignored), naming files in the *build host's* =/lib/firmware=, and appends it
to the list when packing. Nothing is copied into the tree.

- *Which files, read from the kernel.* =pcie/drv.c= maps =8086:34f0= to the Qu
  family; =cfg/22000.c= has =IWL_22000_UCODE_API_MIN= *=* =MAX= = 77, so this
  kernel requests exactly =…-77.ucode=, and =build.sh= reads that number out of
  =./linux=. The file prefix depends on the chip's silicon step, read from a
  register at probe (=Qu-b0=, =Qu-c0=, =QuZ-a0=, all with the =hr-b0= radio), so
  all three go in, 1,406,576–1,406,720 bytes each. No =.pnvm=: that blob is for
  AX210 and later. Debian keeps the files under =intel/iwlwifi/= with top-level
  symlinks; the build follows them (=readlink -f=).
- *The upstream-signed regulatory database.* Our kernel has
  =CFG80211_REQUIRE_SIGNED_REGDB= + =CFG80211_USE_KERNEL_REGDB_KEYS=, trusting only
  the keys in =linux/net/wireless/certs/= (=sforshee.hex=, =wens.hex=). Debian's
  default =regulatory.db= is re-signed by Debian and would be refused.
  =regulatory.db.p7s-upstream= is signed by =wens= (checked with
  =openssl pkcs7 -inform DER -print=), so that pair is copied in as =regulatory.db=
  / =regulatory.db.p7s=.
- *Present at probe.* The built-in driver probes before =/init= runs, but the
  firmware loader calls =wait_for_initramfs()= before searching =/lib/firmware=
  (=drivers/base/firmware_loader/main.c=), so the cpio's files are there. No
  user-mode helper (=FW_LOADER_USER_HELPER= off).
- *Card-keyed and opt-out.* =LOL_WIFI_CARD=auto= picks =ax201= when the build host
  has one of the Qu PCI ids; =LOL_WIFI_FIRMWARE=0= leaves Wi-Fi out. About 4.2 MB
  of the cpio.

** 7.2 The supplicant: the host's =wpa_supplicant=, driven from Lisp

[[file:../initramfs/wifi.lisp][=wifi.lisp=]] runs the *host's* =/usr/sbin/wpa_supplicant= from =/mnt/host=. Its ELF
header names =/lib64/ld-linux-x86-64.so.2= — *our* loader, which would search *our*
=/lib= for =libnl=, =libdbus=… So [[file:../initramfs/wifi.lisp::defun host-program-argv][=host-program-argv=]] runs the host's loader
explicitly with =--library-path= pointing into =/mnt/host=.

- *Not a chroot.* That needs =CAP_SYS_CHROOT=, and the supplicant must still see
  our =/dev=, =/tmp= and network.
- *Not a container.* =lol-ct= runs its command with *zero* capabilities and
  =NO_NEW_PRIVS=; the supplicant needs =CAP_NET_ADMIN= + =CAP_NET_RAW=, which it
  inherits from PID 1's *ambient* set across =execve=.

*The control interface.* A Unix-domain *datagram* socket per interface
(=/tmp/lol-wifi/ctrl/wlan0=). A request is one datagram of text (=SCAN=, =STATUS=,
=ADD_NETWORK=, =SET_NETWORK 0 ssid 486f6d65=…). The reply goes back to the sender's
*address*, so the client binds its own socket to a path too
([[file:../initramfs/wifi.lisp::defun call-with-ctrl-socket][=call-with-ctrl-socket=]], fresh per request).

- *Events.* One more socket sends =ATTACH= and receives events.
  [[file:../initramfs/wifi.lisp::defun on-wifi-event][=on-wifi-event=]] runs DHCP on =CTRL-EVENT-CONNECTED=, drops the lease on
  =DISCONNECTED=, says "wrong passphrase" on =reason=WRONG_KEY=, and refreshes the
  scan table on =SCAN-RESULTS=.
- *SSIDs are bytes.* Sent as hex, read back through the supplicant's =\xNN=
  escapes, kept as UTF-8 strings.

*The tick.* [[file:../initramfs/wifi.lisp::defun wifi-tick][=wifi-tick=]] is a =netd= hook. When a wireless interface exists and
Wi-Fi isn't running, it clears a *soft* rfkill block (one 8-byte
=struct rfkill_event= written to =/dev/rfkill=, which preinit gives to the user —
the kernel checks nothing else, =net/rfkill/core.c=), raises the interface,
imports the host's profiles, starts the supplicant and hands it *every known
network*. The supplicant picks the strongest in range and roams. Otherwise the
tick caches =STATUS= + =SIGNAL_POLL= in =*wifi-state*=, which is all the systray
reads.

*Known networks*, never in git or the image:

- *Saved by us.* =~/.lol/wifi/<SSID in hex>.net=, one readable plist each,
  created 0600 by =open(2)= itself in a 0700 directory, written *only after* a
  typed passphrase actually connects.
- *Imported from NetworkManager.* Its keyfiles are root-only (0600) on the host,
  so =lol-rootd= copies them on request — signal 41,
  [[file:../initramfs/preinit.c::static void do_nmimport][=do_nmimport=]] — to =/tmp/lol-nm-import/= (tmpfs: gone at power-off). It reads
  as root but *writes as the user*: =setfsuid(2)= changes only the identity used
  for file access, so whatever that path turns out to be (a symlink planted by the
  user, say) the write reaches nothing the user couldn't write anyway.
- *Why root does this.* The secrets are the user's own Wi-Fi passwords, which
  NetworkManager normally shows the logged-in desktop user anyway
  (=nmcli --show-secrets=, subject to polkit), and the request is ~40 lines of C
  with no parsing in the root process.
- *Parsing.* [[file:../initramfs/wifi.lisp::defun parse-nmconnection][=parse-nmconnection=]] reads both SSID spellings (text, and older NM's
  =72;111;…= byte list) and skips a =psk-flags=1= profile (its secret lives in a
  keyring agent, not the file).

=wpa_supplicant='s config file holds no networks — they arrive over the socket —
so no secret is ever written to it.

- *=SuperL-n=* (or =network= / =wifi= in the Spotter) opens [[file:../initramfs/net-views.lisp][=net-views.lisp=]]'s
  view: the Wi-Fi state and message; scan results with signal %, security, band
  and "known"; when not connected, the last kernel-log lines about iwlwifi /
  cfg80211 / firmware ([[file:../initramfs/wifi.lisp::defun kernel-log][=kernel-log=]] reads =/dev/kmsg=; this kernel has no
  =DMESG_RESTRICT=); then interfaces with their IPv4 and IPv6 addresses, leases
  with their renewal time, the v4 and v6 default routes, DNS servers, the clock,
  and what =netd= and the supplicant did recently.
- *Keys.* =c=/=Enter= connect (a *masked* passphrase prompt when needed — the
  minibuffer's =:secret= flag in =poc/shell.lisp=), =s= scan, =g= refresh,
  =d= disconnect, =f= forget, =i= import NetworkManager profiles, =w= Wi-Fi on/off,
  =r= renew the lease, =t= check the clock.
- *The systray* shows the SSID and signal (=Home 72%=, coloured like the battery),

** 7.4 On a new machine: the checklist

Each step says what you should see; the first one that differs is the one to
report.

1. *Build on the machine.* =./build.sh= must print
   =Wi-Fi firmware: card=ax201, 5 file(s) from /lib/firmware=. Fewer files →
   =apt install firmware-iwlwifi wireless-regdb=. Then =./build.sh --install-host=
   (GRUB) or copy to the USB stick ([[file:micro-distro.org][micro-distro.org]]).
2. *Boot it.* Within ~10 s the systray (top right, before the clock) shows
   *=Not connected!=* and then, if a network NetworkManager knows is in range, its
   *SSID and a percentage*.
   - Nothing at all in that spot → no wireless interface; go to 5.
3. *=SuperL-n=.* The first row reads =wlan0: connected to …= or
   =wlan0: scanning= / =disconnected=; the second is the last message
   (=Wi-Fi up on wlan0, N known networks=). Press *=s=*, wait 3 s, press *=g=*: the
   networks around you, strongest first, =known= on the ones it can join.
4. *Join one it doesn't know.* Select it, *=c=*, type the passphrase (shown as
   =*=), Enter, wait, *=g=*. Expected: =connected to …=, a =leases= row
   =wlan0 192.168.x.y/… gw … dns …=, and a =routes= row =default via … dev wlan0=.
   Then in the Workspace, =Print it= on =(http-get "https://example.com/")= gives
   the page's HTML, and =(describe-clock)= gives =clock: 0.0xx s …=.
   - =wrong passphrase for …= → retype; nothing is saved until it works.
   - Connected but no lease row → DHCP got no answer (it retries every 20 s).
     Check the =recent= rows, or later from the host OS =~/.lol/log/network.log=:
     its =DHCP … sent N, M packets seen, K DHCP replies= lines say which half
     failed (§2b).
5. *If something failed*, the view shows a *kernel log* section while Wi-Fi isn't
   connected. Collect those rows (or =(wifi-kernel-log)= from the Workspace), plus
   =(rfkill-radios)=, =(wireless-interfaces)=, =*wifi-message*=, and
   =/tmp/lol-wifi/wpa_supplicant.log=. What they usually mean:
   - =iwlwifi … no suitable firmware found= / =Direct firmware load … failed= →
     the file name the kernel wanted is in the line; check it's in
     =initramfs/firmware.list=.
   - =cfg80211: loaded regulatory.db is malformed or signature is missing/invalid=
     → the Debian-signed database got in (§7.1).
   - =rfkill-radios= shows =:hard t= → the hardware switch or BIOS setting is off.
   - No =wlan0= and no iwlwifi lines → the driver never probed:
     =(kernel-log "0000:00:14.3")=.
6. *Optional.* =i= in the view imports NetworkManager's profiles again; the
   =preinit: lol-rootd: nm import: N profile(s)= line in =(kernel-log "nm import")=
   should match the number of files in =/etc/NetworkManager/system-connections=.

** 7.5 Related kernel options

- *=CONFIG_USB_RTL8152=* (=drivers/net/usb/Kconfig=) — on since tag #27: a Realtek
  RTL8153 USB Ethernet dongle (=0bda:8153=). =network-up= leases on it like =eth0=
  in QEMU, a wired fallback for a laptop with no port.
- *=CONFIG_MAC80211_HWSIM=* (=drivers/net/wireless/virtual/Kconfig=) — off.
  Simulated radios would let QEMU test the *whole* Wi-Fi path (the host's
  =wpa_supplicant= can play the access point in =mode=2=). But built in, it creates
  two fake radios at every boot, on real hardware too; it would need
  =mac80211_hwsim.radios=0= on the command line and radios created at test time.
- *Ruled out, though they looked needed.* =CRYPTO_CMAC= (off): mac80211 now
  selects =CRYPTO_LIB_AES_CBC_MACS= instead (=net/mac80211/Kconfig=). =IWLMLD=
  (off): the op-mode for newer cards, not the AX201 (=IWLMVM=).

* 8. Testing it

- [[file:../check-net.lisp][=check-net.lisp=]] — =LOL_GUEST_HOSTROOT=1 sbcl --script check-net.lisp=, 34
  checks in the guest:
  - *Lease and route.* The lease and default route, =netd= alive, PID 1 as uid
    1000, =/etc/resolv.conf= written and owned by the user, the lease received
    through the packet socket (i.e. =CAP_NET_RAW= reaches it).
  - *DNS.* A, CNAME, NXDOMAIN, cache.
  - *HTTP.* To [[file:../host-client/http-test-server.lisp][=host-client/http-test-server.lisp=]] at =10.0.2.2=:
    =Content-Length=, chunked in three pieces through =on-chunk=, a redirect.
  - *HTTPS.* example.com, and an expired certificate refused.
  - *Clock.* SNTP and =lol-rootd= stepping the clock +100 s and back.
  - *IPv6.* SLAAC and the AAAA rule.
  - *Wi-Fi without a radio.* The view and the tray cope; the host's
    =wpa_supplicant= runs from =/mnt/host= and, started with its *wired* driver on
    =eth0=, answers every control request the UI makes (=ADD_NETWORK= with a
    non-ASCII SSID, events, stop); the NM-import directory appears owned by the
    user (who can read =lol-rootd='s line about it in the kernel log); keyfiles
    parse; saved credentials are 0600.
  - *Ruled out under QEMU:* importing the host's real NM profiles. QEMU runs as
    the user and 9p can't read root-only files, so the copy finds 0 profiles. The
    copy path is tested; the real import is checklist step 6.
- [[file:../poc/http-test.lisp][=poc/http-test.lisp=]] — the same modules on the host: every body framing against
  the loopback test server, DNS, HTTPS, three badssl certificates (wrong host,
  expired, self-signed) each refused *with its reason*, credential stripping, and
  the EINTR premise (§2e).
- [[file:../poc/dhcp-test.lisp][=poc/dhcp-test.lisp=]] — =dhcp.lisp= against a real kernel, without root, 10
  checks. It re-runs itself under =unshare -rn= (a user namespace owning a private
  network namespace) and builds a veth pair whose far end is in a *second*
  namespace, where a child copy of the script plays a router answering by
  broadcast or unicast. The decisive pair: a unicasting router with the UDP socket
  alone gives *no lease*; with the packet socket, a lease. Two setup traps:
  - *Both ends in one namespace.* The kernel gives the DISCOVER the router's own
    address as its source, and the router drops it.
  - *=rp_filter=.* A new namespace copies Debian's =rp_filter=2=, which drops every
    reply before the lease. The image runs with the kernel default of 0, and the
    test sets that.
- [[file:../poc/wifi-test.lisp][=poc/wifi-test.lisp=]] — =wifi.lisp='s pure parts: keyfiles, SSID escapes, flags,
  passphrase quoting, the tray item in each state.
- =sbcl --script poc/render-frame.lisp network= renders the view headless (it
  shows the *host's* interfaces and routes).
