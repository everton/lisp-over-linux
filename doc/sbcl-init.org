#+TITLE: SBCL Common Lisp as PID 1 — running a Lisp runtime as init
#+STARTUP: showall

Parent doc: [[file:micro-distro.org][micro-distro.org]] (the base EFISTUB micro-linux).
Kernel options: [[file:kernel-config.org][kernel-config.org]].

Instead of a tiny C =init=, this makes *SBCL* (Steel Bank Common Lisp) the first
userspace process. A small C shim does the privileged setup, then =execve=s a
standalone SBCL image that stays PID 1 for the life of the machine.

- *Status.* Works in QEMU + OVMF and on real hardware (a Dell XPS 13 9300).
  Kernel tag *#32*; userland rebuilt by [[file:../build.sh][build.sh]].
- *Shape.* A *separate initrd*: the kernel and =initramfs.cpio= are two files.
- *Boot sequence.* preinit mounts =/proc /sys /dev /tmp /dev/pts /dev/shm= and the
  host's disk (only =/home= shared, [[file:storage.org][storage.org]]), drops to the user and execs
  the Lisp *supervisor*. It boots straight into the pixel environment and falls
  back to a console menu when you leave it or it dies.
- *Two more processes ship beside it.* =/sbin/lol-ct= runs commands in the host's
  distribution as a container ([[file:containers.org][containers.org]]); the web pane drives the host's
  Chrome through it ([[file:web-browser.org][web-browser.org]]).
- *What each tag added* is [[file:kernel-config.org][kernel-config.org]]'s change log; the subsystems have
  their own docs (networking, terminal, agent, session persistence, diagnostics,
  screencasts), linked from the module table below.

* The challenge in one sentence

A C =init= is a few KB and self-contained; SBCL is a whole *language runtime* —
a ~2 MB C runtime plus a Lisp heap image ("core") of tens of MB — *dynamically
linked* against glibc. So "make it init" becomes shipping a dynamic program and
its shared libraries inside an initramfs, the thing static linking avoided.

* Findings from the ./sbcl tree

SBCL is a *built source tree*, version 2.6.8, reached through the gitignored
=./sbcl= symlink ([[file:../deps.sh][deps.sh]]):

| Piece    | Path                          | Notes                                 |
|----------+-------------------------------+---------------------------------------|
| runtime  | =./sbcl/src/runtime/sbcl=     | 2.2 MB ELF, dynamically linked        |
| core     | =./sbcl/output/sbcl.core=     | ~37 MB Lisp heap image                |
| contribs | =./sbcl/contrib/...=          | only the two we =require= at build    |

=ldd= names the only external pieces:

| Library                        | Role                                   |
|--------------------------------+----------------------------------------|
| =/lib64/ld-linux-x86-64.so.2=  | the glibc dynamic loader (~225 KB)     |
| =libc.so.6=                    | glibc (~2.0 MB)                        |
| =libm.so.6=                    | glibc math (~1.0 MB)                   |
| =linux-vdso.so.1=              | provided by the kernel, not a file     |

Modern glibc folded libpthread/libdl into =libc.so.6=, so there's nothing else to
copy. No =libzstd=, so the core is uncompressed.

- */proc must exist first.* A standalone =:executable= image finds its embedded
  core by reading =/proc/self/exe= — [[file:../sbcl/src/runtime/linux-os.c::os_get_runtime_executable_path][=os_get_runtime_executable_path=]] in
  [[file:../sbcl/src/runtime/linux-os.c][=sbcl/src/runtime/linux-os.c=]] =readlink=s it, and [[file:../sbcl/src/runtime/coreparse.c][=coreparse.c=]] maps the core.
- *RAM.* SBCL uses threads (futex) and reserves a large dynamic space, lazily
  committed: give the VM at least 1–2 GB.

* The approach

1. *Standalone image.* =save-lisp-and-die :executable t= bakes the core INTO one
   executable, =/sbin/lisp= (66 MB at #32; it grows with the Lisp world because it
   *is* the heap — see "What a frozen heap means").
2. *Ship glibc.* Copy the loader, libc and libm into the initramfs at the exact
   paths the binary expects.
3. *C preinit.* A musl-static =/init= mounts =/proc= and the rest, then =execve=s
   =/sbin/lisp=. The process is replaced in place, so it stays PID 1.
4. *Separate initrd.* The kernel embeds nothing (=CONFIG_INITRAMFS_SOURCE=""=);
   the cpio (74 MB at #32) is a second file EFISTUB loads via =initrd== on the
   built-in cmdline. The Lisp world changes without a kernel rebuild.

* Dependency checklist (what must be inside the initramfs)

| path in initramfs                                                               | source on host                                                                                      | why                                                  |
|---------------------------------------------------------------------------------+-----------------------------------------------------------------------------------------------------+------------------------------------------------------|
| /init                                                                           | initramfs/preinit (musl static C)                                                                   | mounts fs, execs the Lisp                            |
| /sbin/lisp                                                                      | initramfs/lisp-init (save-lisp-and-die)                                                             | the SBCL image (PID 1)                               |
| /sbin/lol-ct                                                                    | initramfs/lol-ct (musl static C)                                                                    | the container helper                                 |
| /lib64/ld-linux-x86-64.so.2                                                     | /usr/lib/x86_64-linux-gnu/ld-linux-x86-64.so.2                                                      | dynamic loader (hard path)                           |
| /usr/lib/x86_64-linux-gnu/libc.so.6                                             | same                                                                                                | glibc                                                |
| /usr/lib/x86_64-linux-gnu/libm.so.6                                             | same                                                                                                | glibc math                                           |
| /etc/hosts, /etc/nsswitch.conf                                                  | initramfs/etc/ (committed, static)                                                                  | names for glibc programs                             |
| /lib/firmware/iwlwifi-Qu*-hr-b0-77.ucode, regulatory.db{,.p7s}                  | the build host's =/lib/firmware= (generated =initramfs/firmware.list=, gitignored; never committed) | Wi-Fi firmware, card-keyed ([[file:networking.org][networking.org]] §7)       |
| /dev/console,/dev/null,/dev/tty (nodes)                                         | gen_init_cpio nod entries                                                                           | stdio before devtmpfs                                |
| dirs: /proc /sys /dev /tmp /sbin /lib64 /usr /usr/lib /usr/lib/x86_64-linux-gnu | gen_init_cpio dir entries                                                                           | mount points + lib paths                             |

*No =ld.so.cache=.* The loader falls back to its built-in search path, which
includes =/usr/lib/x86_64-linux-gnu=; placing the libraries there is what makes
them resolvable.

* Build & run it — build.sh

[[file:../build.sh][build.sh]] is the one-step rebuild. The fast path rebuilds only the userland — the
point of the separate initrd.

| Command                       | What it does                                                                                                                 |
|-------------------------------+------------------------------------------------------------------------------------------------------------------------------|
| =./build.sh=                  | preinit + lol-ct + lisp-init + initramfs.cpio (seconds)                                                                      |
| =./build.sh --kernel=         | also the kernel + BOOTX64.EFI (minutes)                                                                                      |
| =./build.sh --run=            | build, boot HEADLESS in QEMU, screenshot to =screen.png=, print the serial boot markers                                      |
| =./build.sh --interactive=    | build, boot in a QEMU WINDOW you can type into                                                                               |
| =./build.sh --kernel --run=   | the full cycle                                                                                                               |
| =./build.sh --install-host=   | build, then copy kernel + cpio to the host's =/boot/lisp= (sudo) — [[file:micro-distro.org::Booting from the host's GRUB][micro-distro.org → Booting from the host's GRUB]] |

Flags combine. Environment: =QEMU_WAIT=<seconds>= (pre-screenshot wait),
=QEMU_DISPLAY=<gtk|sdl>= (the =--interactive= window backend), =QEMU_SMP= (CPUs,
default 4).

- *=--run=, the everyday loop.* Boots =iso_root/= under OVMF headless, grabs the
  framebuffer over QMP. Edit → =./build.sh --run= → open =screen.png=.
- *=--interactive=, to use it.* A foreground QEMU window (=-display gtk=,
  =-serial mon:stdio=). The cmdline ends with =console=tty0=, so =/dev/console= is
  the framebuffer VT: you type in the window, and the launching terminal mirrors
  serial + kernel log and gives the QEMU monitor (=Ctrl-A C=). With =-no-reboot=,
  the menu's =s= quits QEMU cleanly. The right mode for the line editor
  ([[file:line-editing.org][line-editing.org]]).
- *KVM.* Every QEMU launch passes =-machine q35,accel=kvm:tcg= — hardware
  virtualisation when =/dev/kvm= is usable, software otherwise; the browser is an
  order of magnitude slower without it ([[file:micro-distro.org][micro-distro.org]], "KVM vs TCG").

The sections below spell out what =build.sh= does.

* The supervisor (didactic, not production)

The Lisp userland is many small modules baked into one image by
=save-lisp-and-die=. =registry.lisp= is loaded first with a plain =load=, because
it defines =load-recording=, the loader used for every other module: it loads
them normally AND captures each one's verbatim source into the image
([[file:code-browser.org][code-browser.org]] §2).

** Ordering constraints

Which moves are safe (the full derived graph is [[file:guide/modules.html][the guide's module map]]):

- *Macros before their users.* =line-editor= precedes =repl= and =fb-browser=: both
  expand its =with-raw-mode=, which must exist when they compile. =shell= only
  calls its functions at run time — a softer need.
- *Layers.* =canvas= precedes =textview= / =fb= / =shell=; =model= precedes
  =present=; =tls= precedes =http=.
- *The agent chain.* =json=, =agent-wire= → =agent= → =agent-ui= (after =shell=: it
  defines methods on the shell's subjects) → =agent-tools=, =agent-store= (an
  =:around= method on its Activity subject; a hook on =*turn-end-hooks*=).
- *The network chain.* =net= → =dhcp= → =dns= / =sntp= / =wifi= (they hang on
  =*lease-hooks*= and =*netd-hooks*=); =net-views= after =shell= and =wifi=.
- *The web pane* comes after =fb-browser=, because =web.lisp= registers with
  =*fb-services*= when loaded; =worker-live= after =web-cdp=.
- *First and last.* =logcount-fix= first, so the image is repaired before anything
  else lands (the build host has POPCNT, so nothing needs it at build time — first
  is where a reader looks for a patch to SBCL). =supervisor= last: the entry point.

Everything else is grouped for readability.

*One implementation, two backends.* =build.sh= loads the =poc/= toolkit *straight
out of =poc/=* — the same sources =sbcl --script poc/run-host.lisp= runs on the dev
host ([[file:../poc/README.org][poc/README.org]]).

** The network REPL

- *Off at boot* unless QEMU's =fw_cfg= (or =lol.netrepl=1=) asks for it; menu =t=
  toggles it. It serves the full line editor over the socket; the host-side
  raw-forwarding client is in =host-client/= ([[file:networking.org][networking.org]] §6a).
- *Sockets are baked in.* =build.sh= runs =(require :sb-bsd-sockets)= at build time
  (=SBCL_HOME= pointed at the tree's =obj/sbcl-home=) before =save-lisp-and-die=, so
  sockets are frozen into =/sbin/lisp= and need no fasl at runtime.

** One executable, several roles

=init-toplevel= dispatches on argv:

| argv          | Role                                                        |
|---------------+-------------------------------------------------------------|
| (none)        | the SUPERVISOR (PID 1): =supervisor-main=                   |
| =worker <id>= | a short-lived worker (=worker-main=)                        |
| =job NAME=    | compute one view and print it ([[file:../initramfs/worker.lisp][worker.lisp]])                 |
| =serve NAME=  | stay up and serve a LIVE view ([[file:../initramfs/worker-live.lisp][worker-live.lisp]])            |
| =try=         | Accept one definition in a throwaway heap ([[file:../initramfs/sandbox.lisp][sandbox.lisp]])    |
| =repl=        | a REPL on its own terminal, the shell of last resort        |

Every role calls =disable-ldb= first, so a fatal runtime error ends the process
instead of waiting in LDB on a console nobody sees ([[file:diagnostics.org][diagnostics.org]]).

** Boot goes straight into the environment

After its diagnostics (input devices, DHCP, the network REPL, interfaces),
=supervisor-main= calls =run-browser-fb=, which opens on the Workspace. The
environment is what the machine is for, so it doesn't wait behind a menu.

- *The menu is the fallback.* You reach it by leaving the environment
  (=SuperL-q=, which asks: this console, or power off). A bare =q= is only /back/.
- *A dying environment lands there too.* =run-browser-fb= catches any
  =serious-condition=, prints it and returns. A single failing turn is logged and
  survived; only repeated failures leave ([[file:diagnostics.org][diagnostics.org]] §9).
- *Its last words stay visible.* The screen is cleared /before/ the environment
  opens, not after. With no framebuffer at all the environment fails at once and
  the menu comes first.

** How each piece works

- *Reading the console.* The menu reads =*standard-input*= (fd 0 = =/dev/console=
  = the fb console). The kernel's N_TTY line discipline gives canonical input:
  type a choice, press Enter; backspace works.
- *REPL.* =run-repl= wraps EVERY read and eval in =handler-case= for
  =serious-condition=, so a bad form prints and re-prompts — it can't kill PID 1.
- *Shutdown.* =power-off= calls libc through =sb-alien=: =sync()= then
  =reboot(#x4321fedc)= (=RB_POWER_OFF=). No new dependency; if refused, it returns
  to the menu.
- *Workers.* =sb-ext:run-program= forks + execs =/sbin/lisp= and reaps its own
  children. The menu loop catches =serious-condition= too.
- *Alien.* =draw-alien= reads the fb geometry from sysfs and blits a 256x150 RGBA
  sprite (=/alien.rgba=) into the top-right of =/dev/fb0= with read-modify-write,
  honouring alpha. The menu redraws it after printing, every cycle, so it stays in
  the corner ([[file:framebuffer.org][framebuffer.org]] §8, §5 for =/dev/fb0=).

** Pitfalls and rules

- *PID 1 must never return.* Every menu action loops or powers off.
- *PID 1 must reap children.* =run-program= reaps the children it launched. A
  fuller init would also reap *reparented* orphans with a =waitpid(-1, WNOHANG)=
  loop on SIGCHLD — not implemented (the web pane's =WEB-REAP-ORPHANS= covers its
  own, below).
- *Ruled out: =sb-posix=.* It's a contrib; it loads and freezes in fine with
  =SBCL_HOME= set. We still don't ship it: several entry points (=tcgetattr=
  among them) are =declaim inline= and expand into its groveled alien structs,
  whose type information doesn't survive =save-lisp-and-die=. Code calling them
  runs but can never be RECOMPILED in the running image, which breaks =C-c C-c=
  on any definition using one ([[file:processes.org][processes.org]] §6). Use =(sb-unix:unix-getpid)=
  and friends.
- *"segfault" spam on the console is normal SBCL.* Its generational GC uses
  write-protected pages and a SIGSEGV handler as a write barrier; the kernel logs
  every one as "lisp[1]: segfault ...". preinit writes "0" to
  =/proc/sys/debug/exception-trace= to silence it.
- *ACPI power-off halting = =CONFIG_PCI= off.* The DSDT declares operation regions
  in PCI config space; with PCI off it's rejected ("ACPI: Unable to load the
  System Description Tables", =AE_BAD_PARAMETER=), so there's no =\_S5=. Same root
  cause as a dead USB keyboard ([[file:micro-distro.org][micro-distro.org]], "Real-hardware input
  (PCI/USB/HID)"). =show-input-devices= prints =/proc/bus/input/devices= names at
  startup as a keyboard check.

*Why the startup =(sleep 2)= exists.* The firmware's keyboard driver is a Boot
Services driver, destroyed at =ExitBootServices()=, so the kernel must bind its
OWN keyboard: PCI → USB → xHCI → USB-HID → input device. That binding is
*asynchronous* and finishes a moment AFTER PID 1 starts, so =supervisor-main=
sleeps ~2 s before reading input, and =show-input-devices= checks that it
completed. Background — why firmware drivers die at the handoff and the kernel
re-enumerates everything except the framebuffer: [[file:background/background.org][background.org]] §5 (the
handoff itself in §3).

** Building the SBCL image (what build.sh stage 2 runs)

=build.sh= *generates* the build script into a temp file (=mktemp=, removed by a
=trap=), one =(load-recording …)= line per =LISP_SOURCES= entry, and feeds it to
the SBCL in =./sbcl=. Its shape:

#+begin_src sh :results output
  cat > "$BUILD_LISP" <<'LISP'
  (require :sb-bsd-sockets)                     ; baked into the heap (needs SBCL_HOME)
  (require :sb-introspect)                      ; who-calls &c, also frozen in
  (load ".../initramfs/registry.lisp")          ; defines load-recording (plain load)
  ;; …then one (load-recording "…") per module, in LISP_SOURCES order — see the
  ;; table above; the list is generated, so it never drifts from build.sh.
  (with-compilation-unit ()                     ; one unit: see below the block
    (load-recording ".../initramfs/logcount-fix.lisp") ; patches SBCL, self-tests
    (load-recording ".../initramfs/model.lisp")
    ;;  …
    (load-recording ".../initramfs/supervisor.lisp"))
  (set-utc-offset "+0100")                      ; the build host's zone (doc/systray.org)
  (setf *build-stamp* "a392d7d+dirty 2026-10-16T10:47:00Z") ; journal.lisp's build stamp
  (setf *build-root* ".../")                    ; the checkout, where update.lisp looks
  (sb-ext:save-lisp-and-die ".../initramfs/lisp-init"
    :executable t :toplevel #'init-toplevel)
  LISP
  cd ./sbcl
  SBCL_HOME=$PWD/obj/sbcl-home \
  ./src/runtime/sbcl --core output/sbcl.core --no-userinit --no-sysinit \
       --non-interactive --load "$BUILD_LISP"
#+end_src

- *=--no-userinit --no-sysinit=* so a personal =~/.sbclrc= / Quicklisp can't
  interfere.
- *Both =require=s come before the modules.* =net.lisp= names the =sb-bsd-sockets=
  package at load time, and =registry.lisp='s =senders= names =sb-introspect='s.
  =SBCL_HOME= lets =require= find the contrib fasls in the built tree
  ([[file:../sbcl/obj/sbcl-home][=sbcl/obj/sbcl-home=]]); after =save-lisp-and-die= they're frozen into the heap
  and neither fasls nor =SBCL_HOME= exist at runtime.
- *One compilation unit around the modules.* Without it, a call to a function
  defined later draws an "undefined function" STYLE-WARNING as its caller
  compiles — hundreds per build, all resolved by the end, burying the real ones.
  =with-compilation-unit= holds them and reports only names *still* undefined at
  the end. So a clean build ends with no "Undefined function" summary, and one
  that appears names something missing from the image.
- *Known leftover warnings.* Style-only: struct accessors called before their
  =defstruct= (=mb-*= in =shell.lisp=, =lease-iface= in =agent.lisp='s preflight)
  cost an inline expansion, not correctness; three lambda lists mix =&optional=
  with =&key=.

** What "a frozen heap" actually means

The phrase turns up all over these docs. It's the single fact that most shapes
how this project is built.

A running Lisp is a *heap*: one graph of live objects — every package, symbol,
function, class and global — reachable from a set of roots.
[[file:../sbcl/src/code/save.lisp::defun save-lisp-and-die][=save-lisp-and-die=]] ([[file:../sbcl/src/code/save.lisp][=sbcl/src/code/save.lisp=]]) runs a full GC, writes *that
entire graph, verbatim*, to a file, and exits. [[file:../sbcl/src/runtime/coreparse.c][=coreparse.c=]] reads it back.
Starting the image isn't "loading a program": it's *mapping the graph back into
memory and resuming*, with =:toplevel= as the one function called on the way in.

- *Anything you want must be present before you save.* =require=, Quicklisp and
  =load= need machinery and files the initramfs won't have, so every dependency is
  baked in at build time — hence both =require= lines above.
- *But the image isn't read-only.* "Frozen" describes the *file*, not the running
  system. =eval= and =compile= are part of the graph too, which is why the code
  browser can compile an edited definition into the live image
  ([[file:code-browser.org][code-browser.org]]) with no fasl, no compiler on disk, no source tree.
- *Size and speed.* You ship a heap, not a program — hence a binary of tens of MB.
  Equally, startup is effectively instant: nothing is loaded.
- *The image carries its own source.* [[file:../initramfs/registry.lisp][=registry.lisp=]]'s =load-recording= stuffs
  each definition's source text into the heap on the way past, so the frozen
  world can show its code back with no files present.

* The C preinit

[[file:../initramfs/preinit.c][=initramfs/preinit.c=]] (869 lines) still has a ~40-line core: mount =/proc=,
=/sys=, =/dev=, =/tmp=, then =execve= the Lisp, which stays PID 1. Around it, it
does every *privileged* setup step once, before the Lisp exists:

1. *Configuration.* Read =/etc/lol.conf= (written by =build.sh=: the user and the
   disk UUID), then any =lol.user== / =lol.disk== on the kernel command line, then
   fw_cfg blobs =opt/lol/user= / =opt/lol/disk= (QEMU can't give an OVMF-booted
   EFISTUB kernel a cmdline).
2. *The disk.* Find it by reading ext4 superblocks itself (no udev/blkid), mount
   it at =/mnt/host=, bind-mount only its =/home= onto ours, make =/mnt/host=
   read-only. =disk=9p:<tag>= instead mounts the *build host's* =/= over virtio-9p,
   with =/home= as an overlay on a tmpfs — the QEMU-only path that lets tests run
   the host's programs ([[file:storage.org][storage.org]] §8).
3. *Identity and devices.* Look the user up in the host's =/etc/passwd= /
   =/etc/group=; chown the device nodes the Lisp opens (=give_devices=:
   =/dev/fb0=, input, =/dev/rfkill=, =/dev/snd/*= — the mixer and PCM devices
   =mixer.lisp=, ffmpeg and mplayer open — and =/dev/video*= for the webcam);
   create =/etc/resolv.conf= for the user.
4. *lol-rootd.* Fork the one process that stays root: device hotplug, the
   read-only remount at power-off, and three one-signal requests — set the clock,
   copy the host's NetworkManager profiles, install a new build into =/boot/lisp=
   ("Updating from inside").
5. *Drop to the user*, keeping five capabilities through =execve= via the
   *ambient* set, and =execve= the Lisp with =HOME=, =USER=, =LOL_ROOTD_PID= (and
   =LOL_NETREPL=1= when QEMU asked for the net REPL — read here because fw_cfg
   files are root-only).

Smaller jobs, each with its reason:

- *=/dev/pts= and =/dev/shm=.* A =devpts= mount for ptys (the terminal pane,
  container shells) and a tmpfs for =shm_open= (Chrome, PostgreSQL).
- *=/dev/fd= and =/dev/std{in,out,err}=.* devtmpfs lacks them, and bash's =<(…)=
  needs them.
- *=ping_group_range= = =0 2147483647=* (the value systemd writes). An
  unprivileged =ping= uses an ICMP datagram socket, allowed only for groups in
  that range, and the default =1 0= is empty — so =ping= fails in every container
  (no =CAP_NET_RAW= there). =check-containers.lisp= pings SLIRP's gateway.
- *=kernel.panic= = 10.* A dead PID 1 reboots after ten seconds instead of leaving
  the last frame on screen ([[file:diagnostics.org][diagnostics.org]]).
- *The host's =/etc/hosts=* is appended to ours once the disk is mounted
  ([[file:../initramfs/preinit.c::static void merge_host_hosts][=merge_host_hosts=]], [[file:networking.org][networking.org]] §2c).
- *=--dynamic-space-size 4GB=.* SBCL's default heap ceiling is 1 GiB. The runtime
  strips the option from =*posix-argv*=, so the role dispatch still sees no
  argument.

Every step is non-fatal; with no disk it's just the old shim and the Lisp runs as
root. Why each mount flag, why capabilities, why C and not Lisp, what was ruled
out: [[file:storage.org][storage.org]]. The skeleton:

#+begin_src c
  int main(void) {
      mount("proc",     "/proc", "proc",     0, NULL);
      mount("sysfs",    "/sys",  "sysfs",    0, NULL);
      mount("devtmpfs", "/dev",  "devtmpfs", 0, NULL);
      mount("tmpfs",    "/tmp",  "tmpfs",    0, "size=64m,mode=1777");
      /* ... storage + identity + lol-rootd ... */
      char *argv[] = { "/sbin/lisp", "--dynamic-space-size", "4GB", NULL };
      execve("/sbin/lisp", argv, envp);

      /* Only reached if exec failed. */
      perror("preinit: execv /sbin/lisp");
      for (;;) pause();
      return 1;
  }
#+end_src

Built with musl: =musl-gcc -static -O2 -s -o preinit preinit.c= (66,960 bytes at
#32). musl ships no kernel headers, so the five capability numbers and the
=capset= structs are copied in from the kernel's =include/uapi/linux/capability.h=.

* lol-ct — the second C program (containers)

[[file:../initramfs/lol-ct.c][=initramfs/lol-ct.c=]] (627 lines, 71,312 bytes static) runs one command inside
the host's own distribution: user + mount + pid + uts namespaces, the host root at
=/mnt/host= with per-directory overlays on top, our =/home=, =/tmp=, =/dev= bound
in, =pivot_root=, and the command run as the user with no capabilities. Design
and findings: [[file:containers.org][containers.org]]. How it fits the build:

- *Compiled like preinit*, right after it:
  =musl-gcc -static -O2 -s -o initramfs/lol-ct initramfs/lol-ct.c=.
- *=/sbin/lol-ct= in the cpio*, mode 0755, root-owned, no setuid bit: an ordinary
  user may create a user namespace, and everything else happens inside one.
- *A separate process, not the Lisp.* The Lisp starts it with =sb-ext:run-program=
  ([[file:../initramfs/containers.lisp::defun container-command-line][=containers.lisp=, =container-command-line=]]): =unshare(CLONE_NEWUSER)= refuses
  a multithreaded caller, and PID 1 has threads.
- *Its output* reaches the screen through =runs.lisp= and the SGR reader in
  =ansi.lisp=.

* The web pane — a third process tree, and no new file in the image

[[file:../initramfs/web-cdp.lisp][=web-cdp.lisp=]] and [[file:../initramfs/web.lisp][=web.lisp=]] load after =fb-browser.lisp=, because =web.lisp=
registers with the loop's =*FB-SERVICES*= when loaded (Chrome's pipe joins the
poll; each turn runs =WEB-LOOP-SERVICE=). Nothing is added to the cpio: Chrome is
the *host's* =/usr/bin/google-chrome=, started on first use through
=container-command-line= in a container named =web=. What touches PID 1's duties:

- *Reaping.* lol-ct's init reaps inside the container; =WEB-REAP-ORPHANS= is a
  safety net that reaps only children SBCL didn't start (=waitid= with =WNOWAIT=
  first, so =run-program='s exit codes are never stolen).
- *Power-off.* =POWER-OFF= ([[file:../initramfs/process.lisp::defun power-off][process.lisp]]) calls =WEB-SHUTDOWN= before
  =RELEASE-DISK=, so Chrome writes its profile while =/home= is still writable.
- *Threads.* The net REPL may ask a page a question (=WEB-JS=) while the loop reads
  the pipe; sends are serialised by a mutex and replies delivered by the loop
  ([[file:web-browser.org][web-browser.org]] §5–§6).
- *Modal choosers from a service.* A page's =<select>= is answered with the
  =RUN-CHOOSER= overlay, which waits by turning the environment's loop.
  =WEB-SERVICE= opens it only after the pipe's batch has been dispatched, never
  from inside =WEB-EVENT=. A service inside its own =:run= sits the inner turns out,
  fd and all (=*services-running*=, fb-browser.lisp), and Chrome's frame acks make
  that pause harmless ([[file:web-browser.org][web-browser.org]] §4.4).

  file /usr/lib/x86_64-linux-gnu/libm.so.6 /usr/lib/x86_64-linux-gnu/libm.so.6            0755 0 0
#+end_src

- *Relative source paths.* =file= sources are *relative to the project root*:
  =build.sh= runs =gen_init_cpio= from there. Never write an absolute =$HOME= path
  here; it would make the repo unbuildable for anyone else.
- *The Wi-Fi firmware fragment.* =build.sh= appends a generated
  =initramfs/firmware.list= (the build host's =/lib/firmware= paths, by nature;
  =LOL_WIFI_FIRMWARE=0= leaves it out).
- *The font comes from the build host.* =initramfs/mono.ttf= isn't in git:
  =build.sh= copies =$LOL_FONT=, else DejaVu Sans Mono, else what =fc-match
  monospace= names, and writes an *empty* file when there's none —
  =gen_init_cpio= needs the file to exist, and the image treats an unparseable font
  as "use the bitmap". Its licence: [[file:fonts.org][fonts.org]] §7.

** Reading those =nod= lines — what a device node is

#+begin_src text
  nod  /dev/console 0600 0 0 c 5 1
       └─ path      └─ mode
                         └─ uid, gid
                                └─ type: 'c' = character, 'b' = block
                                    └─ major   └─ minor
#+end_src

A *device node* is a file that isn't storage — it's a *name for a driver*.
Opening it connects you to kernel code rather than bytes on a disk. The two
numbers pick which code:

- *Major selects the driver.* 5 is what =devices.txt= calls "Alternate TTY
  devices"; 1 is the "Memory devices" driver owning =/dev/null=, =/dev/zero= and
  friends.
- *Minor selects the unit.* Major 5 minor 1 is the system console; minor 0 is
  =/dev/tty=, "the terminal my process is attached to"; major 1 minor 3 is
  =/dev/null=.

So =c 5 1= reads *"a character device, driver 5, unit 1"* — =/dev/console=. The
numbers are fixed by Linux, listed in
[[file:../linux/Documentation/admin-guide/devices.txt][=Documentation/admin-guide/devices.txt=]]. Get one wrong and there's no error, just
a file that talks to the wrong driver.

*Character vs block.* A character device is a *stream* — bytes in order, like a
terminal. A block device is *randomly addressable* in fixed-size blocks behind the
buffer cache, like a disk. =/dev/fb0= is a character device even though it
behaves like an array of memory ([[file:framebuffer.org][framebuffer.org]] §5½).

** Why both static nodes *and* devtmpfs

[[file:../initramfs/preinit.c][=preinit.c=]] mounts =devtmpfs= on =/dev=, which has its own =console=, =null= and
=tty=. The static three exist anyway *because of ordering*:

- *They exist before any code runs.* The kernel opens =/dev/console= as PID 1's
  stdin/stdout/stderr at exec time, and preinit wants =perror= to land somewhere
  if a mount fails — both *before* the devtmpfs mount.
- *Without them, early failures are invisible* — the classic silent boot.
- *After the mount*, devtmpfs's nodes shadow ours, and everything else
  (=/dev/fb0=, =/dev/input/event*=, =/dev/tty0=) appears unlisted. The static set
  is a deliberately minimal *bootstrap*.

* Separate-initrd kernel config (one-time)

=build.sh= never touches the kernel; it needs this config once, then
=build.sh --kernel= rebuilds it. From the project root:

#+begin_src sh :results output
  cd linux
  ./scripts/config --set-str INITRAMFS_SOURCE ""      # embed NOTHING
  ./scripts/config --enable TMPFS                      # for the /tmp mount
  # EFISTUB opens initrd= RELATIVE TO THE VOLUME ROOT, so "initrd=initramfs.cpio"
  # resolves to \initramfs.cpio (scripts/config strips backslashes anyway).
  ./scripts/config --set-str CMDLINE "console=ttyS0,115200 console=tty0 initrd=initramfs.cpio"
  make olddefconfig
  make -j"$(nproc)" bzImage
  cp arch/x86/boot/bzImage ../iso_root/efi/boot/bootx64.efi
#+end_src

dmesg confirms it with "Unpacking initramfs..." and "Freeing initrd memory".
=build.sh= stage 3 packs the cpio:
=linux/usr/gen_init_cpio initramfs/initramfs.sbcl.list > iso_root/initramfs.cpio=
(plus the firmware fragment).

* Updating from inside — build, install, restart

The image can install its own successor (tag #31). When it boots through the
host's GRUB from =/boot/lisp= ([[file:micro-distro.org::Booting from the host's GRUB][micro-distro.org → Booting from the host's GRUB]]),
the environment's terminal can *build* a new image — its container is the host's
own distribution, with the compilers and the checkout in =/home= (=./build.sh= ~11 s,
an incremental =make -j8 bzImage= ~20 s on the XPS 13).

*Installing* is the hard part: =/boot/lisp= is root's, on a filesystem the image
sees read-only, and a container has no =sudo= (setuid is off there by design,
[[file:containers.org][containers.org]] §4). So lol-rootd does it, on one fixed request:

1. In the terminal (=SuperL-Return=): =./build.sh= (with =--kernel= if the kernel
   changed).
2. =SuperL-q= → *Install the new build and restart* (key 5; it names the build).
   From the console menu, =u=.

The desk is saved on the way out, as by "Save and shut down", so the restart comes
back to the same tabs and Workspace text.

** What happens, piece by piece

- *=build.sh=* writes =iso_root/build-info= last, after both files are final: one
  READable plist, =(:stamp "rev date" :bzimage N :initramfs N)= — the stamp it also
  bakes into =*build-stamp*=. It's removed when packing starts, so a half-done
  build never has one vouching for it. =*build-root*= (the checkout's path) tells
  the image where to look. =--install-host= copies =build-info= into =/boot/lisp=
  too; inside a container (=LOL_CONTAINER= set) =build.sh= only points at the menu.
- *[[file:../initramfs/update.lisp::defun pending-build][=pending-build=]]* is a finished checkout build (its two files the sizes
  =build-info= says) whose stamp differs from =/boot/lisp/build-info='s. Only then
  does the leave menu offer the entry.
- *[[file:../initramfs/update.lisp::defun install-pending-build][=install-pending-build=]]* runs while the environment is still on screen,
  so a refusal shows in the status line with nothing left behind. It copies the
  three files into =~/.lol/stage/=, checks the copy is still that build, sends
  =lol-rootd= signal 42, and waits (60 s at most) for the one-line answer in
  =/tmp/lol-install.status=.
- *lol-rootd* ([[file:../initramfs/preinit.c::static void do_install][=do_install=]]) takes no argument: the source is always
  =<home>/.lol/stage/=, the destination always =/boot/lisp/=.
  - It opens the stage *as the user* (=setfsuid=, =O_NOFOLLOW=), so a planted
    symlink to a root-only file is refused, not copied.
  - It checks each file's magic number (=MZ=, and =HdrS= at =0x202= — the x86 boot
    protocol — for the bzImage; =070701= for a newc cpio) and size.
  - It makes the =/mnt/host= view writable (a bind remount), writes each file to
    =.NAME.new= with an fsync, then renames: old → =NAME.prev=, new into place. The
    view is read-only again before it answers =ok=.
- *[[file:../initramfs/process.lisp::defun restart-machine][=restart-machine=]]* loads =/boot/lisp='s pair with =kexec_file_load(2)= and
  reboots into it (=LINUX_REBOOT_CMD_KEXEC=, [[file:kernel-config.org][kernel-config.org]] §11). A kernel
  without kexec answers =ENOSYS=, and it restarts through the firmware instead,
  whose GRUB boots our entry first. =(save-setting :restart-via :firmware)= skips
  kexec. Both share =stop-for-reboot= with =power-off=: Chrome closed, the session
  log's last line (=shutdown: restart (kexec)=, so the next boot reads a clean
  end), sync, the disk read-only.

** Rollback, limits, trust

- *Rollback.* The previous pair stays as =bzImage.prev= / =initramfs.cpio.prev=. If
  a new build doesn't come up, boot the host distribution (GRUB's next entry) and
  move them back.
- *From a kernel before #31* the first update goes through the firmware; after
  that, restarts are kexecs.
- *What this widens.* Whoever may install an image may run any code as root at
  the next boot. That's the request's purpose, not a side effect; it's still a
  fixed request with no arguments, like lol-rootd's others ([[file:storage.org][storage.org]] §6).

* /tmp — what it took

1. *The directory must exist.* One gen_init_cpio line, sticky and world-writable:
   =dir /tmp 1777 0 0=. The initramfs root is already a writable RAM filesystem,
   so this alone makes =/tmp= usable.
2. *A dedicated tmpfs* (optional, done here) for isolation and a size cap. Needs
   =CONFIG_TMPFS=y= (=CONFIG_SHMEM=y= is its prerequisite); preinit runs
   =mount("tmpfs", "/tmp", "tmpfs", 0, "size=64m,mode=1777")=.

* Gotchas / lessons

- *PID 1 must never exit.* The Lisp =:toplevel= loops forever; if it returns the
  kernel panics ("Attempted to kill init!"). Same rule as the C init.
- */proc before the core.* The =:executable= image finds its core via
  =/proc/self/exe= — the whole reason for the preinit shim.
- *Dynamic linking is the real tax.* Ship the loader + libc + libm at the exact
  paths, version-matched to the host that built SBCL. A mismatch means loader
  errors at boot.
- *No =ld.so.cache=.* Rely on the loader's default search path
  (=/usr/lib/x86_64-linux-gnu=).
- *RAM.* SBCL wants real memory; don't test with =-m 256=.
- *Skip personal config* when building images: =--no-userinit --no-sysinit=.
- *Everything else is micro-distro's.* Secure Boot, the framebuffer console,
  =BOOTX64.EFI= placement are unchanged ([[file:micro-distro.org][micro-distro.org]]); only the initramfs
  contents and the =initrd== cmdline differ.

* Ruled out: rlwrap for line editing

The fb console gives *canonical-mode* editing for free (backspace, Ctrl-U,
Ctrl-W, line at a time, via N_TTY) but not *rich* editing — history, in-line
cursor movement, completion. =rlwrap= could add it; the editor is pure Lisp
instead ([[file:line-editing.org][line-editing.org]]: raw-mode termios via =sb-alien= plus ANSI escapes,
and why linedit's dependencies — an osicat native shim and the terminfo DB — lost
too). What rlwrap would have cost, so it isn't re-derived:

- *Five more files, ~1 MB.* =libreadline.so.8= (379 KB), =libtinfo.so.6= (220 KB),
  =libptytty.so.0= (117 KB), =libgcc_s.so.1= (183 KB) and =/usr/bin/rlwrap= (104 KB).
  Ship each REAL file at its SONAME path; gen_init_cpio allows dest ≠ src
  (=file /usr/lib/x86_64-linux-gnu/libreadline.so.8 …/libreadline.so.8.3 0755 0 0=).
- *A terminfo entry.* readline looks =$TERM= up to decode keys: =TERM=linux= in
  preinit's environment and =/usr/share/terminfo/l/linux= (1,740 bytes) in the
  cpio, or the arrows don't decode.
- *A pty.* rlwrap runs its child on a pseudo-terminal: =CONFIG_UNIX98_PTYS=
  (on), =/dev/ptmx= (devtmpfs) and =devpts= at =/dev/pts= (preinit mounts it now,
  for the terminal pane).
- *The catch: it changes the process model.* =/init= → rlwrap (PID 1) → SBCL as
  its child. rlwrap exits when its child does — PID 1 exiting is a panic — and it
  wraps ONE interactive REPL, which composes badly with a supervisor that spawns
  workers.

* Next steps / ideas

- *A real trigger for workers.* Spawn a worker in response to input (a console
  line, a socket message) rather than from the menu.
- *Reap reparented orphans.* A SIGCHLD handler doing =waitpid(-1, ..., WNOHANG)=.
- *Drop the C preinit.* Mount =/proc= and =/sys= from Lisp via =sb-alien=. But SBCL
  needs =/proc= to find its core, and preinit now does the privileged setup too, so
  the shim is the safer design.
- *Build SBCL static against musl*, eliminating the shipped glibc libraries.
- *Swank/SLynk over a socket* — a remote Lisp REPL into PID 1 from an editor.
- *A debugger in the console REPL that can't kill PID 1.* =run-repl= catches
  =serious-condition= around every eval, so an error never reaches
  =invoke-debugger=. Two ways back: (a) rebind =*debugger-hook*= to a guarded
  mini-debugger whose restarts always unwind to a safe loop; or (b) run the REPL
  in a *subprocess*, where the real SBCL debugger can run and a crash kills only
  the child. (b) is the cleaner separation. (The environment already has its own
  framebuffer debugger, [[file:code-browser.org][code-browser.org]].)

  =lisp-implementation-version=.

  =sb-kernel::restart-interactive-function= (the debugger) — the ones a release

  ([[file:kernel-config.org][kernel-config.org]], the #23 and #24 change-log entries).
