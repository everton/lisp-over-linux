How to verify things

The project's rule is "verify, don't assert". There are four tools, from cheapest to most thorough: a plain SBCL on the host, a rendered frame, the docs' own checkers, and a booted guest that is questioned over the network.

Host tests

  • clipboard-test.lisppoc/clipboard-test.lisp, undo-test.lisppoc/undo-test.lisp, files-test.lisppoc/files-test.lisp, sysinfo-test.lisppoc/sysinfo-test.lisp (fake /sys/class/power_supply trees, since QEMU has no battery), image-test.lisppoc/image-test.lisp (fixtures generated with ImageMagick).
  • sbcl-source-test.lisppoc/sbcl-source-test.lisp must run under ./sbcl's own runtime: SBCL_HOME=sbcl/obj/sbcl-home sbcl/src/runtime/sbcl --core sbcl/output/sbcl.core --script poc/sbcl-source-test.lisp gives 23/23. The system sbcl on this machine is a different version (2.6.6), its source locations point elsewhere, and it gives 14/23. That is not a regression (checked 2026-10-12).

render-frame

parse-subjectpoc/render-frame.lisp:246 lists the subjects it can open (-h prints them). It loads most of the stack in build order, but not fb.lisp, fb-browser.lisp, the network modules or the supervisor. In a rendered frame those modules' definitions show as "not in this image". That is expected. Convert the PPM with sbcl --script host-client/ppm2png.lisp in.ppm out.png.

sbcl --script poc/render-frame.lisp tour -s 1280x800
sbcl --script poc/render-frame.lisp workspace --spotter tour
sbcl --script poc/render-frame.lisp defn:accept-source
sbcl --script poc/render-frame.lisp modules --halo 300,200

The guest harness

  • Harness: boot-guesthost-client/guest-harness.lisp:97, probehost-client/guest-harness.lisp:328, qmp-holdhost-client/guest-harness.lisp:228. Its header records two hard-won traps: hold the modifier (a QMP chord releases it before the tty byte is read) and make answers self-identifying.
  • Environment: LOL_PORT (host port of the forward, default 4005), LOL_QEMU_CPU (default qemu64, which has no POPCNT; that is how the LOGCOUNT bug was caught), LOL_GUEST_DISK=test-disk.img (attached snapshot=on).

Writing down a negative result

AGENTS.md asks for this: when a check rules something out, record it, so the next reader does not search again. This guide's own examples are the red "Ruled out / corrected" boxes (the registry that could not show itself, the debugger that was never entered through *debugger-hook*, the 14/23 above).
