Live editing, the debugger

The Smalltalk part. You change a definition and the running image changes. The old text is kept, the change is listed, and an error opens a debugger while the stack that raised it is still there. Design: code-browser.org §3, §3a, §6.

Accept: C-c C-c

  • accept-panepoc/shell.lisp:2404, accept-targetinitramfs/present.lisp:797, accept-sourceinitramfs/registry.lisp:238, accept-packageinitramfs/registry.lisp:203, changed-definitionsinitramfs/registry.lisp:395.
  • Why the package matters: an edit of lol.textview::tv-draw read in CL-USER would define a new cl-user::tv-draw and leave the real one running. Accept would appear to work and change nothing. The package slot of each DEFN prevents this.
  • Why the method label matters: a generic function's methods share one name. Accept finds the right DEFN by the printed specializer list, the same string method-labelinitramfs/registry.lisp:77 produced at build time.
  • Not yet: writing changes back to files on disk ("file-out"). The plan is in session-persistence.org. Today a reboot loses every Accept.

"The form before point" is found by reading forms from the start of the buffer to the caret and keeping the last complete one (form-before-pointpoc/shell.lisp:757). Evaluation captures *standard-output* and catches every error (ws-evalpoc/shell.lisp:797), so a bad form cannot take PID 1 down.

The debugger

  • run-debugger-fbinitramfs/fb-browser.lisp:2059: a modal loop over the same canvas and the same three fds, published in *fb-canvas* and friends.
  • Data from the model: restart-listinitramfs/model.lisp:724 (compute-restarts), backtrace-frame-objectsinitramfs/model.lisp:734 (walks sb-di frames), frame-localsinitramfs/model.lisp:802.
  • A frame's locals are places, as an object's fields are: Tab to them, Enter or C-c C-c writes a value into the standing frame (set-frame-varinitramfs/model.lisp:924), then CONTINUE runs on with it, or R calls the frame again with the arguments it now holds (restart-frameinitramfs/model.lisp:1003). Why only some locals can be set, and the SBCL setter that faults on one kind: inspector-history.org §5.4.
  • The stage arms the same handler around every simulation tick (step-stage-panepoc/morphic.lisp:1818), so a collision with no method opens the debugger with the stage's own restarts (define-method drops a method template into the Workspace).
Several comments and two docs said the debugger is entered through *debugger-hook*. Nothing in the image sets *debugger-hook* or sb-ext:*invoke-debugger-hook* (checked by grep on 2026-10-12). Both entry points use handler-bind. The comments were corrected. An error that no armed handler catches reaches the handler-case around run-browser-fb, which prints it and returns to the supervisor menu.

The inspector's powers

The (present (x t)) fallback is the inspector (inspector-viewinitramfs/present.lisp:1055). Its rows come from inspect-placesinitramfs/model.lisp:507. A row that is a real place carries a setter in item-edit, and C-c C-c on it writes a value (set-fieldpoc/shell.lisp:2291). C-c C-e evaluates with self and the slots bound (eval-in-contextinitramfs/model.lisp:598). "Why is this alive?" asks the GC (retention-pathinitramfs/model.lisp:662). The history and cost of each power is in inspector-history.org.
