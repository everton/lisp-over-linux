Exercises

Small things to do, each with what you should see. They go from reading, to changing the running system, to extending it. Exercises marked host need only SBCL. The others need the environment, on the laptop or under QEMU (./build.sh --interactive). The expectations were checked on 2026-10-12. Where one was checked on the host rather than in the guest, the exercise says so.

Reading

1 · Take the tour

Press SuperL-Space, type tour and press Enter. Move with ↓. Press Enter on stop 06, read it, then C-g.

29 numbered rows in 8 chapters, starting at "1 · boot". As you move, the right column shows each stop's source. Stop 06 opens load-recording as an editable definition (title "definition load-recording"). The preinit.c and build.sh rows open the real files on the laptop, where the repository is under /home. Under QEMU they say "not on this disk".

2 · Jump around with M-. and M-,

In stop 06's source, put the caret on record-source and press M-. (or Esc then .). Then put it on read-file-into-string and press M-,.

A new breadcrumb level holding record-source's source. Then a list titled senders of read-file-into-string, whose rows drill to the callers. C-g pops each level. On a CL symbol such as mapcar, M-. gives a reference view: lambda list, docstring and, if the SBCL tree is on the disk, SBCL's own list.lisp source.

3 · Render a frame on the host (host) 
sbcl --script poc/render-frame.lisp tour -s 1280x800 -o /tmp/t.ppm
sbcl --script host-client/ppm2png.lisp /tmp/t.ppm /tmp/t.png

The tour list with stop 01's preview on the right. About 20 rows say "… is not in this image", because render-frame does not load fb-browser.lisp, the shell's input half, or the network. That is expected (How to verify things). Add -k "down down down down down ret" to see stop 06 opened.

4 · The protocol without pixels (host) 
sbcl --non-interactive --eval '(require :sb-introspect)' \
  --eval '(load "initramfs/registry.lisp")' \
  --eval '(mapc (function load-recording) (list "initramfs/model.lisp" "initramfs/present.lisp" "initramfs/tour.lisp" "initramfs/examples.lisp"))' \
  --eval '(show-view (subj-xref :senders (quote source-of)))'

A text rendering of the same view the browser would draw: == senders of source-of [list], a row (fast-method present (subj-defn)), and the commands line. present is pure data, so a REPL is enough to explore it.

Changing the running system

5 · Define a function live, and watch the change set

In the Workspace, change the primer's greet to return (list :hi who), put the caret after it and press C-c C-c. Put the caret after (greet "lisp") and press C-x C-e. Then SuperL-Space "change set". Go back, edit greet again, and press C-c C-c again.

Status line: Accepted: greet, then (GREET "lisp") => (:HI "lisp"). The change set lists greet as "new this session". After the second Accept it says "new this session · 1 revision". On the host, changed-definitions went from ((GREET 0 T)) to ((GREET 1 T)).

6 · Edit the environment itself

SuperL-Space, type +wheel-lines+, press Enter. Change 3 to 10 and press C-c C-c. Scroll a long source pane with the mouse wheel.

Each wheel notch now moves 10 lines instead of 3. No rebuild and no restart were needed: defparameter re-evaluated sets the variable, and the main loop reads it on every notch. The change set lists +wheel-lines+ with "1 prior version". A reboot reverts it, since nothing is written to disk yet (session-persistence.org).

7 · Pick a restart in the debugger

In the Workspace, put the caret after (lol.examples:launch) and press C-c C-d.

The debugger, with an OFF-COURSE condition and a restart list that starts with STEER's own: correct-course, hold-heading, use-heading, scrub, then "Return to the workspace" and the outer ones (checked on the host with compute-restarts). Tab moves to the backtrace, where ↑/↓ show each frame's locals. Choosing use-heading (2, Enter) asks you for a value, and the launch continues, because the stack was never unwound.

8 · Who drew this?

Middle-click (or Alt-click) on a row of any list.

The halo: handles around the point and a caption naming the innermost thing under it. Its entries include "Code: draw-list-body", which opens the function that painted the row. Up, Tab or another middle click walks outward through the layers (row, pane, screen) and Down walks back in. On the host: render-frame.lisp modules --halo 300,200 prints the layers.

Extending it

9 · Add a subject of your own

Type these into the Workspace and press C-c C-c after each, then put the caret after (subj-hello) and press C-c C-i:

(defstruct (subj-hello (:constructor subj-hello ())))

(defmethod present ((s subj-hello))
  (make-view :title "hello, subjects"
             :items (list (make-item :label "the tour" :subject (subj-tour))
                          (make-item :label "a class"
                                     :subject (find-class 'standard-object)))))

(subj-hello)

A list pane titled "hello, subjects" with two rows. The right column previews the tour, and Enter on "a class" shows standard-object's class DAG. The shell did not change: one method was enough. The change set now lists present and subj-hello, both "new this session" (checked on the host). To make it findable, push a function onto *spotter-sources* as tour.lisp does at its end.

10 · Break a guide reference on purpose (host)

In a scratch copy, rename jump-at-point in poc/shell.lisp and run sbcl --script doc/guide/regen.lisp. Then undo the rename.

UNRESOLVED paths.html: poc/shell.lisp#jump-at-point (and the other pages that cite it), and exit status 1. This is how the guide stays true. check-tour.lisp does the same job for the in-image tour.

11 · Ask the booted guest a question (host + QEMU) 
./build.sh && LOL_PORT=4018 sbcl --script check-tour.lisp

QEMU boots headless, and five rows print: 29 stops, 0 unresolved, 0 failing views, Spotter 1, :source 1. Then ===== ALL PASS =====. Read check-tour.lisp: each assertion is a Lisp form the guest evaluates about itself.
