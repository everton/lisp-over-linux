Glossary

The terms the code and the documents use without stopping to explain them. Each entry says briefly what the term is and then where this code uses it. Grouped from the metal up.

Boot and kernel

EFISTUB
The kernel image built so that UEFI firmware can run it directly as an EFI application. No bootloader is needed. Here the bzImage is copied to \EFI\BOOT\BOOTX64.EFI, the path firmware tries by default (build.shbuild.sh:389; micro-distro.org).
initramfs, cpio
A cpio archive the kernel unpacks into an in-memory filesystem and uses as /. Ours is a separate file, not built into the kernel, listed line by line in initramfs.sbcl.listinitramfs/initramfs.sbcl.list.
PID 1
The first user process. The kernel panics if it exits, and orphaned processes are re-parented to it. Here it is preinit and then, after execve, the Lisp (supervisor-maininitramfs/supervisor.lisp:84, whose docstring says "Never returns").
devtmpfs
A filesystem the kernel fills with /dev nodes for the devices it finds, so no udev is needed. Mounted first thing in preinit maininitramfs/preinit.c:594. Its nodes are root-owned, which is why lol-rootd exists.
sysfs, /proc
Kernel state presented as small text files. The framebuffer's geometry comes from /sys/class/graphics/fb0 (fb-geometrypoc/fb.lisp:18), input devices from /proc/bus/input/devices (scan-input-devicesinitramfs/fb-browser.lisp:211), the battery from /sys/class/power_supply.
ioctl
"Do this device-specific thing": a syscall taking an fd, a request number and a pointer to a struct. Used for KDSETMODE (with-graphics-consolepoc/fb.lisp:41), EVIOCGABS (evdev-abs-rangeinitramfs/fb-browser.lisp:419) and SIOCSIFADDR (bring-up-interfaceinitramfs/net.lisp:68). The struct is built byte by byte in a Lisp vector.
framebuffer, efifb, fbcon
A framebuffer is screen memory you can write to (/dev/fb0). efifb is the driver that exposes the one the firmware set up. fbcon is the kernel's text console drawn onto it, which must be told to stop (KD_GRAPHICS) while we draw. framebuffer.org.
evdev, input_event
The kernel's generic input interface: one /dev/input/eventN per device, read as 24-byte records (time, type, code, value). Decoded by hand in read-mouseinitramfs/fb-browser.lisp:607. input.org.
poll(2), inotify
poll sleeps until one of several fds is readable. inotify makes a directory change readable as an fd. Together they let one loop wait for keys, mice and new devices (poll-input-onceinitramfs/fb-browser.lisp:1021).
raw mode (termios)
A tty normally buffers a line and turns Ctrl-C into a signal. Raw mode delivers each byte as it arrives, which is needed for C-c C-c to reach us (with-raw-modeinitramfs/line-editor.lisp:43).
fw_cfg
QEMU's firmware-configuration device, visible under /sys/firmware/qemu_fw_cfg. Real hardware has none, which makes it a safe test-only switch for the net REPL (net-repl-wanted-pinitramfs/net.lisp:450).

Privilege and storage

capabilities, ambient set
Root's power split into about 40 pieces. A capability is normally lost across execve for a non-root program. The ambient set (Linux 4.3+) is how it survives. preinit keeps five (become_userinitramfs/preinit.c:557).
bind mount
The same directory made visible at a second path, possibly with different flags. Only /mnt/host/home is bound onto /home (mount_storageinitramfs/preinit.c:270).
real vs effective uid
The effective uid decides permissions; the real uid decides who may signal you. lol-rootd is real = user, effective = root, so the user's Lisp can signal it and it keeps root's powers (start_rootdinitramfs/preinit.c:494).

SBCL and the image

core, frozen heap, save-lisp-and-die
The whole Lisp heap written to a file, which wakes up as it was. What is loaded before the save is all the image has. No Quicklisp, no require at run time (How the image is built).
sb-alien (FFI)
SBCL's foreign function interface: declare a C function and call it. Every syscall here goes through it, e.g. poll, open, ioctl at the top of %fbb-pollinitramfs/fb-browser.lisp:24. sb-posix is avoided on purpose (processes.org §6).
pinning, SAP
The GC moves objects. with-pinned-objects promises it will not, and vector-sap gives the raw address (a "system area pointer") to hand to the kernel (blit-fbpoc/fb.lisp:104).
package
A namespace of symbols. Most of the image is in CL-USER; the toolkit has lol.* packages. A pkg:name needs the package to exist when the file is read, which constrains the load order. load-recording follows in-package so each definition is filed in its real package.
reader macro
A character that changes how the reader parses. !#RRGGBB is a colour literal (!# in canvas.lisppoc/canvas.lisp:39), installed in the readtable that is saved into the image.
POPCNT, the LOGCOUNT fix
A CPU instruction QEMU's default CPU lacks. SBCL 2.6.8's fallback routine had a register mismatch, so compiling arithmetic crashed the guest. patch-logcount-routineinitramfs/logcount-fix.lisp:124 patches the machine code at build time (inspector-history.org §5.6).

CLOS and the condition system

generic function, method, specializer
A function whose behaviour is chosen from its arguments' classes. Each defmethod handles one combination (its specializers). present is the central one (presentinitramfs/present.lisp:341). Tutorial: learn-clos.org.
multiple dispatch, dispatch matrix
Choosing a method on several arguments. lol.examples:collide dispatches on two, and its matrix of covered and missing pairs is dispatch-matrixinitramfs/model.lisp:211.
EQL specializer
A method for one specific object rather than a class, written (eql :hull-breach). Printing it correctly is why specializer-labelinitramfs/registry.lisp:48 uses prin1.
method combination, effective method
How :around, :before, primary and :after methods are combined for one call. effective-method-onioninitramfs/model.lisp:253 draws it as layers.
MOP (metaobject protocol)
Classes, generic functions and methods are themselves objects you can query (sb-mop:class-direct-superclasses …). The whole model layer is built on it (class-infoinitramfs/model.lisp:63).
condition, handler, restart
Lisp's error system separates signalling a condition, handling it, and the restarts (ways out) the code around it established. handler-bind runs the handler before unwinding, which is how the debugger sees a live stack (workspace-debug-itpoc/shell.lisp:697, restart-listinitramfs/model.lisp:715).
closure, captured variable, value cell
A function that remembers variables from where it was made. SBCL stores a captured variable that is assigned in a boxed "value cell", and only those can be written from the inspector (closure-capturesinitramfs/model.lisp:359).

The environment's own words

registry, DEFN
The table of every definition's source text, kept in the image (*registry*initramfs/registry.lisp:37).
subject, view, item, command
The present protocol's data (present and the shell).
pane, trail, tab
The shell's state: a presented view; a stack of them, shown as breadcrumbs; several trails, shown as tabs.
drill
Opening an item's subject as a new pane at the bottom of the trail (trail-pushpoc/shell.lisp:169).
nav split, preview
A list on the left, a live read-only view of the selected item on the right (preview-forpoc/shell.lisp:1316).
Workspace
A Lisp scratch buffer with Do it / Print it / Inspect it / Debug it / Accept ((present subj-workspace)initramfs/present.lisp:844).
Accept, change set
Compiling an edit into the running image, and the list of everything accepted this session (accept-sourceinitramfs/registry.lisp:207).
Spotter
The fuzzy finder, SuperL-Space, after Pharo's (run-spotter-fbinitramfs/fb-browser.lisp:2586).
halo
Handles around whatever is under the middle button: what it is, and which code drew it. After Morphic (halo-entriespoc/shell.lisp:3285).
stage
A live simulation of COLLIDE's objects, where a missing method opens the debugger ((present subj-stage)initramfs/stage.lisp:671).
PRIMARY, CLIPBOARD
X11's two selections: PRIMARY is "what you last selected" (middle-click pastes it), CLIPBOARD is what you copied. Kept as plain data (primarypoc/clipboard.lisp:267; clipboard.org).
QMP, SLIRP
QEMU's JSON control socket (tests use it to type), and QEMU's user-mode network (the guest is 10.0.2.15, the host forwards port 4005).
