Storage, privilege, network

How the machine around the environment is set up: whose files it can touch, which root powers it keeps, and how it gets an address. Design documents: storage.org (tag #25), networking.org (tag #21 onward), processes.org.

Two processes, two trust levels

  • Finding the disk without udev or blkid: find_diskinitramfs/preinit.c:206 reads each block device's ext4 superblock (magic 0xEF53 at offset 0x438, the UUID at 0x468) and compares it with disk=UUID=… from lol.conf.
  • Mounting: mount_storageinitramfs/preinit.c:272. The filesystem is mounted read-write, because one superblock has one rw/ro state and /home needs to write. Then the /mnt/host view is bind-remounted read-only.
  • Dropping privileges: become_userinitramfs/preinit.c:713. Shrink the bounding set, PR_SET_KEEPCAPS, set gid then uid, capset, then raise each of the five as ambient. Ambient capabilities are what survive execve for a non-root program.
  • The helper: start_rootdinitramfs/preinit.c:648. Its real uid is the user's, so the user may signal it, and its effective uid is 0, so it keeps root's powers. The Lisp side is release-diskinitramfs/process.lisp:36 and power-offinitramfs/process.lisp:93.
  • QEMU-only alternatives (tag #26): lol.disk=9p:hostroot mounts the build host's whole root over virtio-9p, with /home as an overlay whose writes vanish (mount_storage_9pinitramfs/preinit.c:249). Tests use test-disk.img, attached snapshot=on. Never pass the real disk to QEMU.

The file system as data is file-entryinitramfs/files.lisp:224 and friends, calling libc through sb-unix / sb-alien rather than sb-posix (processes.org §6 explains why: an inlined sb-posix entry point cannot be recompiled in the guest). Folders and files become subjects in file-views.lisp. The keys and operations are in poc/file-manager.lisp (file-manager.org).

Networking, as it is today

  • configure-eth0initramfs/dhcp.lisp:480, dhcp-acquireinitramfs/dhcp.lisp:322, build-dhcpinitramfs/dhcp.lisp:116 (the packet, byte by byte), bring-up-interfaceinitramfs/net.lisp:68 (an ifreq built in a byte vector and passed to ioctl).
  • The REPL server: start-net-replinitramfs/net.lisp:392, %serve-net-replinitramfs/net.lisp:368, net-repl-wanted-pinitramfs/net.lisp:450. The host client is host-client/lol-repl-client.c. The test harness uses the same socket to read the guest's state (How to verify things).
  • Tutorial from scratch: learn-networking.org.

A second process

Only one process writes /dev/fb0. A peer process contributes a view (data), never pixels. call-workerinitramfs/worker.lisp:151 re-executes /sbin/lisp job NAME, reads one plist from the pipe with *read-eval* off, and (present subj-worker)initramfs/worker.lisp:189 rebuilds real subjects from the names it receives. processes.org §2 and §7 explain the design. check-worker.lisp proves the fork is real.
