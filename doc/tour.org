#+TITLE: A guided tour of the code — index of the HTML guide and the in-image tour
#+STARTUP: showall

This is the org-mode entry point to two teaching resources that cover the same ground:

- *The HTML guide*, [[file:guide/index.html][doc/guide/index.html]]. It works offline from =file://= and has light and
  dark themes. It contains diagrams of the boot, the build, the module graph, the =present= protocol and a keypress,
  the rendering and input pipelines, live editing, privilege and networking. It also has six guided reading paths, a
  glossary and exercises. Open it with =xdg-open doc/guide/index.html=, or =M-x eww-open-file= for a text-only look.
- *The in-image tour*, =subj-tour= in [[file:../initramfs/tour.lisp][initramfs/tour.lisp]]. In the running environment:
  =SuperL-Space=, type =tour=, =Enter=. Each row is one of the image's own live definitions, in reading order. The
  right-hand column previews its source as you move down. =Enter= opens it (editable, and Acceptable), and =C-g= comes back.

* How the guide stays true

Every =file:line= in the HTML is generated. [[file:guide/regen.lisp][doc/guide/regen.lisp]] does three jobs:

1. It indexes every top-level definition in the Lisp sources.
2. It rewrites each =<a class="ref" data-ref="FILE#NAME">= in the pages from that index, and exits non-zero on any
   reference that no longer resolves.
3. It re-derives the module dependency graph into =guide/deps-data.js= from which names each file mentions, and
   stamps the sidebar into every page.

Run it after changing code the guide talks about, as you run =./check-links.sh= after changing docs:

#+begin_src sh
  sbcl --script doc/guide/regen.lisp    # "refs: N checked, 0 unresolved; 0 errors in all"
#+end_src

The in-image tour has its own guard. Its stops name symbols as strings and resolve when shown, so a rename
degrades a stop to a polite "not in this image" row instead of failing the build. [[file:../check-tour.lisp][check-tour.lisp]] boots
the image and asserts that every stop resolves and presents.

What writing the guide turned up (each is recorded where it belongs):
- =registry.lisp= was the one module missing from its own registry, so =accept-source= opened as "SBCL's own"
  reference. It now records itself (=record-source=, the last form in [[file:../initramfs/registry.lisp::when *load-truename* (record-source][registry.lisp]]).
- Comments and two docs said the debugger is entered through =*debugger-hook*=. Nothing sets that variable: both
  entry points use =handler-bind= ([[file:../poc/shell.lisp::defun workspace-debug-it][workspace-debug-it]], [[file:../poc/morphic.lisp::defun step-stage-pane][step-stage-pane]], once =tick-live-stage=).
- [[file:sbcl-init.org][sbcl-init.org]] said =shell.lisp= expands =with-raw-mode=. It does not. =fb-browser.lisp= and =repl.lisp= do.

* Regenerating, and extending

- Derived data: =doc/guide/deps-data.js= (module graph) and every =file:line= in =doc/guide/*.html=. Both come from
  =sbcl --script doc/guide/regen.lisp=. Do not edit them by hand.
- Hand-written: the pages' prose and diagrams (inline SVG), =guide.css= and =guide.js= (the theme button), and the
  layer of each module (=+layers+= in =regen.lisp=).
- Adding a subsystem: see [[file:guide/in-progress.html][in-progress.html]], "How to add a section".
