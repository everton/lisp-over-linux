#+TITLE: Line editing in pure Lisp — readline-class input without a native lib
#+STARTUP: showall

Parent doc: [[file:sbcl-init.org][sbcl-init.org]] (the SBCL supervisor / REPL) ·
related: [[file:framebuffer.org][framebuffer.org]] (the fbcon console that renders the
escapes) · [[file:kernel-config.org][kernel-config.org]] · [[file:input.org][input.org]] (the OTHER half of input: the raw
=/dev/input/event*= devices, for the mouse and for the bare modifiers this
termios path structurally cannot see).

The console REPL has readline-style editing — history, arrows, =C-a= / =C-e=,
kills, Tab completion, Lisp colouring — written entirely in Lisp. SBCL's core has
no readline, and the image ships no GNU readline or any other new native =.so=.
The one thing Lisp can't do alone, switching the terminal to raw mode, is an FFI
call into the =libc= the image already ships.

*Status: built.* Code: [[file:../initramfs/line-editor.lisp][initramfs/line-editor.lisp]] (termios, editing, history,
completion hook) and [[file:../initramfs/repl.lisp][initramfs/repl.lisp]] (the REPL that drives it).

* Why canonical mode is the wall

The kernel TTY (N_TTY line discipline) defaults to *canonical mode*: it buffers a
whole line and hands it to the program only on Enter. It handles Backspace for you
but nothing else. Arrow keys, history recall, word movement — the program never
even sees those keystrokes.

That behaviour is real code you can read: [[file:../linux/drivers/tty/n_tty.c][=drivers/tty/n_tty.c=]], and specifically
[[file:../linux/drivers/tty/n_tty.c::static bool n_tty_receive_char_canon][=n_tty_receive_char_canon=]] — the per-character path taken when =ICANON= is set,
where "hold it until a line terminator arrives" lives.

To edit for real you switch the TTY to *raw mode* (canonical and echo off). Then
you receive each keystroke as it's pressed, including the escape sequences arrows
send (=ESC [ C=, =ESC [ D=, …), and you echo and redraw the line yourself.

* termios: the one syscall, and why it isn't a new dependency

Raw mode is set with =tcgetattr= / =tcsetattr= — a syscall, not portable Lisp.
Calling it is FFI into =libc.so.6=, which is already in the initramfs. So the
editing logic (buffer, cursor, history, keys) is all Lisp; only the mode flip is a
few lines of =sb-alien= to a function that's already there.

- *Why not =sb-posix=.* It grovels =struct termios= from the real header, nicer
  than our hand-counted offsets, and a migration to it was written and tested. It
  was reverted: =sb-posix:tcgetattr= is =declaim inline= and expands into groveled
  alien structs whose type information doesn't survive =save-lisp-and-die= into
  the guest. The REPL still ran, but =(compile nil '(lambda () (with-raw-mode (0)
  :x)))= failed in the guest — you could no longer =C-c C-c= this file's own
  definitions from inside the image. The hand-rolled version recompiles there
  (checked both ways). Full audit: [[file:processes.org::#sb-posix-audit-nothing][processes.org, sb-posix — the audit, and why nothing was migrated]].
- *Always restore.* The saved termios goes back on every exit through
  =unwind-protect=.

* Aside: what an =ioctl= is

=tcsetattr= isn't its own syscall — glibc implements it as an *ioctl*. This
project leans on ioctls throughout, so here is what one is.

=read= and =write= move a *stream of bytes*. Much of what you need from a device
isn't a stream — "set the baud rate", "give this interface an IP", "stop rendering
the console". Rather than a syscall per question, Unix has one catch-all door:

#+begin_src c
  int ioctl(int fd, unsigned long request, void *argp);
#+end_src

- *=fd=* — which device (an open file descriptor, so the usual permission rules
  apply).
- *=request=* — a magic number naming the operation.
- *=argp=* — a pointer to a struct carrying arguments in, results out, or both.

The request number packs a direction (read/write/both), the struct's size, a
"magic" letter claiming a namespace for the subsystem, and an ordinal within it —
what the kernel's =_IOR= / =_IOW= / =_IOWR= macros build. Each device family
defines its own set, which is why the constants look unrelated and must each be
exactly right:

| constant                   | value    | what it does                  | where we use it    |
|----------------------------+----------+-------------------------------+--------------------|
| =TCSETS= (via =tcsetattr=) | =0x5402= | set terminal attributes       | raw mode, here     |
| =SIOCSIFADDR=              | =0x8916= | set an interface's address    | [[file:../initramfs/net.lisp::defconstant +siocsifaddr+][net.lisp]]           |
| =SIOCSIFFLAGS=             | =0x8914= | bring an interface up/down    | [[file:../initramfs/net.lisp::defconstant +siocsifflags+][net.lisp]]           |
| =KDSETMODE=                | =0x4B3A= | console text ↔ graphics mode  | [[file:../poc/fb.lisp::defconstant +kdsetmode+][fb.lisp]]            |
| =FBIOGET_VSCREENINFO=      | =0x4600= | read framebuffer pixel format | [[file:framebuffer.org::#dev-fb0-driving-pixels][framebuffer.org, /dev/fb0 — driving the pixels yourself]] |

An ioctl is *the same three-argument FFI call every time*. Bind it once with
=sb-alien= and every one of those knobs is reachable — which is why this project
needs no =stty=, =ip=, =fbset= or =setfont=. The cost: the kernel does no type
checking for you. A wrongly laid-out struct gets =EINVAL= at best, silence at
worst.

See also [[file:networking.org::#userland-half-reaching-network][networking.org, Userland half — reaching the network from SBCL]] (the interface ioctls in anger) and [[file:framebuffer.org::#kd-graphics-telling-fbcon][framebuffer.org, KD_GRAPHICS — telling fbcon to stand down]] (=KDSETMODE=, with the =unwind-protect= that keeps you from a dead console).

* What makes it render: fbcon speaks ANSI/VT

The Linux framebuffer console is itself a *terminal emulator*: it interprets a
solid set of ANSI/VT escape sequences. So a Lisp editor renders by emitting
escapes (=\e[K=, =\e[C=, =\e[D=, =\e[<n>G=), exactly as readline drives a
terminal. "The fb console is line-based" is only true of the canonical default; in
raw mode it's a full escape-driven canvas ([[file:framebuffer.org][framebuffer.org]]).

* The editor

** The three pieces

1. *Raw mode* — [[file:../initramfs/line-editor.lisp::defmacro with-raw-mode][=with-raw-mode=]]. Two [[file:../sbcl/src/code/target-alieneval.lisp::defmacro define-alien-routine][=sb-alien:define-alien-routine=]] bindings,
   =%tcgetattr= / =%tcsetattr= — the same "FFI into the libc we ship" trick as
   =reboot(2)= in [[file:../initramfs/process.lisp::defun power-off][=power-off=]]. (The macro is readable Lisp: it expands into a
   =%alien-funcall= with the declared types; SBCL's alien layer is
   [[file:../sbcl/src/code/target-alieneval.lisp][=sbcl/src/code/target-alieneval.lisp=]], its syscall wrappers
   [[file:../sbcl/src/code/unix.lisp][=sbcl/src/code/unix.lisp=]].) =struct termios= is treated as a 60-byte blob,
   patched only where needed:
   - *=c_lflag=* (offset 12): clear =ICANON|ECHO= (=0x0A=) in the low byte.
   - *=c_cc=* (offset 17): =VMIN=1=, =VTIME=0=, so =read()= returns one keystroke
     at a time.
   - *=c_iflag=*: clear =IXON|IXOFF=. With =IXON= on, Ctrl-S is flow control
     (XOFF): the kernel keeps the byte and stops the console's output until a
     Ctrl-Q, which froze the environment on its next write ([[file:diagnostics.org::#four-ways-screen-freezes][diagnostics.org, Four ways a screen "freezes"]]).
   - *=ISIG= kept by default*, so Ctrl-C still interrupts a runaway eval. Passing
     =signals nil= clears it too, so Ctrl-C arrives as a byte — what the code
     browser needs for its =C-c C-c= chord.
   =unwind-protect= restores the saved settings on every exit (return, error,
   Ctrl-C), so a crash never leaves the console raw.
2. *Rendering* — [[file:../initramfs/line-editor.lisp::defun refresh-line][=refresh-line=]] redraws the whole line on every edit with three
   escapes fbcon understands: =\r= (column 0), =\e[K= (clear to EOL), =\e[<n>G=
   (absolute column for the cursor). One uniform redraw covers insert, delete,
   motion and history. The line goes through =colorize-lisp= (strings, comments,
   keywords, =#\= characters, depth-cycled parens), which inserts only zero-width
   SGR, so the column math stays exact.
3. *Editing logic* — [[file:../initramfs/line-editor.lisp::defun read-line-edited][=read-line-edited=]] keeps a =line= string and a =point=,
   rebuilding the string on each edit (lines are short; clarity beats a gap
   buffer). [[file:../initramfs/line-editor.lisp::defun read-escape][=read-escape=]] parses arrow / Home / End / Delete sequences (=ESC [ …=,
   the numeric =ESC [ n ~= forms, and =ESC O H/F=). History is a plain list in
   =*repl-history*=.

** Key bindings

| Key                 | Action                                            |
|---------------------+---------------------------------------------------|
| Left / Right        | move cursor by one                                |
| Home / End, C-a/C-e | jump to start / end of line                       |
| C-b / C-f           | move cursor (same as arrows)                      |
| Backspace, C-d      | delete before / under the cursor                  |
| Delete              | delete under the cursor                           |
| C-k / C-u           | kill to end / to start of line                    |
| C-w                 | kill the previous word                            |
| C-l                 | clear screen and redraw                           |
| Up / Down, C-p/C-n  | history previous / next                           |
| Tab                 | complete the symbol at point (or list candidates) |
| C-d on empty line   | EOF — leave the REPL (same as =:quit=)            |
| C-c                 | abandon the line (network REPL only; locally it's SIGINT) |

** Tab completion (symbols)

=Tab= completes the partial symbol before the cursor. The editor stays
Lisp-agnostic: =read-line-edited= calls a hook, =*completer*= (token → list of
candidate strings), which the REPL points at =complete-symbol= (=repl.lisp=).

1. *Find the token* — scan back from point over symbol constituents (=token-start=).
2. *Ask* =*completer*= for matches.
3. *Insert* — one match: insert it; many: insert their =longest-common-prefix=; if
   that can't extend the token, list the candidates on a fresh line and redraw.

=complete-symbol= matches case-insensitively (returning lowercase) the symbols
accessible in =*package*=, or with a =pkg:= / =pkg::= prefix the external / all
symbols of that package, or keywords after a leading =:=. It iterates with
=do-symbols= / =do-external-symbols=; nothing native, nothing precomputed. It works
the same on the local console and over the network REPL (the host client forwards
the Tab byte).

** How it plugs into the REPL

=run-repl= picks the mode at entry. =tty-raw-capable-p= (a throwaway =tcgetattr=)
decides whether there's a real terminal:

- *A terminal* → =with-raw-mode= + =editing-repl=. If =complete-form= reports the
  form unbalanced, it keeps reading continuation lines (=  ...>= prompt), so
  multi-line forms work like a normal listener.
- *A pipe or file* → =plain-repl=, a line-buffered =read= loop.

Every =read= and =eval= is guarded, so a typo can't kill PID 1.

* Alternatives ruled out

- *linedit* (https://github.com/sharplispers/linedit). A pure-CL editor with far
  more: a multi-line form reader, unlimited undo / kill ring / history, paren
  matching, symbol and filename completion, apropos at point. But it depends on
  =:cffi :terminfo :osicat :alexandria=. *osicat* builds a native C shim
  (=libosicat=) with CFFI-grovel — a C compiler at build time and a new =.so= to
  ship. *terminfo* reads the terminfo database at runtime, so its data files
  (=/usr/share/terminfo/l/linux=) and =TERM=linux= would have to ship too. Worth
  revisiting only if the no-native-lib goal is relaxed.
- *cl-readline.* A binding to GNU readline — the native library being avoided.
- *Swank / SLY.* Full editing from your own editor over TCP, but a large
  dependency to bake in. The image has its own network REPL instead
  ([[file:networking.org][networking.org]]).

* Known limits

- *Single line only.* A line longer than the screen mis-renders on the wrap (the
  =\r= / column math assumes one row). Fine for a REPL prompt.
- *No kill ring / yank, no undo, no paren match.* The editor's =C-k= / =C-u= /
  =C-w= delete; nothing can be yanked back.
- *Multi-line history is flattened* to one line (newlines → spaces), so the
  single-line renderer stays honest.
