#+TITLE: host-client/ — tools that run on YOUR machine, not in the Lisp machine
#+STARTUP: showall

Everything here runs on the *host* (the developer's machine). None of it ships in
the initramfs, is baked into =/sbin/lisp=, or runs as the guest's PID 1. The guest
world lives in =initramfs/=; this directory is its deliberate opposite, kept
separate so the boundary is obvious.

* Why the tools are Lisp

They replaced about 440 lines of Python embedded in three shell scripts and two
=.py= files. The work is a Unix socket, a TCP socket, some byte packing and some
sleeps, all of which SBCL has built in, and a project about its own Lisp machine
shouldn't require Python to follow its build. *python3 is not a dependency of
anything here.*

- *PNG without zlib.* The only piece that looked like it needed a library is the
  zlib stream. =lol.deflate= writes it: CRC-32, Adler-32, LZ77 over a 32 KB
  window, and DEFLATE's fixed Huffman code.
- *Measured cost.* On a 1280×720 screenshot: PPM 2 764 816 bytes, ours 29 316,
  zlib =-9= 12 765. That's 94× better than storing and 2.3× worse than zlib, about
  16 KB per committed screenshot. The whole gap is dynamic Huffman, a known ~150
  lines if it ever matters.
- *No JSON parser for QMP.* QMP is line-delimited JSON, but we only ever emit JSON
  (=format=) and only ask of a reply whether it says =return= or =error= (=search=).

* lol-repl-client.c — a host terminal for the guest's network REPL

Connects your terminal to the guest's TCP REPL on port 4005 ([[file:../doc/networking.org][networking.org]] §6a).
It puts your *local* terminal in raw mode and forwards keystrokes byte by byte, so
the line editor *inside the guest* gets arrows, Ctrl-C and Ctrl-D and drives
history and editing remotely. No PTY is needed on the guest side.

- *When the REPL is on.* The guest serves it only when the boot asks: QEMU's
  =fw_cfg= (=build.sh= passes it) or =lol.netrepl=1= on the kernel command line.
  The supervisor menu's =t= toggles it.

Build it once (the binary is gitignored), then run it:

#+begin_src sh
  cc -O2 -o host-client/lol-repl-client host-client/lol-repl-client.c

  ./build.sh --interactive                     # boots QEMU with the hostfwd and the REPL on
  host-client/lol-repl-client                  # defaults: 127.0.0.1 4005
  host-client/lol-repl-client 10.0.2.15 4005
#+end_src

Keys (the guest interprets them; the client just forwards them raw):
- *=Ctrl-C=* aborts the current input line; you stay connected.
- *=Ctrl-D= on an empty line* ends the session in the guest, so the client
  disconnects. The local terminal is always restored on exit (normal, error or
  signal).

*Security.* The network REPL is a plaintext, unauthenticated remote =eval= in PID 1:
root on a diskless boot, the user with PID 1's capabilities otherwise. Use it only
over QEMU's =hostfwd= (host loopback) or a trusted cable, never on an untrusted
network.

Dependencies: a C compiler and libc for the client; a host SBCL for the Lisp tools
(the one =build.sh= already needs). Nothing else.
