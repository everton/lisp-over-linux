# AGENTS.md — working notes for AI agents in `~/lisp-over-linux`

This is a **learning project**: a very minimal EFISTUB Linux that a UEFI laptop
boots directly from a USB stick (no GRUB/bootloader), now running **SBCL Common
Lisp as PID 1**. The user is here to *understand* the system, so prefer
**didactic, well-commented** code and explanations over production hardening.

## Keep the docs in sync with reality — REQUIRED

The `.org` files are the deliverable, not an afterthought. When you change the
system, update the matching doc **in the same turn**:

- **Changed the kernel `.config`** (enabled/disabled any option) →
  update **`doc/kernel-config.org`**: fix the relevant table, bump the kernel tag,
  and add a line to its "Change log". Re-run the audit `grep`s documented in
  that file's "How to regenerate / audit" section and reconcile differences.
  **Also refresh the tracked snapshot** in the same turn (run from the project
  root): `cp linux/.config kernel/config-7.2.5` (the live `.config` lives outside
  the repo behind the `./linux` symlink; `kernel/config-7.2.5` is our copy).
- **Changed the boot chain / USB / EFISTUB** → update `doc/micro-distro.org`.
- **Changed `preinit.c`, the Lisp modules, the initramfs list, or `build.sh`** →
  update `doc/sbcl-init.org` (and its STATUS line).
- **Bumped the kernel build** → bump the tag (`#NN`) consistently across
  `doc/kernel-config.org`, `doc/sbcl-init.org`, and `doc/micro-distro.org`.

If a doc and the code disagree, the **code/`.config` is truth** — fix the doc.

### Verify, don't assert

**Every factual claim in a doc gets checked against the source before it is
written** — our code, `./linux`, `./sbcl`, or a running SBCL. This is not
pedantry; it routinely catches real errors. Recent examples: `ship`'s class
precedence list includes SBCL's own `SLOT-OBJECT` (the ANSI-only answer was
wrong), `COLLIDE` has 13 methods where a `grep` suggested 12, `fbcon.c` lives
under `drivers/video/fbdev/core/` and not `drivers/video/console/`, and
`DRM_FBDEV_EMULATION` is defined in `drivers/gpu/drm/clients/Kconfig`.

Cheap checks worth running: `grep` the kernel headers for an ioctl constant's
value, `grep -n "^config FOO"` for a config symbol, `wc -l` for a line count,
`stat`/`ls` for a size, and a throwaway `sbcl --non-interactive --eval` for
anything about CLOS/the MOP.

**Check every `[[file:...]]` link resolves** — run **`./check-links.sh`** (add
`--quiet` for problems only; it exits non-zero if anything is broken). It
resolves each link relative to the file it lives in, because depth differs —
`../` from `doc/`, `../../` from `doc/background/`, the commonest way to get one
wrong — and it verifies the `::search` anchor is really present, so a renamed
function surfaces as a broken link instead of a silent one. Links into the
gitignored `./linux` and `./sbcl` trees are reported as SKIPPED when those
symlinks are absent. Run it before committing any doc change.

### Drift shapes to check first

The rule above has existed for a while and drift still accumulated, because these
failures are *quiet* — nothing breaks, a doc merely stops being true. The audit on
2026-08-09 found all of these; check them by name when touching a doc:

- **Facts that were true once.** `AGENTS.md` claimed "Networking is entirely OFF
  (`CONFIG_NET` unset)" — wrong since tag #21 — and `line-editing.org` ruled out a

### Write down what the check ruled OUT, not only what it confirmed

"Verify, don't assert" says to check. It is silent on what to leave behind when
the check comes back **negative**, and that is the half that gets lost — because
a negative result looks like nothing happened, so nobody records it, so the next
person repeats the entire search.

Two from 2026-09-20, both of which cost real time twice:

- The condition sweep reported a type called `TYPE`, which has never existed.
  `quoted-symbol` accepted a bare symbol, which is right for handler clauses and
  wrong for signalling sites. The useful artifact is not the fix, it is the
  *reason the leniency was there* — so the next reader does not "simplify" the
  two functions back into one.
- A probe showed `accept-source` failing with `REDEFINITION-WITH-DEFUN`. That was
  a **test artifact** — a `handler-case` on `CONDITION` swallowing a redefinition
  *warning* — not a finding. Recorded as explicitly-not-a-finding, because a
  phantom seen once tends to be rediscovered.

So: when you investigate something and it turns out not to be real, say so in the
commit message or the doc, with the reason. The next person should find the
*answer*, not the search.

### Explaining concepts

When a doc leans on a term the reader may not have (`ioctl`, character device,
major/minor, "a frozen heap", sysfs, endianness), explain it **where the reader
first meets it**, not in a glossary — and keep the surrounding didactic register.
Prefer a few well-placed sections over one-liners scattered about.

## Conventions

- Every `.org` file starts with `#+TITLE` / `#+STARTUP`.
- The docs live under **`doc/`** (and theory/tutorials under `doc/background/`);
  only `README.org` stays in the repo root. Cross-link with **relative** paths:
  within `doc/` it's `[[file:other.org]]`; from `doc/background/` up to a sibling
  doc it's `[[file:../other.org]]`; to code it's `[[file:../../initramfs/foo.lisp]]`.
- Kernel build tags are `#NN` (currently **#32**). Always say which tag a claim
  refers to.
- The external trees are **gitignored symlinks** (`./linux`, `./sbcl`); reference
  them via those names, never an absolute/`$HOME` path. `build.sh` derives its own
  location and the cpio source paths are relative — keep it that way.
- Don't rebuild the kernel (`build.sh --kernel`, minutes) unless a *kernel*
  option actually changed; userland-only changes are `build.sh` (seconds).

## Known design facts (don't re-derive these)

- The bzImage **is** the EFI app; `\EFI\BOOT\BOOTX64.EFI` must be a literal copy of it.
- Separate initrd: `CONFIG_INITRAMFS_SOURCE=""` + `initrd=initramfs.cpio` on the cmdline.
- `CONFIG_PCI` is the keystone for real hardware: USB keyboard **and** ACPI power-off both depend on it.
- Real UEFI has no VGA text mode → need `FB_EFI` + `FRAMEBUFFER_CONSOLE`, or the screen is blank.
- PID 1 must never return, or the kernel panics.
- A saved SBCL image is a **frozen heap**: install libraries *before* `save-lisp-and-die`, not at runtime. No Quicklisp/`require` at runtime (no contrib fasls, no network).
- **The guest compiles at runtime — because `logcount-fix.lisp` patches SBCL**
  (found 2026-09-20, root-caused and fixed 2026-10-02). The symptoms were: compiling
  untyped arithmetic (`(lambda (x) (* x 2))`, any `+ - * < 1+`) died with `Unhandled
  memory fault at #x1A`, a typed `aref` on `(unsigned-byte 32)` signalled `NIL is not of
  type SB-VM::SPECIALIZED-ARRAY-ELEMENT-TYPE-PROPERTIES`, and so `C-c C-c` could not
  accept most real definitions. **Cause: SBCL 2.6.8 itself, on a CPU without POPCNT.**
  QEMU's default CPU (qemu64) has no POPCNT; the laptop does, so real hardware never
  had the bug. Compiled `LOGCOUNT` falls back to an assembly routine; 2.6.8 reordered
  the Lisp argument registers to RDI RSI RDX and the routine moved to RDI, but its one
  caller still passes and reads RDX — so `(logcount x)` returned `x` and the routine
  clobbered the caller's RDI (the fault: `BIGNUM-LOGCOUNT` loading through a bit count;
  the NIL: `(unsigned-byte 32)` printed as `(mod 4294967296)`, which `find-saetp` does not
  know). **Fix:** `initramfs/logcount-fix.lisp`, first in `LISP_SOURCES`, rewrites the
  routine to RDX at build time and self-tests with the POPCNT bit (`[NIL+97]`, bit 1)
  cleared; `check-compile.lisp` asserts it in the guest. **Ruled out** (don't re-search):
  `build.sh`/tree-shaking (the plain `./sbcl` core shows it too with the bit cleared),
  PID 1 / `SBCL_HOME` / environment / static-space mapping / kernel config (the same
  image and bzImage under `-cpu max` compile fine), SBCL's AVX2 routine variants, and
  "static-space call fixups for `GENERIC-*`" (the old hypothesis; `#x1A` was a bit count,
  not a tagged 13). **Reproduce on the host in a second**: clear that bit with
  `(setf (sap-ref-8 (int-sap (+ (get-lisp-obj-address nil) 97)) 0) …)` in a plain
  `./sbcl` and print `(sb-kernel:type-specifier (sb-kernel:specifier-type '(signed-byte
  64)))`. If `./sbcl` is ever bumped, the patch refuses to touch an unfamiliar routine and
  warns; then re-check whether upstream fixed it. Full story: `doc/inspector-history.org`
  §5.6. (`check-pointer.lisp`'s `probe-plain` dodged the `aref` shape and is kept as is.)
- **The image runs as the USER, not root** (tag #25 onward) whenever the laptop's
  disk is found: preinit drops PID 1 to the uid from the host's `/etc/passwd`
  with only `CAP_SYS_BOOT`, `CAP_NET_ADMIN`, `CAP_NET_RAW`, `CAP_NET_BIND_SERVICE`,
  `CAP_SYS_TTY_CONFIG`. Anything new needing root must either use one of those or
  go through `lol-rootd` — do not add capabilities casually; see `doc/storage.org`.
  Diskless boots (the older `check-*.lisp`, any QEMU without `test-disk.img`) still
  run as root. Our `/` is the initramfs; only `/home` is the host's.
- **The image is updated from inside it** (2026-10-20, tag #31): `./build.sh` in the
  terminal's container, then `SuperL-q` → "Install the new build and restart".
  lol-rootd (signal 42) copies `~/.lol/stage/` into the host's `/boot/lisp` and keeps
  the old pair as `*.prev`; the restart is a kexec, or the firmware (GRUB's default
  entry is ours: `/etc/grub.d/06_lisp`). `sudo` in a container is impossible by
  design (`doc/containers.org` §3.5), and `apt` into the host's Debian stays a
  Debian job — the user's call. A build in the container finds the disk's UUID in
  the host's `/etc/fstab`, because `findmnt` cannot see it there.
- **Networking is on** (tag #21 onward): `CONFIG_NET=y` + `INET` + `virtio-net`, and
  the userland ships DHCP (`dhcp.lisp`) and a TCP REPL on :4005 (`net.lisp`).
  Details: `kernel-config.org` and `doc/networking.org`.
- **Host libraries and programs are used at RUNTIME, from `/mnt/host`, never baked
  in** (2026-10-12): HTTPS loads the host's libssl with `load-shared-object
  :dont-save t` on first use and calls OpenSSL by name; Wi-Fi runs the host's
  `wpa_supplicant` through the host's own `ld-linux` with `--library-path`. A
  library loaded at build time would make the saved image refuse to start without
  `/mnt/host`. Container commands get zero capabilities, so anything needing
  `CAP_NET_ADMIN` must be run from PID 1 (ambient caps), not via `lol-ct`.
- **A frozen screen can be PID 1 dead, and two ways to die silently were found**
  (2026-10-16, `doc/diagnostics.org`). (1) The image is saved from a
  `--non-interactive` build, so its `*invoke-debugger-hook*` was SBCL's
  `DEBUGGER-DISABLED-HOOK`: an unhandled error on ANY background thread quit the
  whole process — a kernel panic nobody sees under `KD_GRAPHICS`. Now
  `log-unhandled` (session-log.lisp) logs it and ends only that thread. (2) SBCL's
  runtime enters LDB on `lose()` (heap exhaustion, GC invariants) unless
  `--disable-ldb` — `runtime.c` calls `enable_lossage_handler()` by default — and
  LDB waits on the console forever. Now `disable-ldb` calls
  `disable_lossage_handler` in every role, and preinit sets `kernel.panic=10`, so a
  dead PID 1 reboots. Both are proven by `poc/session-log-test.lisp` and
  `check-crash.lisp`. **Every new module that logs** calls `session-log.lisp`,
  which build.sh loads early; a host test loading modules one by one must load
  `poc/host-logging.lisp` first.
- **A backtrace taken by interrupting a thread that is inside C loses the frames
  between the C call and the next Lisp frame** (libc has no frame pointers: frame 0
  reads `bogus stack frame`, the caller is gone; measured 2026-10-16). Name long C
  calls on the environment's thread with `with-main-activity` so a STALL report
  still says what it was.
