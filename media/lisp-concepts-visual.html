§ packages & namespaces
⬡
namespace
PACKAGE

A first-class namespace mapping symbol names to symbol objects. Packages are not modules — they contain symbols, not code. Every symbol lives in exactly one home package.

(defpackage :my-system (:use :cl :alexandria) (:export #:frobnicate #:widget) ((:shadow #:list)))
⬡:my-system
└intern: FROBNICATE
└intern: WIDGET
└shadow: LIST
intern export :use :shadow
◈
atomic unit
SYMBOL

Symbols are objects with identity. The same printed name interned in the same package always yields the identical object. They carry five cells: name, package, value, function, and plist.

; anatomy of MY-SYS::FOO (symbol-name "FOO") (symbol-package #<PACKAGE MY-SYS>) (symbol-value 42) (symbol-function #<FUNCTION FOO>) (symbol-plist (:doc "…"))
name home-package value-cell function-cell plist
§ clos — classes & instances
▣
clos
STANDARD-CLASS

Classes are first-class objects themselves (instances of STANDARD-CLASS). Multiple inheritance is native. Slots are defined per-class with allocation, initargs, readers, writers, and type specifiers.

(defclass widget (drawable clickable) ((label :initarg :label :initform "" :accessor widget-label :type string) (active-p :initform nil :accessor widget-active-p)))
▣widget
├drawable (super)
├clickable (super)
├slot: label
└slot: active-p
defclass multiple-inheritance slots accessors
◫
class hierarchy
CLASS PRECEDENCE LIST

CLOS linearises the inheritance DAG into a CPL using C3 (as in Python). Method dispatch consults the CPL left-to-right. All classes ultimately inherit from T.

①widget
②drawable
③clickable
④standard-object
⑤t

§ generic functions & methods
⊕
dispatch
GENERIC-FUNCTION

A generic function is a function whose behaviour specialises based on the runtime classes (or eql-specialisers) of one or more arguments. It holds a set of methods; dispatch selects and combines them via the Effective Method. This is multiple-dispatch — not single-dispatch OO.

; generic definition (defgeneric render (obj surface) (:documentation "Draw obj.") (:method-combination standard)) ; primary method (defmethod render ((obj widget) (sfc framebuffer)) (blit (widget-label obj) sfc))
gf call (render w fb)
compute-em applicable methods
sort by CPL most-specific first
:before run all
:primary call-next-method
:after run all (reversed)
defgeneric defmethod :around call-next-method eql-specialiser
⊞
mop
METHOD COMBINATION

Beyond standard, combination types like +, list, progn, or custom ones via define-method-combination merge all applicable methods into a single effective method without call-next-method.

(defgeneric collect-tags (x) (:method-combination append)) (defmethod collect-tags append ((x tagged-mixin)) (list :mixin))
standard append progn + define-method-combination
§ macros & special forms
∿
compile-time
DEFMACRO

Macros transform code at read-time/compile-time. A macro function receives unevaluated forms and returns a new form for the compiler. Backquote syntax makes the expansion readable.

(defmacro when-let ((var expr) &body body) `(let ((,var ,expr)) (when ,var ,@body))) ; expands at compile time: (when-let (x (find-widget :main)) (render x))
backquote unquote splice gensym
⟲
reader
READ MACRO

Reader macros hook into the Lisp reader, transforming character sequences before the tokeniser sees them. #', ', `, and ,@ are all built-in dispatch macros.

; define #{ … } as a hash literal (set-dispatch-macro-character #\# #\{ (lambda (stream char n) (read-hash-literal stream))) ; now #{:a 1 :b 2} works
readtable dispatch-macro reader
§ condition system
⚡
non-local flow
CONDITION SYSTEM

Conditions are CLOS classes. Signalling a condition searches the dynamic handler stack without unwinding the stack first. This is the key distinction from try/catch — the signaller's context is still live when the handler runs, enabling restarts.

⬦
condition types
CONDITION HIERARCHY

Conditions form a CLOS class hierarchy. SERIOUS-CONDITION must be handled. ERROR invokes the debugger if unhandled. WARNING and CONDITION are advisory.

§ restarts
↺
recovery points
RESTART

Restarts are named recovery strategies established by the signalling code, not the handler. The handler (or the user in the debugger) chooses which to invoke. Policy lives high; mechanism lives low.

(restart-case (parse-form raw) (use-default () :report "Return default value" *default*) (retry (new-raw) :report "Try different input" :interactive read-new-input (parse-form new-raw)))
restart-case restart-bind invoke-restart find-restart
⊛
built-in restarts
STANDARD RESTARTS

CL specifies a set of standard restarts that operators like USE-VALUE, STORE-VALUE, and CONTINUE invoke, enabling portable recovery across implementations.

ABORT exit current op cleanly
CONTINUE resume after warning
USE-VALUE substitute a value
STORE-VALUE substitute + remember
MUFFLE-WARNING suppress warning
use-value store-value abort continue
